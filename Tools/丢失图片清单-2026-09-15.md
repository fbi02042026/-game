## 一、结论先行

1. **图片不是"被删了"，是"引用被清空了"**：预制体里 `m_Sprite: {fileID: 0}`。
   全工程合计 **3448 处**，其中**游戏本体 176 处 / 25 个文件**（其余全在第三方素材包）。
2. **从 git 还原这条路已经验证走不通**（不是没试）：
   - `git fetch --all --prune` 后，对 `git rev-list --objects --all` 里
     **全部 10953 个历史 .meta 对象**建了 (guid → 路径) 索引；
   - 悬空 guid **命中 0 个**；`git stash`、`git fsck --unreachable` 也查过，同样没有。
   - **→ 这批资源从来没有进过这个仓库的任何一次提交。**
3. **根因**：`fd7047c1 入库用户修好的UI预制体`。这些 prefab 是在**另一台机器 / 团结引擎
   （原 `Y:\PixelAdventureTown` 工程）**里做好后导出进来的，它们引用的图片 guid 属于那边，
   图片本体和 .meta 没跟着过来。
4. **`7e526d69`（批量把 581 个 .meta 的 base64 guid 换成随机 hex）让情况变差了 63 处**，
   但它不是最初的根因（见下表）。它是一颗定时炸弹，见第四节。

## 三、几个具体问题的答案

### 「初始武器没有了」→ 其实没坏
`Assets/Resources/Config/Equips/equip_sword_1.asset` 的 `icon` 指向 `fa4d91f01f014619bff94dcccbb37fb4`
= `Assets/Resources/UI/EquipIcons/Sword_1.png`，**引用有效**。
坏的只是第三方素材包自带的 `Assets/Art/RPG Props and Items 370+/1/Sword_1.prefab`
（它引用 `e19c4362…`，该图从未入库）。游戏内武器图标不受影响。

### 「选职业页立绘丢失」→ 是引用被清空，不是 guid 悬空
`PlayerJobSelect.prefab` 当前**悬空 guid = 0**，但有 **31 处 `m_Sprite: {fileID: 0}`**。
工作区那份 4927 行的未提交改动，正是 Unity 打开工程后把 29 个**已经悬空**的引用清成 0 的结果
（`git diff` 可见 39 个有值 → 29 个变 0）。被清掉的 13 个去重 guid 在 git 全历史里同样 0 命中，
**所以回退这个文件也修不好**，两者表现一致（都是空）。

### 「战斗场景 Missing Prefab Asset: 'box'」
`Battle.unity` 引用 `429795ccaa0c615408a6c4b24a06711d`，该 guid 同样从未入库
（`6e3c24b8 sync PixelAdventureTown` 时带进来的）。box 是特效素材包里的预制体。

## 四、修复路径（按推荐顺序）

### 方案 A：语义重绑（推荐）
用工程里**现有的同名/同语义图**重新指向。已具备工具：
- `Tools/DiagnosePhantomSprites.py` → 悬空 guid 的**宿主节点名**
- `Tools/SuggestPhantomRebind.py` → 同 prefab 内正常引用目录 + 候选图
- `Tools/phantom-sprite-report.txt` / `phantom-rebind-candidates.txt` → 现成报告

流程：跑工具 → 人工确认映射 → 写入 `Tools/phantom-rebind.json` → 批量替换 guid。
**映射表一旦建立就是可重放资产**，以后再搬工程直接重放，不用再手改。

176 处，工作量大，但最准。**先把 `PlayerJobSelect` / `BattleUI` / `WorldMapPopup` 三个做完**（63 处，占 36%）。

### 方案 C：从原 `Y:\PixelAdventureTown` 工程拷贝（最彻底）
如果那台机器/目录还在：把 `Assets/Art/**` 的 **`.png` 连同 `.png.meta` 一起**拷过来，
guid 就对上了。**拷资源必须带 .meta，否则等于重新导入、生成新 guid，白拷。**

## 五、彻底根绝的铁律

1. **单一真源**：UI 预制体只允许在一个工程里改，改完导出时必须**连美术资源 + .meta 一起**迁。
2. **拷资源必带 .meta**：`.png` 和 `.png.meta` 永远成对出现。丢 .meta = 资源换身份 = 引用全断。
3. **绝不 hex ↔ base64 互转**：团结引擎给新资源分配 base64 guid 是正常行为。
   `7e526d69` 那次"修复"把 581 个 .meta 的 guid 随机化，正是这个错误的典型后果。
   （`Tools/FixAllCorruptedGuids.ps1` 已废弃，头部写了这个结论。）
4. **提交前跑校验**：已装 pre-commit 钩子（`Tools/install-git-hooks.py`），
   跑 `Tools/CheckGuidRefs.py --quiet`，只拦"本次新增"的悬空，历史遗留不阻塞。
5. **Unity 打开后立刻看 git diff**：Unity 会把悬空引用清成 `{fileID: 0}`，
   这种改动**看起来是噪音，实际是丢图证据**，不要无脑提交，也不要无脑回退。
6. **新增检查项**：`m_Sprite: {fileID: 0}` 的数量应该只减不增，
   建议把「游戏本体 176 处」作为基线，列进 `Tools/CheckGuidRefs.py` 一起拦。

## 一、为什么重做（根因，不是丢波）

现状把两拨怪压成了一整场，玩家看不到任何「还有下一波」的信号：

| 证据 | 位置 | 说明 |
|---|---|---|
| `LoadStage 战斗关 type=Normal waves=2` | `Editor.log:61905` | 代码铺了 2 波 |
| 第 1 波 | `Editor.log:64565-64576` | 点「开始战斗」→ `DoStartFight → ForceSpawnFirstWaveNow → SpawnWave` |
| 第 2 波 | `Editor.log:64977-65051` | `CoWaveStreamNext → TickWaveStreamSpawn → SpawnNextPendingWave(allowStackWhileAlive:true)`，**不等清场叠刷** |
| 编译 | `Assembly-CSharp.dll 13:22:42` > 源码 12:37 | 11-13 流式衔接已生效，不是「改了没生效」 |

**根因链**：`WavePlanner.Advance.cs:210-211` 每刷完一波就 `ScheduleWaveStreamNext()` → 第 1 波刚出完 1 秒就叠刷第 2 波 → 第 1 波永远等不到「场上清空」那一刻 → `BeginNextWaveCountdown()`（`BattleManager.Waves.cs:842`）即使恢复播报也进不去 → 全关 0 次过场 → 2-2 / 2-4 都被看成「只有 1 波」。

结论：这是**节奏结构**问题，不是波数/刷怪数量问题。继续调波数、调怪数、调间隔都只是在补漏洞，所以本版改结构。

## 三、设计意图（Level Design）

**Player Fantasy**：「先摸清这关是什么怪，然后主力压上来，一路打到底」——不是一开场就被一整场怪糊脸，也不是每波都被过场打断。

**Pacing Arc**：接触（低）→ 喘息（闸门）→  escalation（中高，连续）→ 结算 / Boss（高潮）。

**记忆点**：全关**唯一一次**「下一波来袭」。它是关卡中段的节奏闸门，玩家一看到它就知道「热身结束，主力来了」。

**可读性**：第 1 波固定单独一波、怪数减半（`FORMAL_WAVE1_DISCOUNT=0.5` → 5~8 只），给玩家读场、看怪、攒技能的时间（entry read time）；Gate 之后才允许叠怪，压力升级是**被预告过的**，不是偷袭。

## 四、波次规格 v5「两段式」

### 4.1 结构定义（每关固定四段）

```
Act A  开场波 Wave 1   固定 1 波 · 单独刷 · 不叠刷 · 不流式 · 怪数 ×0.5
   ↓ 场上清空
Gate   唯一一次过场     普通/精英关：「下一波来袭」  Boss 关：「首领来袭」（待确认 §7.2）
   ↓
Act B  主力怪潮 Wave 2..N   连续 N-1 波 · 波间 1s 流式衔接（不等清场、允许叠怪）
                            · 不再播任何过场 · 进度条按「已刷波数」推进
   ↓
Climax 末波            普通关：清场 → 结算
                       Boss 关：Boss 波仍走「首领来袭」+ 羁绊本前剧情（11-12 口径）
```

**关键约束**：整个关卡**恰好一次**过场。Gate 播完才允许流式衔接启动 —— 这是「第一波始终是一波」的硬保证。

### 4.2 波数表（主推 A 案：波数/怪量/掉落一字不动）

| 关卡类型 | 前期 Ch1-2（cap=2） | 后期 Ch3+（cap=3） |
|---|---|---|
| 普通 / 精英关 | `W1` 开场 5~8 只 → Gate → `W2` 主力 8~12 只 | `W1` 开场 5~8 只 → Gate → `W2` 8~12 只 →（1s 叠刷）`W3` 10~15 只 |
| Boss 关 | `W1` 小怪 → Gate → `W2` 小怪 → 首领来袭 → `W3` Boss（**3 波，§11 补波**） | `W1` → Gate → `W2` 小怪 → `W3` Boss（不变） |
| 资源副本（金币/徽记/卷轴/礼物） | 2 波 × 8~10 只 | 3 波 × 8~10 只 |
| 羁绊本 | 2 波（1 小怪 + 1 Boss）不变 | 同左 |
| 引导局 | `TutorialDirector` 直刷，`Rules.SkipWaveAnnounce=true`，**不同轨** | — |

> 「这一波可以是多波」在 A 案下的落地：后期主力段 = 2 波连续；前期主力段 = 1 波。若主人要前期主力段也多波，走 §5 的 B/C 案放开 cap。

### 4.3 节奏图（前期普通关，A 案）

| 时间 | 段 | 张力 | 说明 |
|---|---|---|---|
| 0:00 | Act A | 低 | 开场波 5~8 只，读场 / 攒技能 |
| ~0:15 | 清场 | 低 | 场上空 → 播 Gate（约 2~3s，不带 5s 倒计时，见 §7.1） |
| ~0:18 | Act B | 中高 | 主力波 8~12 只压上；后续波 1s 流式衔接、不再提示 |
| ~0:40 | 结算 | 低 | 清场 → 宝箱 / 结算 |

### 4.4 Flow Diagram

```
[进关/点开始战斗] → [W1 开场波 · 单独] → [场上清空]
                                            ↓
                                   [Gate · 全关唯一一次过场]
                                            ↓
                        [W2 主力] ──1s──> [W3 主力] ──1s──> [Wn]   ← 连续怪潮，无过场
                                                                  ↓
                                    [普通关：结算]  /  [Boss 关：首领来袭 → Boss → 结算]
```

## 十、附录：PvZ 关卡难度参考与本项目映射（13:4x 补充）

> 本节只补「难度曲线层」，**不改 §四 两段式结构**；T8~T11 是增量任务，落地时并入 §6。
> 资料：PvZ Wiki「关卡」/「Progress bar」、3楼猫《从〈植物大战僵尸〉看如何设计关卡的节奏》(2022-05-31)、PvZ Wiki 波次点数讨论页。

### 10.1 PvZ 怎么造难度（6 条，可核实）

1. **进度条 + 旗帜**：进度条有僵尸头 + 0~4 面旗；僵尸头碰旗 → 红字「一大波僵尸正在接近！」→ 旗帜僵尸率大波；走到最左 → 再播「最后一波」→ 最后一大波，清完胜利。**提示只给旗帜波，普通波不给**（1-1 例外，只播「最后一波」）。
2. **每波战力上限**：线性 `y=kx+b`，经典序列 `1,1,1,2,2,3,3,3,4,10(旗),5,5,5,6,6,7,7,7,8,20(旗)`；旗波 ≈ 相邻普通波的 2~2.5 倍。
3. **卡池 + 战力值 + 权重**：普僵1 / 路障2 / 撑杆3 / 铁桶4 / 伽刚特尔10；每关先定卡池、**进关就展示给玩家**；逐波抽怪直到战力和 = 本波上限（超了放回重抽）。普僵/路障权重随波次递减 → 后期自然变强，不用改属性。
4. **刷怪间隔自适应**：本波出完等 X 秒；玩家打得快、本波血量降到阈值 → **立刻**刷下一波。高手不无聊，新手有喘息。
5. **不靠属性膨胀**：同一只普僵在 1-1 与 5-10 属性一样；难度来自战力曲线 + 卡池种类 + 地形/环境修饰 + 大波密度（Wiki 原话「旗多不一定更难」）。
6. **情报节奏 / 关卡外节奏**：开局预告地形 + 本关僵尸，进程中预告高压波位置，玩家才能做宏观规划；新僵尸预留 2~4 关学习，多数给对应植物解；每 5 关一个小游戏换口味。

### 10.3 采纳方案：只搬「编排」，不搬「数值」

A 案总量不变，把难度做成三段可感知的曲线：

| 段 | 相对 W1 强度 | 规则 |
|---|---|---|
| W1 开场波 | 1× | 怪数 ×0.5；**禁止**精英 / 词缀 / 签名怪 / 事件层（对应 PvZ 前 3 波战力=1、新怪有最早波次） |
| Gate 旗帜 | — | 全关唯一一次「一大波来袭」；进度条旗标（待确认，动 UI 先问） |
| 大波段 | 2~2.5× | 不打折的 10~15 只；**本关所有**精英 / 签名 / 词缀 / 事件层集中挂这里；后期可 2 波 1s 流式连续 |
| 末波 / Boss | 3× | Boss 关「首领来袭」；普通关大波段末波即「最后一波」 |

- 前期普通关（2 波）：`W1 = 5~8 只纯普通` → Gate → `W2 = 8~12 只`（含本关 1 只签名怪 + 词缀配额 + 精英关的精英）。
- 后期普通关（3 波）：`W1 = 5~8` → Gate → `W2 = 8~12` → `W3 = 10~15`（特殊怪集中 W2/W3，流式 1 秒）。
- **总怪量、时长、金币、掉落一字不变**，只是把「随机摊」改成「按段集中」——玩家能明显感到「大波来了」，这正是 2-2 / 2-4 现在缺的东西。

### 10.4 能搬 / 要拍板 / 别搬

## 十一、补一波与抽奖经济（14:2x 主人拍板「可以补一波让玩家能抽几次奖」）

> 本节覆盖 §2 / §4.2 / §7.2 / §9 中 Boss 关的旧描述；代码落点 `WavePlanner.Plan.cs:760-761`，**已落地未提交**。

### 11.1 机制核实：多一波怪确实能多抽几次

主线正式关的抽奖是「**币够就能抽**」，没有本场次数硬上限（`FreeDrawsLeft` 只在免费额度模式/竞技场/资源副本生效，正式关恒 0）：

| 环节 | 真源 | 值 |
|---|---|---|
| 击杀发币 | `BattleManager.MonsterDeath.cs:68-74` | 普通怪 `KILL_GOLD_NORMAL=10` / 精英 25 / Boss 50，发进 `currentGold` |
| 抽价 | `SlotMachineSystem.cs:38-45` + `SlotMachineDefs.cs:67` | `BASE_PRICE=40`，每已抽一次 +10（`DRAW_PRICE_STEP`） |
| 面板 | `BattleEntryDraftPanel.Flow.cs:127-135` | 11-12 拍板「全部常显」，战斗中随时可点，只看 `CanAffordDraw` |
| 通关补贴 | `SlotMachineDefs.cs:166-177` | 普通/Boss 100、精英 150（关末到账） |

补一波 = 多 10~15 只普通怪（`FORMAL_WAVE_MONSTERS_MIN/MAX=10/15`）→ **+100~150 抽奖币** → 前期抽价 40/50/60 时能多抽 **2~3 次**；`DrawIndex` 跨关累计、后期抽价更高时约多 1~2 次。主人 10-10 的目标「尽量每关都能抽 1-2 抽为佳」（`SlotMachineDefs.cs:139`）由此更稳。

### 11.2 落地范围（最小增量）

只改 `WavePlanner.Plan.cs:761` 一处：`Mathf.Max(1, StageWaveCap(chapter) - 1)` → `Mathf.Max(2, ...)`，`:760` 注释同步。

|---|---|---|---|
| 前期 Ch1-2（cap=2） | 1 波小怪 + Boss = 2 波 | **2 波小怪 + Boss = 3 波** | +1 波 |

### 11.3 顺带修掉 14:1x 自检的两个边界

- **Gate**：前期 Boss 关第 1 波清场时，下一个未刷波不再是 Boss 波 → `BeginNextWaveCountdown` 的 `!boss` 分支命中 → 播 1 次「下一波来袭」，随后 Boss 波仍播「首领来袭」。前后期 Boss 关统一为 **2 次过场**（Gate + 首领来袭），自检里的「次数不一致」自动对齐；代价是「全关恰好 1 次过场」不再适用 Boss 关。
- **词缀怪**：`InitAffixQuota`（`Picks.cs:313` 排除下标 0）现在有第 2 波小怪可挂 → `spawnable=[1]` 非空，配额不再归零。
- **索引安全**：`RollFormalRoundWaveCounts` 前期返回 `[1,1,0]` → `FormalRoundEndFlags` 长度 2；`minionWaves=2` 时 `:792` 的 `i < formalBossRoundEnd.Length` 短路保护下不越界。`perWave` / `:826 bossX` / `:844 InitAffixQuota` 都按 `minionWaves` 或 `_waves.Count` 自动跟随，无需兜底。

### 11.4 边界与不做的部分

- ❌ **没有全局补波**：普通 / 精英关仍是前期 2 / 后期 3 波。若每关都补，需改 `StageWaveCap` 到 3/4，单关时长 +33~50%、掉落与经验同步涨，与 11-11「21-2 打的时间太长了」冲突 → **列为待确认项 9**。
- ❌ 不动抽奖系统本身（不调价格、不加免费额度、不恢复波清抽奖窗；11-01「波清一律不弹抽奖窗」口径保留）。多抽几次完全靠击杀币，符合「不要第二套口径」。
- ⚠ 前期 Boss 关比普通关多 1 波，单关时长略增；这是主人明确要的「补一波」。

## 一、一句话结论

不是显示 bug —— **这件装备在战斗里真的几乎不产生任何属性**，因为「力量→物理攻击」这条派生对玩家被整整关了（`AttrSystem.cs:216`），
所以力量词条只能折成 `PhyPower +0.05`（技能伤害乘区），而战力口径根本不看它 → 战力 +0 是**如实反映**。
昨天（2026-10-25）给智力补了「折进魔攻」那段时，力量没有对称补 —— 这就是漏的那半条。

## 二、为什么是 0（三层定位，逐条可查）

| 层 | 位置 | 原文 / 现状 | 判断 |
|---|---|---|---|
| ① 战斗层（根因） | `Assets/Scripts/Systems/AttrSystem.cs:216` | `if (!UsesPlayerJobTable) AddAttr(AttrType.Attack, str * 2f, false);` | **玩家走职业表 → 整段跳过**。玩家加的任何力量都不进物理攻击。 |
| ② 派生层（残留收益） | 同文件 `:228` | `AddAttr(AttrType.PhyPower, str * 0.01f, false);` | 力量+5 → PhyPower +0.05。但 `DamageFormula.cs:108` 只在**技能**里用 `(1+phy+mag)`，**普攻（`BuildAttackRaw`）不吃**。所以只剩「技能伤害 +5%」。 |
| ③ 战力口径 | `Assets/Scripts/Config/PowerCalc.cs:31-35` `IsCountedAttr` | 只认 Attack / MagicAttack / CritRate / AttackSpeed / MaxHp / Defense / MagicDefense / Vitality | **不含 Strength**（也不含 Intelligence，但智力已在 ② 折成 MagicAttack，所以法系算得到）。 |

叠加结果：`EquipSwapPowerDelta` 走真值模拟 → 副本 `AttrSystem` 里力量不派生 → 攻击不变 → DPS 不变 → **净差恰好 0** → 文案「两件差不多」。
所以这条链是**自洽的**，它诚实地告诉你「这件装备没给你任何战力」。

### 同根同源的第二个受害者：狂战升级白升

`LevelSystem.JobTendencyAttr()`（`LevelSystem.cs:34-46`）—— **狂战士 = 力量**，每级 +1 力量。
`JobTendencyLabel()` 对狂战也明写「力量」（`:63`）。
但按 ① 那条，狂战每升一级，攻击一点不涨。全六职业里只有他一个人升级不加伤害。

> 对照：2026-10-25 主人原话是「智力可以改成加成魔攻 **物攻有加成** 魔攻应该也有」——
> 这句话的前提是「物攻已经有加成」，实际上物攻侧是关着的。这次改的是对的前提、错的事实。

## 三、全面体检：装备 ↔ 战力换算的问题清单

复算口径（`PowerCalc.cs` 常量，与 `RunLoadout.TotalPower` 同一把尺子）：
`Power = 130.50 + 4.42267 × DPS + 0.15 × 生命 + 2.5 × (物防+魔防)`，`DPS = 攻击 × (1+暴击率) × 每秒攻击次数`。

### 3.1 公式一致性 ✅（这块没问题）

- `RunLoadout.TotalPower()` 玩家段（`:726-734`）与 `PowerCalc.PlayerPowerSegment`（`:177-186`）**逐项一致**，含 `RoundToInt`。
- 换装模拟（`EquipSwapPowerDelta`）复刻了 `Hero.RecalcAttr` 全链：装备表 → tempBuffs → RecalcAllAttr → 武器类型攻速乘区（`PowerCalc.cs:189-197` 对 `Hero.cs:259-265`，写法一致）。✅
- 副手攻击封顶、强化倍率只作用于 baseAttr、`Clamp01(暴击)`、攻速 ≥0.2 —— 两侧同源。✅

### 3.4 同档位不同价：传奇一件词条的战力价值能差 200 倍

| 词条（传奇档） | 数值 | 剑盾战力 |
|---|---|---|
| 攻击 | 33~39 点 | **167** |
| 防御 | 28~44 点 | 90 |
| 生命 | 180~300 点 | 36 |
| 攻速 | 12~20% | 30（A=40 时；A=160 时 119） |
| 暴击率 | 7~12% | 17（同上会放大约 4 倍） |
| 力量 / 智力 / 移速 / 元素 / 暴伤 / 减伤 / 闪避 / 吸血 / 射程 | — | **0** |

两个附带失衡：
- **生命 vs 防御**：表里 HP 数值是 DEF 的 ~6.7 倍，但战力权重只有 1/16.7 → 同样档位的生命词条只有防御词条的 40%。玩家会系统性低估生命。
- **百分比词条随攻击膨胀**：暴击/攻速的当量 = k×A×…，A 从 40 涨到 160 时涨 4 倍；攻击词条恒定。后期一件攻速手套 ≈ 两件武器主属性（见脚本 F 段）。

### 3.5 顺带查出的三个较小缺陷

1. **卡面预估分支不认识智力**（`PowerCalc.cs:46` `EquipPowerDelta` 走 `IsCountedAttr`，不含 Intelligence）。
   城镇等取不到 `BattleBagSystem`/`Hero` 的场景（`EquipSwapPowerDelta:149-150` 的既定分支）会退回预估，
   那时智力装备显示 +0；进战斗再看又涨了 → 同一件装备两个数字。
   → 建议：预估分支补 `pctInt/flatInt`（法系 ×2 折 MagicAttack，与真值同口径）。
2. **换装模拟不吃等级倾向**（`PowerCalc.SimPlayerSegment` 用 `new AttrSystem(Player)`，只写 `BASE_*`；等级的 +N 点只在 `LevelSystem.RestoreHeroLevel` 里写给 `hero.attr`）。
   影响：狂战/法师的 A 被低估 → 暴击/攻速词条的净差偏小。力量修好之后这一项误差会变大（等级越高偏得越多）。
   → 建议：模拟前用 `LevelSystem` 的「基底 + level-1」把倾向属性写进副本（一行）。
3. **自动换装会把「不涨战力但更好用」的装备丢掉**：`EquipReplaceConfirmUI.AutoPickByPower`（`:121-125`）在 d≤0 时留旧的。
   极端情况：旧件已是 0 战力的垃圾（如力量手套），新件是减伤/吸血手套（也是 0）→ d=0 → 永远换不上。
   → 建议：d=0 时按品质/星级（`EquipCompare.Score`）兜底，或 d=0 时改问玩家而不是静默留旧。

## 四、修法方案（等主人拍板，本次未动代码）

### 方案 A（推荐）：补对称派生 + 同步下调表里力量/智力区间

1. `AttrSystem.cs:216` 附近，与智力那段（`:240-241`）**同写法**补一条：只折 `BASE_STRENGTH` 以外的成长段 ×2 折 `Attack`。
   - 效果：装备力量、等级力量、天赋力量全部生效；狂战升级终于加伤害；战力自动跟着涨（真值口径，不用另改 PowerCalc）。
2. **必须同步调表**，否则力量词条会变成攻击词条的 2 倍强：
   `equip_attr_ranges.csv` 的 `STRENGTH` / `INTELLIGENCE` 三档 ÷2（普通 1.25~3、稀有 3.75~7.5、传奇 14~22），
   并同步 `ArmorAffixSystem.RollValue`（`:147-148` 的 `2.5 + rand(0,3.5)` → `1.25 + rand(0,1.75)`），
   改完跑 `Tools/sync_table_bytes.py equip_attr_ranges`（⚠ 该表本无 BOM，脚本按整份拷贝，先验）。
3. 影响面：物理系（尤其狂战）伤害上调；法系智力词条从「2 倍魔攻」回到「1 倍」。**要重看一次战力目标值**。

> 为什么必须调表：现在 `INTELLIGENCE` 与 `MAGIC_ATK` 区间几乎一模一样（普通 2.5~6 / 4.5~6，传奇 28~44 / 33~39），
> 智力按 ×2 折魔攻 → 智力词条 = 魔攻词条的 **1.6（普通）~2.0（传奇）倍**价值。
> 这条超模是 10-25 补智力时留下的，力量修好后会复制一遍。

### 方案 B（只在显示层补力量折算）—— ❌ 不建议

会让「战力涨了、伤害没涨」，直接违背 2026-10-25 拍板的「提示增加的战力必须与实际一致」。

### 方案 C（给所有生存/功能词条加权重）

解决「0 战力」的观感，但会动全职业战力排序（`Docs/战力口径改造_待办任务清单.md` 第六节的两处冲突还没解决），
建议**等 A 落地、排序重算之后再单独做一轮**，并按 EHP 折算给：
减伤 / 吸血 / 闪避 / 移速 / 射程 / 暴伤 / 元素 各给一个小权重（具体值待定，需要先定「1 点防御 = 多少战力」为锚）。

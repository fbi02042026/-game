## 二、已确定的硬事实

1. **删除规模 1944 个文件**，类型分布：`.meta` 950 / `.png` 431 / `.asset` 182 / `.cs` 137 / `.prefab` 78 / 无扩展 44 / `.bytes` 34 / **`.lock` 29** / `.mat` 29 / `.txt` 7 / `.anim` 4 / `.csv` 4。
2. **目录集中在 `Assets/`**：`Resources/Config/Equips` 260、`Resources/UI/EquipIcons` 229、`Scripts/UI` 172、`Resources/Data/Tables` 70、`Resources/Config/Monsters` 60 …——与 git 报告的 2095 个 ` D` 分布吻合（git 数到的更多，因为它还统计了 `.meta` 之外的条目）。
3. **删除走了 Windows 回收站（shell 删除 API）**——这是关键：`git` 自己删文件用 `unlink`，**不会进回收站**。所以**动手的进程不是 git**；git 是受害者，它只是发现「索引里有、磁盘上没了」。
4. 被删集合里含 **`.lock`（29 个）这类 git 不跟踪的文件**——再次指向「不是 git 干的」。
5. **本次零损失**：因为 pull 前工作区干净，`checkout-index -f -a` 用索引（= 新 HEAD）恢复，内容与删除前一致。

## 三、没查清的部分（不编结论）

- **谁删的：未确定。** 已排除：
  - ❌ 团结编辑器 —— Hub 20:11:44 才启动，pull 是 19:50，早 20 分钟；现在跑着的团结是主人后来开的。（注：我一开始据「团结现在在跑」推断过它，这个归因**是错的，已撤回**。）
  - ❌ git 自己 —— 见上面第 3、4 条。
- 剩下可能：某个带「安全删除」行为的外壳/沙箱层、清理或同步类软件、人为操作。Windows 默认不审计文件删除，事件日志里没有记录；**回收站在 20:33–20:38 之间被清空**，进一步线索已无法再取。

## 四、为什么这次没出大事（别指望下次还有这个运气）

`checkout-index -f -a` 恢复的是**索引内容 = 刚拉下来的 HEAD**。

- ✅ 已提交的东西 → 100% 回来。
- ❌ **未提交的本地改动 → 会被 HEAD 覆盖，git 救不回来**，只能去回收站捞（而回收站会过期/被清空）。

今天零损失，纯粹是因为 pull 前工作区刚好是干净的。**下次如果正在 Unity 里改预制体又没提交，就是真丢。**

## 五、定的规矩（照做）

| # | 规矩 | 谁执行 |
|---|---|---|
| 1 | **pull 之后立刻 `git status --short`**，看到成片 ` D` 不要慌，直接 `git checkout-index -f -a` | 每次 pull |
| 2 | **装 post-merge 钩子**（已升级：pull 后自动检测成片删除 → 自动恢复 → 报警 + 提示去回收站捞）。换机器重装：`cp Tools/git-hooks/post-merge .git/hooks/post-merge` | 一次/每台机器 |
| 3 | **美术 / 预制体做完就提交**，别让未提交的改动长时间躺在本地 | 日常 |
| 4 | 出事后**先别清回收站**，先跑 `python Tools/prefab-analysis/scan_recycle_bin.py`（只读，能还原被删文件的原始路径） | 出事时 |
| 5 | 恢复后**重启团结编辑器**让它重新导入，否则缓存错位会表现为「白框 / 界面不对」 | 出事时 |
| 6 | 关键改动留一份到 `.workbuddy/backup/`（目前是空的） | 大改前 |

## 六、已落地

- `Tools/git-hooks/post-merge`：新增安全网（自动恢复 + 报警），已安装到 `.git/hooks/`
- `Tools/prefab-analysis/scan_recycle_bin.py`：回收站只读扫描（还原原始路径）
- `Tools/prefab-analysis/recycle_stats.py`：回收站删除规模统计（取证用）

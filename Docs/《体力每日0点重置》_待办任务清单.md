### T2 跨天补满结算（核心）【已完成 2026-11-03，落盘 StaminaSystem.cs:103-114；验收 1~4 待主人验证】

- 文件：`Assets/Scripts/Systems/StaminaSystem.cs` → `Tick()`（:94-125）
- 做法：在 ：100 `lastStaminaUtc` 初始化**之后**、按秒恢复逻辑**之前**插入跨天判断：
  `data.staminaDayKey != DayKeyUtil.TodayKey()` 时 → ① 补满 `data.stamina = Mathf.Max(data.stamina, Max)`；② 写 `data.staminaDayKey = 今日键`；③ 重置恢复时钟 `data.lastStaminaUtc = Now()`（与 ：106/:121 满管重置口径一致）；④ **强制 Save 一次**（无视 `save` 参数）。
- 细节红线：
  - **判天只能用 `DayKeyUtil.TodayKey()`**，禁止自写 `DateTime.Now.ToString("yyyyMMdd")`。
  - **幂等**：键写当日后短路，同一天内后续 Tick（`Current`/`IsFull`/`SecondsTo*` 全走 Tick，高频）零开销、零重复 Save。**禁止**新增 Update 轮询/协程做跨天检测。
  - 补满用 `Mathf.Max(当前, 上限)`，不许把药水顶上去的超上限值压回（:105 的压回是既有行为，不归本次管、不顺手改）。
  - 结算块必须放在恢复逻辑之前：玩家 23:50 打空体力、跨天后 0:01 读 `Current` 就应是满管，不能先按旧值算回复。
- 验收：
  1. 编辑器把系统时间调到次日 0 点后回游戏 → 体力满、`staminaDayKey` = 当日。
  2. 当天反复进出主界面 / 重启游戏 → 只结算一次（无重复 Save）。
  3. 跨天时已满体力的玩家 → 数值不变、不报错、只写键一次。
  4. 旧档（无 `staminaDayKey`）首次进游戏 → 补满一次，之后再进不再触发。
- 依赖：T1。风险：Tick 调用面极广，结算逻辑必须在最前且短路，避免高频开销与重复落盘。

# 酒馆功能梳理（2026-09-17）

> 触发：酒馆从「招募佣兵」改成「解锁佣兵」之后，页面上的功能没跟着重构，
> 出现「活的只有 2 个、死的 1 套、写好了没挂的 1 套」三种状态混在一起。
> 本文只做梳理与方案，**不含代码改动**。

---

## 一、结论先行

| 状态 | 内容 |
|---|---|
| ✅ **活的功能（2 个）** | ① 佣兵名册（解锁，本次改版核心）② 佣兵情报（独眼每日问答） |
| 🟡 **写好了没挂 UI（1 套）** | `TavernLore` —— 策划案 §7 的全部酒馆叙事（空座位 6 阶段 / 独眼请酒 / 老板娘台词 / 佣兵 Lore 轮换） |
| ❌ **已成死代码（1 套）** | `TavernRosterPanel` → `MercenaryRecruitPopupUI`（861 行旧招募 UI）+ `MercHireSession` 一半成员 |
| ⬜ **占位未清（2 个）** | 页面上的「信任交流」「酒馆任务」两张卡被 `SetActive(false)` 隐藏 |

**一句话**：酒馆现在是"一个买佣兵的商店 + 一个答题摊"，但它被设计成"回城的理由"（叙事锚点），
这层完全没接上——而这正是策划案里标注"性价比最高"的部分。
同时旧招募链路整条没有入口了，占着 1000+ 行代码和一套存档字段。

### 2.2 页面上的四张功能卡

`TavernUI.BuildContentOnly()`（`TavernUI.cs:360-367`）建 4 张卡，`WireClicks()`（`:277-295`）决定去留：

| 卡 | 状态 | 去向 |
|---|---|---|
| **佣兵名册** Recruit | ✅ 活 | `TavernUnlockUI.Show()`（`TavernUI.cs:284`） |
| **佣兵情报** Intel | ✅ 活 | `InformantIntelDirector.StartDaily()` → `InformantQuizDirector`（`:293`） |

| 酒馆任务 Quest | ⬜ 隐藏 | `SetActive(false)`，无实现（`:288`） |

> 卡面文案在运行时被改写：`RetitleRecruitCard("佣兵名册", "解锁佣兵，让其进入战斗三选一池")`（`:285`）。
> 也就是说预制体上还是旧的「招募」文案，靠代码覆盖——**下次有人改预制体就会露出旧文案**。

### 2.3 新版解锁链路（佣兵从哪来）

```
默认解锁 3 名（SaveData.DefaultUnlockedMercIds = H001 老盾 / H005 小红 / H019 星火）
        │
教程强制解锁 H011 小白（StoryProgress.TutorialMercHireId）
        │
酒馆「佣兵名册」花金币解锁其余 19 名  ← 当前唯一获取途径
        │   门槛：普通无限制 / 稀有 需酒馆 Lv2 / 传说 需酒馆 Lv3
        │   写 SaveData.unlockedMercIds + AdventureCodex.MarkMercSeen
        ▼
局内三选一池（DraftPool.CollectRecruitMercs，只从 unlockedMercIds 抽）
        │   抽到才上阵，局内升等级/星级，撤离即清空（RunLoadout）
        ▼
佣兵上限 2（RunLoadout.MaxRunMercs）
```

**价格表**（`MercRosterDefs.RecruitGold`，0 则按稀有度兜底 500/1500/5000）

| 稀有度 | 数量 | 价格区间 | 酒馆等级门槛 |
|---|--:|---|---|
| 普通 | 8 | 500 ~ 800（3 名默认免费） | 无 |
| 稀有 | 11 | 1600 ~ 2200 | Lv2 |
| 传说 | 3 | 5000 ~ 8000 | Lv3 |

### 2.4 酒馆的"彩蛋"其实是硬机制

`TavernLandladyTease`（点老板娘立绘）：
点 5 次开始压暗警告 → **点满 10 次被赶出酒馆 60 秒**。
Ban 状态通过 `TavernNavBanHud` 在导航按钮上显示倒计时（`TownHubController.cs:43-56,158-161`）。

> ⚠️ 这个 ban **只拦 TavernUI 页面**，不拦已经打开的 `TavernUnlockUI` 弹窗
> （弹窗挂在 TownPopup 层，独立 Canvas）。交互上需要确认是否符合预期。

## 四、问题清单

### P0 —— 影响玩家决策

**P0-1 名册卡片没有任何佣兵信息，玩家无法判断该买谁。**
卡片只有「名字·绰号 / 职业 / 稀有度 / 解锁价」（`TavernUnlockUI.cs:158-171`）。
H004 钢盾（5000 金）和 H007 大锤（600 金）在界面上长得一模一样——
看不到 HP/ATK/DEF/攻速/移速，看不到主动技与被动技。
项目已有 `MercPortraitSprites`（战斗角色栏在用）可以加载头像，但名册**连立绘都没有**。

**P0-2 22 张卡平铺、不排序、不分组。**
按 `MercRosterDefs.Table` 的原始顺序排（`TavernUnlockUI.cs:146-151`），
普通/稀有/传说混着排，已解锁和没解锁混着排。玩家要滚 3 屏才找到买得起的。

**P0-3 解锁后没有反馈闭环。**
解锁成功只弹一句 toast + 卡片变绿「已在招募池」（`:215-218`）。
玩家不知道"招募池"是什么、在哪抽、抽到之后会怎样。没有「去冒险试试」的引导。

### P1 —— 内容浪费与文案残留

**P1-1 `TavernLore` 整套叙事没接**（见 §3.3）。这是当前最大的内容浪费。

**P1-2 「招募」语义残留。**
- 成就 A009「酒馆常客」描述仍是「首次在**招募**佣兵」（`AdventureLogCatalog.cs:383`）
  ——判定已兼容（解锁会触发 `AdventureCodex.MarkMercSeen`），**只是文案没改**
- 名册按钮文案「已在**招募池**」（`TavernUnlockUI.cs:218`）
- `MercHireSession.AddHired` 里还在调 `AdventureLogAchievements.OnMercRecruited()`

**P1-3 预制体与代码文案不同步。**
`Recruit` 卡的标题/描述靠 `RetitleRecruitCard` 运行时覆盖，预制体里还是「招募」旧文案。
谁下次直接改预制体，旧文案就会露出来。**应该把文案写回预制体，删掉运行时覆盖。**

**P1-4 两张占位卡没清。**
「信任交流」「酒馆任务」被隐藏但没有实现计划，也没注释说明什么时候做。

### P2 —— 技术债

**P2-1 死代码 1000+ 行**（`TavernRosterPanel` + `MercenaryRecruitPopupUI` + `MercHireSession` 一半）。
风险不是体积，是**误导**：后来人看到 `MercHireSession.GoldCost` 会以为"还有金币招募"。

**P2-2 存档孤儿字段**：`mercScrollRare` / `mercScrollLegendary` / `hiredMercs` /
`mercOfferDayKey` / `mercOfferRefreshUtc` / `mercOfferDirty` —— 无写入方。
（建议**保留字段不删**，只清逻辑，避免旧档反序列化出问题。）

**P2-3 `TavernUI.GuildHideWhenTavern` 是空数组**（`TavernUI.cs:155`），
原意是"进酒馆时隐藏公会大厅的某些节点"，现在是空占位。

### 7.1 佣兵归属划分（22 = 商店 8 + 酒馆 14）

> **2026-09-17 二次修订**：初版按"解锁价 ≥1900"切（商店 7 / 酒馆 15），用户指出
> **好货应该只放酒馆**，于是改成**按稀有度切**——商店挂普通档直接卖，酒馆放稀有 + 传说。
> 设计依据见 `Docs/佣兵获取与定位设计_2026-09-17.md`。

`MercRosterDefs.Def` 新增 `SoldInShop` 字段，划分口径：**按稀有度**。

| 归属 | 数量 | HireId | 门槛 |
|---|---:|---|---|
| 商店直售 | 8 | 普通档 H001 H005 H007 H011 H015 H018 H019 H021 | **无门槛**（`showFromChapter = 0`） |
| 酒馆名册 | 14 | 稀有 11 + 传说 3 | 见下方条件表 |

三个传说（H004 钢盾 / H010 狂牙 / H014 火舞）**全部留在酒馆**，不进商店。

**酒馆 14 名的解锁条件**（`Config/MercUnlockGate.cs`）：
稀先用"已解锁人数"软门槛（5 / 7 / 9），高价稀有走通关第 2~3 章，
传说走通关第 4 / 5 / 6 章。条件文本直接印在卡面按钮上，并显示进度（如「解锁 7 名佣兵（5/7）」）。

> ⚠️ 原先的门槛是「酒馆 Lv2 / Lv3」，但**酒馆根本没有等级功能**
> （`townLevel.tavern` 是被 clamp 到 0~2 的残留字段，玩家看不到也升不了），已全部删除。

- 对外只暴露 `MercRosterDefs.TavernRoster` / `ShopRoster`，`All` 仍是全部 22 名（图鉴、解锁计数不受影响）。
- 商店商品**由 `ShopRoster` 程序生成**，不手写第二份价格表（`ShopDefs.BuildAll`），避免两处漂移。
- 商店侧无上架章节门槛（`showFromChapter = 0`），普通档直接挂卖。

### 7.5 复用冒险日志图鉴（`AdventureLogCodexPanel` + `AdventureCodex` + `CodexInfoPopupUI`）

用户提示"冒险日志已经做了佣兵图鉴，能复用就复用"。核对后发现**图鉴那一套正好覆盖名册缺的东西**，
于是把本轮新建的 `MercDetailPopupUI` 删掉，改成拼现成的：

| 图鉴已有 | 名册怎么用 |
|---|---|
| `CodexInfoPopupUI.Show(title, meta, desc, lore, sprite)`（立绘+标题+meta+描述+Lore 的信息弹窗） | **当二级详情弹窗直接用**。字段映射：title=`名字·绰号`／meta=`职业·稀有度·HP/攻/防/攻速/移速`／desc=`技能段+简介`／lore=`Lore` |
| `AdventureCodex.LoadMercHead(e)` / `LoadMercStand(e)` | 名册卡头像与详情立绘改走这个入口（内部就是 `MercPortraitSprites`，但多了 AssetId 兜底），两边口径统一 |
| `AdventureCodex.GetMercRarity(e)` / `IsMercRevealed(e)`、按稀有度分三组的 `SpawnMercSection` | 稀有度口径统一（名册仍用 `MercRosterDefs` 直取，因为商店不需要"未结识剪影"）；分组逻辑暂不搬，名册按购买力排序更合用 |
| `AdventureLogCatalog.Mercs`（22 条含 Desc + Lore） | 详情的简介与 Lore 直接读，**零新增文本** |

新增的唯一小工具：`AdventureLogCatalog.TryFindMerc(id, out entry)`（按 H/C 编号查条目），
给名册、商店、图鉴三方共用一个查找入口，避免各写一遍线性查找。

**取舍（已知代价）**：`CodexInfoPopupUI` 是预制体弹窗，**没有按钮位**，
所以二级详情里不能直接解锁——玩家要关掉弹窗再点卡面上的「解锁 xxx」。
若想要"详情里直接买"，得给 `Resources/Prefabs/Town/CodexInfoPopup` 加一个按钮节点（动预制体，本轮没做）。

另外：名册点开详情**不调 `MarkMercViewed`**，在商店里看图不该消耗图鉴红点。

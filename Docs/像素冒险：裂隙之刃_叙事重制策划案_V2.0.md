**新增核心设定：年年逛街 = 例会**

> 公会高层知道沉座需要"容器"。与其等它自己失控，不如**定期送一支够强的小队进去**——让他们当临时容器，拖住裂隙扩张几年。

> **第七次，轮到艾丽娅小队。**
> 而每一支被送走的小队的补给箱，都是同一个人装的。她在每一个箱子里塞了同一张纸条，署同一个名字。

## 3. 双结局与关键转折点

### 3.1 转折点设计原则

按抉择必须有**种类差异**（不是程度差异）的标准设置。三个选项是三种**不同的价值观**，不是同一件事的三种语气：

| 选项 | 你选择的东西 | 你放弃的东西 |
|---|---|---|
| **A** | 她这个人（现在、立刻） | 交代、真相、以后所有的可能 |
| **B** | 一个交代（和她一起去赌） | 安全；她可能会死在路上 |
| **C** | 所有人（让她成为封印） | 她这个人 |

**没有任何一个选项是"最优解"。** 这是它有分量的原因。

### 3.2 结局总表

| 结算标题 | 代号 | 达成条件 | 到底发生了什么（= 结算画面第二行） | 定位 |
|---|---|---|---|---|
| **《回来的不是她》** | `BAD_END_HOME` | Ch7 选 **A** | 你把她背了回来。但她每隔几天就忘一件事。 | BAD · 苦涩偏温柔 |
| **《回来的是两个人》** | `HAPPY_END` | Ch7 选 **B** | 沉座碎了。你们一起走出裂隙，天亮得刺眼。 | HAPPY · 第一周目多数人走这条 |
| **《留下的是她》** | `BAD_END_GATE` | Ch7 选 **C** | 她坐进沉座成了封印。世界保住了，她没回来。 | BAD · 苦涩偏壮烈 |
| **《最后一个箱子》** | `TRUE_END` | 选 **B** ＋ 三条支线全通 ＋ 集齐 5 份关键日志 | 梅莉莎装了十一年箱子。今天她不用装了。 | TRUE · NG+ 隐藏 |

> 用户要的"happy / bad 两种"由此满足：B 通向 HAPPY；A、C 通向两种风味不同的 BAD；TRUE 是给愿意玩三遍的人的奖励。
> **标题就是给玩家看的，代号只是给程序用的** —— 结算画面显示中文标题，`HAPPY_END` 这类只出现在代码和图鉴排序里。

### 3.3 结局判定（伪代码，可直接实现）

```csharp
// SaveData 新增字段，见 §9.1
public enum EndingId { None, Happy, BadHome, BadGate, True }

public static EndingId ResolveEnding(SaveData d)
{
    // 1) 先看 Ch7 的选择
    if (d.endingChoice <= 0) return EndingId.None;

    // 2) BAD 分支：立即结算，不需要任何附加条件
    if (d.endingChoice == 1) return EndingId.BadHome;   // A：带她回去
    if (d.endingChoice == 3) return EndingId.BadGate;   // C：让她坐上去

    // 3) B：判定是否达成真结局
    bool allBranches = d.HasClearedChapter(2)
                    && d.HasClearedChapter(3)
                    && d.HasClearedChapter(4);
    bool allKeyLore  = StoryClue.HasAll(d, StoryClue.KeyFive);  // 见 §6.4

    return (allBranches && allKeyLore)
        ? EndingId.True
        : EndingId.Happy;
}
```

> **注意**：`A / C` 不需要任何前置，**第一次就能选**。真结局的门槛只加在 `B` 上——这样重玩的动力来自"我想看更好的那个"，而不是"我必须先满足一堆条件才能看懂"。

### 3.4 四份结局演出文案 → 见 §5 的 N8 节点

### 3.5 结局标题为什么改成了这样（命名规则）

**旧标题的共同毛病**：《替你把名字要回来》《门》《装箱的人》用的都是**必须先懂设定才能解码的核心意象** —— 「名字」要打到第 2 章的第八块空碑才懂，「装箱的人」要打到 TRUE 才懂，而《门》连一个明确指向都没有。玩家在结算画面上看到的是四个谜语，不是四个结果。更糟的是旧稿 §3.2 写着《装货的人》、N8 小节写着《装箱的人》，两处自己就没统一。

**新标题的四条标准**：

1. **结果先于隐喻** —— 标题回答"发生了什么"，不回答"这象征什么"。
2. **≤ 7 个汉字** —— 竖屏 720 宽，标题区不折行。
3. **不看配色也能分辨好坏** —— 情绪方向写在标题里，不依赖 HAPPY 绿 / BAD 红的配色。
4. **三个主线结局共用同一句式** —— 一句话的三种填法，扫一眼就知道彼此差别。

于是三个主线结局是同一句话的三个版本：

> 回来的**不是她**　｜　回来的**是两个人**　｜　**留下的是她**

A 是"回来了一个，但不是她"；B 是"回来了两个，都是本人"；C 是"没回来，她留在里面"。三者互为对照，不需要读剧情也能明白自己选了什么。

> **已定案（主创拍板）**：TRUE 结局标题 = **《最后一个箱子》**。另一个候选《不用再装箱了》已从全稿移除——它太口语，且会把梅莉莎那句"今天开始，我不用装了"提前剧透。图鉴、结算画面、台词三处一律只写《最后一个箱子》。

### 6.4 关键线索判定实现

```csharp
public static class StoryClue
{
    public static readonly string[] KeyFive = { "C02", "C08", "C11", "C13", "C17" };

    public static bool HasAll(SaveData d, string[] ids)
    {
        if (d?.seenClueIds == null) return false;
        for (int i = 0; i < ids.Length; i++)
            if (!d.seenClueIds.Contains(ids[i])) return false;
        return true;
    }
}
```

## 7. 酒馆叙事系统

### 7.1 酒馆承担三件事

1. **世界观补充**（Tier-2/3，不影响主线可读性）
2. **佣兵侧写**（把现有 22 条佣兵 Lore 变成"会说话的角色"，零新增文本成本）
3. **二周目钩子**（下面最重要的那个"空座位"）

### 7.2 ★核心道具：靠窗的空座位

这是整套酒馆叙事里成本最低、收益最高的一个设计。它是**周目之间的情感锚点**，玩家每次回城都会去看一眼。

| 周目 / 进度 | 座位上的东西 | 点击显示 |
|---|---|---|
| 第 1 周目 · 第 1 章 | 一枚 **三枚铜板**压着的收据 | "出发前她在这儿坐着，说回来就还。到现在也没还。" |
| 第 1 周目 · 第 5 章后 | 铜板旁边多了一张**纸条** | "「如果你也下来了……小心公会。——M」<br>她留的位置上的东西，被人动过。" |
| 第 1 周目 · 第 7 章后 | 座位上摆着她**从不离身的发绳** | "有人替她把这东西带回来了。<br>但人还没回来。" |
| 通关后（任意 BAD 结局） | 三个空杯 + 一个没动过的杯子 | "她的杯子一直没人收。<br>老板娘说，她欠着酒钱呢。" |
| 通关后（HAPPY 结局） | 四个杯子，其中一个收起来了 | "有个人终于回来把酒钱结了。<br>老板娘说她还多付了一倍。" |
| `TRUE_END` 后 | 座位上多了一支笔 | "老板娘也不解释。<br>只是每个月的今天，桌上都会多一份没人吃的面包。" |

> **实现**：一个可在 `TavernUI.BuildContentOnly()` 里挂载的交互 hotspot + 6 条文本。这是整个 V2.0 里**性价比最高**的一处——它让"回城"这件事有了叙事理由，而这正是 roguelite 循环里最容易被浪费的触点。

## 8. 二周目吸引力设计

### 8.1 钩子链（让玩家知道有下一次）

```
第一次通关 Ch8
    │
    ▼
【强制演出】裂隙第二层还有两条岔路 → 揭幕 Ch3 / Ch4
    │
    ├─► 分支 Ch3：遇到梅莉莎（M）              → 拿到 C08 关键线索
    ├─► 分支 Ch4：知道你自己的名字也在表上     → 拿到 C11 关键线索
    │
    ▼
三条支线全通 + 五份关键日志 + 第七章选 B
    │
    ▼
TRUE_END《最后一个箱子》
```

> ⚠️ **必做**：Ch8 通关后的"岔路揭幕"演出不能省。**现有代码里 Ch3/Ch4 只是静默解锁**（`needCh8Clear`），玩家很可能根本不知道它们的存在。加 4 句 narration 即可。

```csharp
StoryDirector.Narration("回城的路上你数了数。裂隙第二层往下，还有两条从来没人走过的岔路。")
StoryDirector.Narration("登记簿上，那两条路有人写过一批队号——比你要早得多。")
StoryDirector.Solo("你", "还有两条。", StoryPortraits.Player)
StoryDirector.Narration("——第 3 章、第 4 章 已开放。选择下一条路线可在冒险入口查看。")
```

### 8.2 中间奖励（不能只有最终那个大饼）

| 达成 | 奖励 |
|---|---|
| 走过 **2** 条支线 | 称号「走得深的人」+ 金币 5000 + 独家日志页 `C26` |
| 走过 **3** 条支线 | 限定头像框「三年」+ 世界条目 `W011 第八条的上一个名字` |
| 集齐 **5 份关键日志** | 解锁日志"线索墙"页签（把关键线索按时间排成一条线） |
| 达成 **TRUE_END** | 结局徽章 + 梅莉莎相关外观 + 结局图鉴全解锁 |

### 8.3 为什么这套能留住人

它不是"重玩一遍剧情"，而是 **"换一条岔路，补一块拼图"** ——每一周目拿到的都是**之前那一遍缺的那块**。这是 roguelite 用户最熟悉、也最能接受的"收集驱动"形式。

## 11. 给主创的三句话

1. **这一版最大的结构性收益是"主线能独立看懂"。** Ch3/Ch4 被锁在 NG+，意味着它们只能做加分项；把必需信息全部压到 Ch1/Ch2/Ch5–Ch8 之后，新玩家再也不会因为漏看东西而掉队，而老玩家每多走一条岔路就多一块拼图。

2. **最高性价比的两个改动**：把 `LoadingTips` 按章节分级（<30 行），以及给酒馆加"靠窗的空座位"（1 个 hotspot + 6 段文本）。前者止损，后者直接产出二周目回头率。

3. **第七章的三选一是全篇唯一不可撤销的东西。** 建议不仅写进存档，还要在 UI 上明确告知"此选择将影响结局"——这样它才真正有重量，也才真正承担得起你要的双结局。

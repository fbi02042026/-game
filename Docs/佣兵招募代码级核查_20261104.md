## 二、A 确认的 bug（可静态证死）

### A1 扣费成功、解锁/发碎片失败时不回滚（玩家白花钱）
- 位置：`MercenaryRecruitPopupUI.Actions.cs:171-177`（首次购买）、`:249-254`（重复购买）
- 逻辑：先 `TrySpend(Gold)` / `TrySpendScroll`，再 `UnlockMerc`；`UnlockMerc` 返回 false（hireId 为空 / 存档为空）时只 `Debug.LogError` + Toast「购买失败」，**钱不退**。
- 触发条件：`offer.hireId` 与 `mercId` 都解析不出花名册（脏存档/表缺失），或 `SaveSystem.Instance.Data == null`。
- 影响：资源已扣、佣兵没到账。虽属边缘路径，但代码里自己写了「钱已扣，需主人确认是否补发」，等于承认未处理。
- 最小修法：把扣费挪到「能解锁/能发碎片」之后；或在失败分支显式回补（`ResourceWallet.Add` / 卷轴 +1）。

### A2 重复购买转碎片：碎片发放 0 时同样白扣
- 位置：`MercenaryRecruitPopupUI.Actions.cs:248-254`
- `ConvertDuplicateMerc` 内部 `DupFragCountOf(def)` 返回 0（`MercGrowInventory.cs:318-323`）时返回 `default`，UI 只报错不退款。
- 触发条件：花名册 Def 解析成功但 `DupFragCountOf` 结果为 0（表/口径缺失）。

### A3 列表「替换」失败分支会刷 Error 日志但不提示玩家
- 位置：`MercDrawPoolUI.Swap.cs:120-125`
- `AddToDrawPool` 返回 false 且 `_picked.Count < data.DrawPoolSlots` 时，只 `Debug.LogError`，界面无任何提示（玩家点了替换像没反应）。
- 触发条件：重复入队 / `DrawPoolSlots` 与 `_picked` 不同步（存档被外部改动、读档后未 `ReloadPicked`）。

> 说明：A1/A2 都是「钱已扣」类；A3 属「静默失败」。三者都不算高频，但都违反项目口径「出错要让我看见」。

## 四、C 可优化建议

1. **价格/扣费与到账顺序**：统一改成「先校验可解锁 → 扣费 → 写入」，从根上消除 A1/A2。
2. **失败提示**：`MercDrawPoolUI.Swap.cs:120-125` 的 Error 分支补一条玩家可见 Toast（如「入队失败，请重开界面」）。
3. **立绘缺失**：`Cards.cs:61` 灰块 + `PortraitIdleMotion` 关闭，建议补 `Debug.LogWarning("[MercRecruit] 立绘缺失 key=...")`，出问题能定位，不改变表现。
4. **去重兜底**：`OfferGenerator.cs:58-64` 撞满 24 次后放行重复，可改成「用已选集合外的最小可用集合」而不是直接重复，避免「三张同脸」。
5. **价格口径统一**：普通涨价、稀有/传奇不涨，建议在概率公示弹窗（`Actions.cs:277-313`）补一行价格规则说明，减少玩家困惑。
6. **`MercHireSession.CanHireMore / HiredCount / AddHired`**（`:32-53`）已是旧「临时雇佣」口径，招募不再调用；若确认无调用方可标 `[Obsolete]` 或删除，防后来人误用（`hiredMercs` 仍被战斗临时队使用，先只加注释更安全）。
7. **列表排序**：已获得按「稀有度降序 + 获得顺序」（`MercDrawPoolUI.Art.cs:70-77`），未获得按稀有度分组（`MercDrawPoolUI.cs:380-408`）——两段规则不同，建议在界面加段头小字（如「按获得顺序」）避免玩家以为排序坏了。

## 一、玩法一句话

道具从天而降，玩家左右滑动主角用竹篓接住，道具落入底部"合成大西瓜式"物理容器**堆叠（不合成）**；混在里面的炸弹**碰到谁炸谁**；堆到警戒线 **或** 60 秒到，即结算。

## 二、定稿规则（主人已逐条拍板）

| # | 规则 | 内容 |

## 三、界面布局（示意已与主人对齐）

竖屏 720×1280，自上而下：

1. **顶栏**：左侧分数，右侧 60s 倒计时（末 5 秒变红放大跳动）；
2. **下落区**：金币/钻石/礼物 + 两种炸弹随机掉落（炸弹红闪）；
3. **主角区**：主角 + 头顶竹篓（竹篓图待主人提供，定"顶头上还是抱手里"），底部左右滑动操作；
4. **容器区**：大西瓜式 U 形物理容器，道具物理堆叠，容器口**红色警戒虚线**=满判定线。

**尺寸适配四原则（图片大小不一致的解法，主人点名要求）：**

1. **统一槽位等比缩放**：所有道具渲染进统一逻辑槽位（S=72 / M=96 逻辑 px），按最长边适配、居中、**不拉伸**；
2. **价值区分靠档位框，不靠图本身大小**：普通 S、稀有 M+金描边、炸弹 S+红描边闪烁；
3. **碰撞与视觉解耦**：接取/爆炸判定用统一碰撞半径（上表），不跟图片实际像素走——大图小图手感公平；
4. **表驱动**：新增道具只填表不改代码。

## 五、难度曲线（60 秒）

| 时间段 | 生成间隔 | 下落速度倍率 | 炸弹实际占比 |
|---|---|---|---|
| 0–20s | 1.2s | 1.0 | 10% |
| 20–50s | 渐降至 0.6s | 渐至 1.4 | 10%→20% |
| 50–60s | **0.45s（狂潮）** | 1.5 | 25% |

- 末 5 秒倒计时数字变红放大跳动；
- 炸弹占比按时间动态放大表内基础权重，普通道具等比压缩。

## 六、奖励发放（2026-10-27 主人改定：**实物直发，无积分无兑换**）

- **接到即得**：
  - 金币接到 1 个 = **+1 金币**（直入钱包）；
  - 钻石接到 1 个 = **+1 钻石**；
  - 礼物接到 1 个 = **接到什么给什么**——按品质几率抽 1 件，进好感礼物库存 `SaveData.favorGifts`（现成通道）；
  - 炸弹无奖励（纯风险物）；
- **礼物品质出现几率（草版）**：普通 70% / 稀有 25% / **传奇 5%**；🔴 传奇=好感体系稀缺货（里程商店每日传奇礼物限购 800 里程币），建议**每日限 1 个**防刷好感，待主人拍板（§九-5）；
- **发放时机**：接到**实时入账**（顶栏钱包数字跳动，爽感强），结算面板给本局实物汇总；
- **单局预期产出（按 §四权重粗算）**：60s 接 15–25 个 → 金币 8–13 / 钻石 2–4 / 礼物 1–2；一天 3 局 ≈ 金币 30 / 钻石 9 / 礼物 4–5——对钻（加号定价 50/100）不通胀；
- 连击降级为纯爽感表现（§二-9）；
- **无积分、无兑换、无新增存档结构**。

## 十、施工红线

- 不许为救断链兜底；禁止删掉重建；改前先问；
- Canvas 一律摄像机模式 `UICanvasSetup.ApplyPopup`；确认弹窗走 `StaminaConfirmPopup`；
- 五坑照避：构造期禁读表 / 编辑模式禁 DDOL / 代码建 UI 的 `Build()` 开头倒序销毁旧 Root / 运行时建树 `Build()` 末尾 `SetActive(false)` / 编辑器自动脚本永久禁用；
- 🔴 **同一张图禁止存两份**（56 字符重导复发）；
- 物理稳定性参数是**验收项不是可选项**（§八-5）；
- 文案按年轻化调性（参考"我勒个豆"），结算/引导文案 ≤7 汉字、结果先于隐喻；
- 汇报讲人话；取不到资源直接 `LogError`，不兜底。

## 一、检测结论：为什么蓝的都是两星（主人点名要查）

### 1. 根因（一行代码写死，与任何配置表无关）

`Assets/Scripts/Config/RiftEquipGenerator.cs:208-210`

```csharp
inst.rarity = MapToEngineRarity(rarity.Id);
inst.star = Mathf.Clamp((int)inst.rarity - 1, 0, (int)inst.rarity);
inst.requireLevel = 1;
```

稀有度枚举 `EquipTemplate.cs:8-15`：`Common=1 / Uncommon=2 / Rare=3 / Epic=4 / Legendary=5`。
代入得 **白 0★ / 蓝 2★ / 金 4★**。`Clamp` 上界 `(int)rarity` 恒大于 `rarity-1`，等于没生效。
结论：**稀有度单向决定星级，无随机、无查表、无区间**，蓝色恒定两星。

### 2. 抽奖链路只产三档，绿/紫永不出现

| 环节 | 位置 | 事实 |
| --- | --- | --- |
| 权重真源（硬编码章节曲线） | `RiftEquipGenerator.cs:271-284` | 只有 `wNormal / wRare / wLegend` |
| ID→枚举映射 | `RiftEquipGenerator.cs:721-729` | 只认 `RARE / LEGEND / default(NORMAL)` |
| 掷骰 | `RiftEquipGenerator.cs:286-315` | 权重和=100；无传奇硬保底；`forceAtLeastRare` 只保底非白 |

白色实例真 star=0，但卡面被 `DraftPool` 抬成 1★显示 → 玩家看到 1★/2★/4★，3★、5★ 是空的。

### 3. 一句话诊断

**不是蓝色概率低，是蓝色拿到手永远两星、同档内没有成长维度**——这是"没有递进感"的数据层根因。定稿用「装备评分」解决（见四）。

## 四、🔴 定稿口径（主人 2026-11-19 拍板，开发照此落地）

### 1. 带出范围：穿在身上的**全部装备**都带

不只是武器——**武器 + 防具，穿戴中的都带出**。抽取/未穿戴件照旧清零。

### 2. 死亡处理：死亡一样带出

通关、死亡、撤离、直进下一关——**所有结束方式都带出**，无差别。

### 3. 职业分库：玩才积累，否则一直空

- 持久库**按职业分**（`PlayerJobId` 分键）。
- **只有切换/使用该职业打战斗并获得装备，才积累该职业的库**；没玩过的职业库**一直是空的**。
- 切职时只穿该职业自己攒的装备，不跨职业借用。

### 4. 装备评分：攻击强度的参考基准（锚敌人血量，非纯展示）

新增**装备评分** `qualityScore`，生成时按稀有度在对应区间内取值：

| 稀有度 | 评分区间 |
| --- | --- |
| 普通（白） | **10 – 30** |
| 稀有（蓝） | **31 – 50** |
| 传奇（金） | **51 – 100** |

**口径（2026-11-19 主人拍板）**：评分是**攻击强度的参考值**，且攻击强度**按敌人血量锚定**——不是纯展示、也不锚敌人攻击。

#### 4.1 换算公式

```
装备攻击 ≈ 本章普通怪平均血量(avgHp) × 评分系数 k(qualityScore) × chapterGrowth
```

- `avgHp` 取 `MonsterStatsTable.TryGetChapterAverage(chapter, out avgHp, out _)`（现有接口已同时给 avgHp/avgAtk，见 `MonsterStatsTable.cs:130-153`）。
- `chapterGrowth` 复用现有章内爬坡（`RiftEquipGenerator.cs:97-98`，chapter_stat_scale × stage_stat_scale）。
- **⚠ 重要事实**：当前代码锚的是敌人**攻击**（`EnemyAvgBaseAtk` → `avgAtk`，`RiftEquipGenerator.cs:599-607`），改锚血量是**换基准**，`combat_tuning.csv:16-21` 的三档系数（白1.2-2.0/蓝2.6-3.6/金4.8-6.8）作废、需整表重标。

#### 4.2 评分→系数 k 建议映射（试玩标定，非拍死）

| 评分 | k | 对普通怪约几刀（仅武器、不含等级/天赋/佣兵） |
| -- | -- | -- |
| 10 | 0.12 | 8.3 |
| 20 | 0.18 | 5.6 |
| 30 | 0.24 | 4.2 |
| 31 | 0.25 | 4.0 |
| 40 | 0.30 | 3.3 |
| 50 | 0.36 | 2.8 |
| 51 | 0.38 | 2.6 |
| 70 | 0.50 | 2.0 |
| 100 | 0.75 | 1.3 |

- 白 30 → 蓝 31 几乎连续（k 0.24→0.25），满足"蓝色和普通差距不大"。
- 传奇 51→100（k 0.38→0.75）跨度拉开，高评分有明确获得感。
- **k 的绝对值必须按真机手感标定**：上面的刀数是"纯武器"理论值，实际玩家还有等级/天赋/佣兵加成，真实刀数会更少。先按此方向落，跑一版看击杀手感再回调。

#### 4.3 跨章贬值（设计意图，非 bug）

- 装备攻击锚"当前章血量"，同一件装备带到更高章，`avgHp` 变高 → 装备相对变弱。
- 这是**有意为之**：促使玩家持续获得更高评分/更高章装备，避免"一把传奇用到毕业"。**不要为了让老装备保值而改成"记录获得时血量"**（会让后期玩家无动力换装）。

#### 4.4 敌人难度曲线补偿（装备带出后的平衡）

**问题**：装备可带出后，玩家整体战力永久上浮（相当于白嫖一层 buff）；若不调敌人，游戏会越玩越简单。

**方案**：整体上调怪物血量/攻击一个小幅度，作为"带出战力增量"的抵消。

- **幅度建议**：按"玩家把 1-2 个槽位持久武器养到中期（评分 40-60）时战力约 +20%~30%"估算，**敌人 baseHp / baseAtk 整体上调 8%~15%**（先取 10% 试水）。
- **落点**：优先调 `monster_stats.csv` 的 `baseHp`/`baseAtk`（全局锚点，一改全章生效）；或调 `chapter_stat_scale.csv` 的 statScale（按章微调）。**推荐前者**，因为它是所有敌人强度的本源。
- **⚠ 先测后调**：必须在 T1-T4 落地、跑出"玩家带出装备后的实际战力曲线"之后，再定具体百分比。**不要现在就拍死数字**——装备带出是渐进的，补偿也应分章渐进（前 2 章玩家还没攒出装备，补偿应低于后期）。
- **红线**：补偿不得变成"凭空加难度"。优先靠"新增的持久装备战力"去填，补偿只是抹平溢出，不是额外施压。

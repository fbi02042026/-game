## 一、结论摘要

**现在不能提交审核上线。** 技术上「首包体积」这个最初最担心的点已经天然达标（主包 0.99MB + wasm 分包 8.2MB，官方插件托管引擎），但游戏**从未在微信开发者工具/真机上完整跑通过一次**——Boot→城镇→战斗→存档全链路在微信端全部是「代码就绪、零实测」状态，且静态核查发现 **Town/Battle 两场景在构建场景列表里是 disabled**，若转换工具按该列表出包，进主城必然失败（需第一个验证）。数据侧 webgl.data 103MB 未压缩、CDN 未配，真机拿不到资源。商业化侧广告位 ID 为空、广告总闸关闭（当前靠钻石补贴撑着），流量主未开通。合规侧备案未启动（强制，13-37 个工作日）、隐私协议页面还指向 TapTap。最硬的阻塞不是代码，是**备案周期**和**流量主 UV≥500 门槛**这两个外部时钟。

## 六、微信开发者工具验证清单（按优先级排序，主人家里自测用）

> 前置：微信开发者工具 → 导入项目 → 选 `Y:/PixelAdventureTown/Builds/wechat/minigame/`（AppID 已在 project.config.json）。
> 建议先把工具里「详情 → 本地设置」的**不校验合法域名**勾上（AdKillSwitch 拉 gitee 必失败，不勾会多一条无害报错干扰视线）。
> 每项按「验什么 / 怎么验 / 预期 / 失败最可能原因」给。

**V1 🔴 场景进包（最高优先，第一个测）**
- 验什么：Town/Battle 是否真的打进了包（`EditorBuildSettings.asset` 里两场景 `enabled: 0` 是本次体检最大疑点）。
- 怎么验：启动后走完登录 → 点「开始冒险」进主城 → 选关进战斗。
- 预期：登录页 → 主城 → 战斗场景都能进，Console 无 `Scene ... couldn't be loaded` 红字。
- 失败最可能原因：转换工具按 EditorBuildSettings 列表出包，Town/Battle 被排除 → 在 Build Settings 里把两场景勾上启用后重新转换。

**V2 🔴 Console 零红字（首帧报错排查）**
- 验什么：启动到进主城全程的报错。
- 怎么验：开着 Console 走完 V1。
- 预期：零红字（黄字 Warning 可记录后放行）。
- 失败最可能原因：IL2CPP 裁剪把某序列化类型裁掉 / SDK 初始化时序 / 11-02 换发 guid 的 8 个音频被 prefab 引用断链（表现：音效 Missing 而非红字，见 V6）。

**V3 🔴 存档读写与恢复**
- 验什么：wx 沙箱里 PlayerPrefs + persistentDataPath 文件 IO 是否通。
- 怎么验：进游戏打一场领奖励 → 完全关掉小游戏（工具里点「切后台」再「关闭」，或清模拟器进程）→ 重进。
- 预期：金币/钻石/关卡进度都在；`player.dat` 写入沙箱（工具「文件系统」面板可见）。
- 失败最可能原因：SDK 文件系统映射未生效 → 看 Console 有无 IO 异常；若进度丢但无报错，查 `SaveSystem` 的版本比对清档逻辑是否被触发（Application.version 不一致会清档）。

**V4 🔴 切后台 / 回前台**
- 验什么：wx.onHide/onShow → OnApplicationPause 链路。
- 怎么验：战斗中点工具「模拟操作 → 切后台」→ 5 秒后切回。
- 预期：回前台战斗继续、不卡死、体力/计时正确；无 `interrupted` 引发的连锁报错。
- 失败最可能原因：后台期间未完成网络请求被微信中断（本项目仅 AdKillSwitch 一处，已按失败无害设计）；若 timeScale 定格查剧情/结算残留。

**V5 🟡 视频跳过守卫**
- 验什么：`#if UNITY_WECHATMINIGAME` 三处 VideoPlayer 跳过是否生效（P3-A 铁证）。
- 怎么验：全新存档（工具里清数据或点清档重置）从头进 → 开场视频与登录视频应直接跳过。
- 预期：不出现任何视频播放/黑屏等待，直接进登录页。
- 失败最可能原因：宏未生效（说明转换目标没定义 UNITY_WECHATMINIGAME，连带影响所有平台分支代码，要回头查构建配置）。

**V6 🟡 音频播放**
- 验什么：Vorbis + 单声道转码后的 BGM/音效在微信 WebAudio 下播放。
- 怎么验：主城听 BGM → 战斗听打击音效与胜负 Sting。
- 预期：正常出声、无爆音；重点听 11-02 换发 guid 的 8 个音频（战斗胜利/失败等）是否 Missing。
- 失败最可能原因：换发 guid 断链（按口径修 guid 或预制体重拖，禁止兜底）/ Vorbis 解码兼容（转 AAC 重导）。

**V7 🟡 触摸与 UI 适配**
- 验什么：按钮点击、摇杆、瘦屏/刘海/微信胶囊按钮避让。
- 怎么验：工具里切换不同机型（iPhone 刘海屏 + 瘦长屏）各走一遍主城/战斗。
- 预期：按钮都可点、顶栏不被刘海/胶囊遮挡、底栏不超屏。
- 失败最可能原因：SafeAreaFitter 拿不到胶囊坐标按常量预留（`SafeAreaFitter.cs:45`），个别机型偏差 → 真机复核。

**V8 🟡 广告占位行为（空窗期口径）**
- 验什么：广告总闸关闭期各入口表现。
- 怎么验：点顶栏钻石「看视频领钻」、金币/体力加号。
- 预期：「暂未开放」提示或钻石档确认框，**无报错、无卡死**；战斗复活走 10 钻确认。
- 失败最可能原因：漏网广告路径没接 PlatformClosed 闸（查该入口脚本）。

**V9 🟢 转发（无奖励）**
- 验什么：右上角「…」→ 转发卡片。
- 怎么验：工具里点胶囊「…」菜单看转发项；真机预览时实际转发一次看卡片。
- 预期：卡片标题 = 「割草爆装，招募佣兵，技能流派自由搭，一局 5 分钟」+ 5:4 封面图；**全程无任何奖励发放**（分享得钻已下线，胜利界面应无分享按钮——顺手确认这一点）。
- 失败最可能原因：`WeChatShare.jslib` 未随包 / 封面图 meta isReadable 未开（Console 有 `[WeChatShare]` 红字）。

**V10 🟢 性能与首屏**
- 验什么：帧率与加载时长基线。
- 怎么验：工具 Performance 面板看战斗帧率；记录启动到可点的时长。
- 预期：战斗流畅（低端机锁 30fps 口径）；首屏时长记录留档（CDN 落地后再正式对 <8s 目标）。
- 失败最可能原因：data 103MB 本地加载慢属已知（T4 压缩+CDN 后复测）。

**真机预览（V3/V4/V6/V7/V9 在真机各复跑一次）**：开发者工具「预览」扫码；重点复测存档恢复、音频、胶囊避让、转发卡片——这四项模拟器与真机差异最大。

1. **今天**：P0-1 开发者工具验证（所有后续判断的事实基础；先确认场景进包）→ 顺手补 .gitkeep meta。

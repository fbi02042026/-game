## 二、拍板口径（2026-10-24）

1. **不保底传奇** —— 传奇纯靠几率，不做任何 N 抽保底金。
2. **保底稀有** —— 装备方向每 5 次抽奖保底 1 次「稀有及以上」（蓝或金）；连续白卡计数，第 5 次强制稀有。
3. **传奇几率调高** —— 章节曲线 Ch2-Ch8 的 LEGEND 列上调；**RARE 列一律不动**（10-12 拍板的稀有梯度 20/25/30/35 保持）；**Ch1 恒 0 不动**（引导章设计）。
4. **别的按架构方判断执行** —— 见第六节「已决策不做项」，均有理由，不擅自扩大战场。

  | Ch1 | 80/20/0 | **80/20/0（不动）** | 0 |
  | Ch2 | 74/25/1 | 72/25/**3** | 3% |

  思路：LEGEND 增量全部从 NORMAL 抠，RARE 列零变动；Ch1 双保险（曲线 0 + RollRarity 的 `chapter<=1 → w=0`）保持。函数头注释补「2026-10-24 主人拍板：传奇列上调（0/3/5/7/7.5/10.5/12.5/14.5），Ch1 恒 0 不动」。

- **风险**：低。纯数值，概率公示弹窗（BuildOddsRows）同源现算自动同步，无第二处要改。

### T2 生成器加「保底稀有」参数（透传链）

- **文件**：`Assets/Scripts/Config/RiftEquipGenerator.cs`（`Generate` 19 行 / `GenerateOne` 32 行）、`Assets/Scripts/Managers/ConfigManager.cs:147`（`GetRandomEquipInstances`）
- **做法**：
  1. 两个函数签名末尾加 `bool forceAtLeastRare = false`（默认参数，既有 6+ 调用点零改动；`GetRandomEquipInstances` 同步加并转调 `Generate` 时带上）。
  2. `GenerateOne` 内 `RollRarity(chapter)` 之后、`PickSlot` 之前插保底升档：
     ```
     if (forceAtLeastRare && !fixedForTutorial && rarity != null && rarity.Id == "NORMAL")
     {
         var rareRule = FindRarityRule("RARE");
         if (rareRule == null || rareRule.Id != "RARE")
             Debug.LogError("[RiftEquipGenerator] 保底稀有取不到 RARE 品质规则，本次保持 roll 出的品质，不静默升档");
         else
             rarity = rareRule;
     }
     ```
     ⚠ `FindRarityRule` 失败时返回 `FallbackRarity()`（Id=NORMAL）而非 null，**必须用 `.Id != "RARE"` 判失败**（fail closed：LogError + 保持原品质，让主人看见，不静默换档）。
     ⚠ `!fixedForTutorial` 是双保险：引导局恒白（10-12 拍板「每次引导战力一样」）绝不被保底污染。
  3. rarity 换成 RARE 后，下游（PickVisualTemplate 按 rarityId 分档 / inst.rarity / star / 词条数 AffixMin~Max）自动一致，**不需要**任何额外改动——这是选在 RollRarity 之后升档的原因。
- **验收**：forceAtLeastRare=true 时产出必为 RARE/LEGEND（表缺 RARE 行时 LogError 且仍可能出白——fail closed 可见）；fixedForTutorial=true 时保底无效；引导三拍战力与现网一致。
- **依赖**：T1 可并行（同文件不同函数，注意合并时别冲突）。
- **风险**：低。默认参数兼容；`Generate` 的 `job` 从 `PlayerJobDefs.GetSelected()` 取，链路不变。

### T4 保底三件套（SlotMachineSystem，同构 _goldPrizesThisRun / MercGuaranteeActive）

- **文件**：`Assets/Scripts/Systems/SlotMachineSystem.cs`（407-431 行区域之后追加）
- **做法**（严格同构抽奖币计数三件套 + 保底佣兵触发条件模式）：
  1. `static int _equipWhiteStreak = 0;` —— 本局装备方向连续白卡数（跨关不清、每局归零）。
  2. `public static bool EquipRareGuaranteeActive() => !IsTutorialRun && _equipWhiteStreak >= SlotMachineDefs.EQUIP_RARE_GUARANTEE_EVERY - 1;` —— **触发条件唯一出口**（同 MercGuaranteeActive 模式；引导局不保底）。
  3. `public static void ResetRunEquipWhiteStreak() => _equipWhiteStreak = 0;` —— 每局清零（唯一调用点 T7）。
  4. `public static void NoteEquipDrawResult(DraftCard card)` —— **生效出口，唯一调用点 T8**：`card.Rarity == SkillRarity.Common` → `_equipWhiteStreak++`；否则 `= 0`。（DraftCard.Rarity 是 SkillRarity，MapRarity 已把 EquipRarity.Common → SkillRarity.Common。）
  5. 每个函数带「2026-10-24 主人拍板」注释 + 引用先例（_goldPrizesThisRun / MercGuaranteeActive）。
- **验收**：streak 语义 = 「本局已生效的装备抽奖里连续几张白」；非装备卡（技能/佣兵/金币）不碰 streak。
- **依赖**：T3。
- **风险**：低。纯新增静态状态，不动既有抽数/ gold 计数。

### T5 DraftPool 接线（CollectEquipCards → PickOne）

- **文件**：`Assets/Scripts/Config/DraftPool.cs`（CollectEquipCards 470 行 / BuildWeightedPool 146 行 / PickOne 184 行）
- **做法**：
  1. `CollectEquipCards(bool forceAtLeastRare = false)`：503 行 `GetRandomEquipInstances(...)` 调用末尾加实参 `forceAtLeastRare`；`tutorialFixed` 与保底互斥已由 T2 的 `!fixedForTutorial` 兜底，这里直接透传即可。
  2. `BuildWeightedPool(DraftCategory c, bool consolation, bool forceAtLeastRare = false)`：Equip 分支 `pool.AddRange(CollectEquipCards(forceAtLeastRare));`。默认参数保证 BuildOddsRows（概率公示）调用点零改动——**公示永远显示基础概率，不含保底**（保底是条件概率，硬塞进行结构会成假数，违背「公示永远是真数」拍板）。
  3. `PickOne(DraftCategory c, bool consolation)`：Equip 分支前算 `bool guarantee = c == DraftCategory.Equip && SlotMachineSystem.EquipRareGuaranteeActive();`，传入 BuildWeightedPool。免费老虎机/升级三选一走 BuildCards（不经 PickOne）→ **不保底、不计数**（免费奖励玩家自选 3 张，有自主规避；且避免白送路径刷爆 streak）。
- **验收**：streak=4 时 PickOne(Equip) 产出的 3 张候选全部至少 RARE；BuildOddsRows 数字与改前一致（除 T1 品质曲线变化）；BuildCards 路径行为零变化。
- **依赖**：T2、T3、T4。
- **风险**：中低。PickOne 是付费直抽出口，改错会影响全部付费抽奖——验收第 2 条必须实机验证。

### T6 每局清零接线（RunDraftDirector）

- **文件**：`Assets/Scripts/Systems/RunDraftDirector.cs:75-85`（`!resumed` 分支）
- **做法**：83 行 `DraftPool.ResetDrawnEquipTemplates();` 旁加 `SlotMachineSystem.ResetRunEquipWhiteStreak();` + 注释「2026-10-24 主人拍板：保底稀有计数每局清零（续关不清，同抽奖币计数口径）」。
- **验收**：新局第一抽 streak=0；续关（resumed）不清——延续上一局白 streak。
- **依赖**：T4。
- **风险**：无（一行）。

### T7 生效记账接线（BattleManager，防刷关键）

- **文件**：`Assets/Scripts/Managers/BattleManager.Settlement.cs`（`CoStageEntryDraft`，950-972 行）
- **做法**：972 行 `SlotMachineSystem.NoteDraw();` 旁加：
  ```
  if (cat == DraftCategory.Equip)
      SlotMachineSystem.NoteEquipDrawResult(card);   // 生效才算：取消替换不计数（防刷保底）
  ```
  位置放在扣钱/免费额度消耗之后、`NoteDraw()` 同段——**bonusFree（金币本送的免费抽）也计**（与 NoteDraw 同语义：本局抽数照常推进）。`ok=false` 分支（950-955，取消替换/无法生效）**不调**——这是防刷的核心：玩家不能靠「抽到不满意就取消」白嫖重掷。
- **验收**：① 取消替换 10 次，streak 不变；② 生效白卡 +1、蓝/金清零；③ 金币本免费抽也正常计数。
- **依赖**：T4。
- **风险**：中。位置放错（放 PickOne 里）就会被取消替换刷——评审重点。

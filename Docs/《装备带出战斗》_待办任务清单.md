# 《装备带出战斗》待办任务清单

> 触发：玩家反馈"装备能带出战斗" + 主人觉"落差是不是有点大"（2026-10-21 设计讨论）。  
> 诊断前置：`legacyEquipPool` 全链路已摸（见本文件「一、现状」），确认带出基建已建好但未接线。  
> 推荐模型（混合，非两极端）：**局内装备按策略写入 `legacyEquipPool` 持久仓库 → 城镇手动配装（槽位带入战斗）→ 不想要分解退金 → 局内每波抽取照旧清零（保留肉鸽层）。**  
> 本文档只给**改造点 + 验收标准**，不写完整代码；C# 落地交给子模型（GLM / Step-5-Preview）。

## 二、目标

1. 战斗结束（通关 / 死亡 / 撤离）按"带出策略"把局内 `EquipInstance` 转为 `EquipmentData` 写入 `legacyEquipPool` 并落盘。
2. 城镇仓库 UI 能展示带出装备、能穿/脱到 7 个槽位、角色属性随之变化；穿戴状态持久化，进战斗自动沿用（战前沿用）。
3. 仓库每件可「分解」退金币/材料（复用 `EquipScrapGold`），消化不想要件与重复件。
4. **局内每波抽取（`GetAllItemsForLegacy` / 抽奖 / 换装弹窗）照旧发生、照旧在 `ClearRunEquipment` 清零**——肉鸽构筑层不变味。

## 三、任务清单

### T0 前置核对（不写代码，先确认，避免 T1/T2 返工）

- [ ] 确认 `EquipInstance` 是否持有与 `EquipmentData.attrBonus` 同构的字段（`rarity/star/attrBonus 或 enchants`）；`equipId` 来源（模板 id 还是实例 id）能否直接映射持久 `equipId`。
- [ ] 确认城镇侧"已穿戴"状态当前落在哪（推测仅在 `GridBackpackSystem` 战斗期内存，无落盘）→ 决定 T2 是给 `EquipmentData` 加 `equippedSlot` 字段，还是 `SaveData` 加 `Dictionary<EquipSlotType,string> equippedEquipIds`。
- [ ] 确认 `TownBackpackGrid.cs:559-569` 当前是否真渲染 `legacyEquipPool`（空池可能一直没暴露渲染 bug）。

### T1 局内装备 → legacyEquipPool 写入接线

- **文件**：`BattleManager.Settlement.cs`（`:1815-1830` `EndRunAndReturnToTown`）、`BattleManager.Death.cs`（`:143-179` `TriggerLegacyFlow`）。
- **做法**：
  1. 在各自 `ClearRunEquipment()` **之前**，取 `GridBackpackSystem.Instance.GetAllItemsForLegacy()`（`List<EquipInstance>`）。
  2. 按"带出策略"（待确认①）过滤后，逐件 **新写** `EquipInstance → EquipmentData` 转换（映射 `rarity/star/attrBonus→AttrBonusData`，`isLegacy=true`；`equipId` 取 T0 确认的源）。**转换原语当前不存在，须新写**（放 `EquipInstance` 或 `SaveData` 静态方法）。
  3. 写入 `SaveSystem.Instance.Data.legacyEquipPool`；调用 `SaveSystem.Instance.Save()` 落盘。
- **验收**：打完一局回城后 `legacyEquipPool.Count > 0`；存档落盘、重开游戏仍在；按策略过滤正确（如"每局1件"只进 1 件）。
- **依赖**：T0；待确认①。
- **风险**：① 转换丢字段（如 enchants 未映射）→ 属性缩水；② 重复件膨胀（靠 T3 分解 + 待确认①门槛缓解）；③ 必须在 `ClearRunEquipment` **之前**取件，否则取到空。

### T2 城镇仓库装备页打通（读取 + 穿脱 + 战前沿用）

- **文件**：`TownBackpackGrid.cs`（`:559-569` 已读 `legacyEquipPool`）、`CharacterBagSystem.cs`（`:10/:161/:169` 仓库视图）、`SaveData.cs`（可能加字段，见 T0）。
- **做法**：
  1. 仓库件按 `equipId` 对应槽位类型分组渲染（7 槽）；点击 → 复用 `TryEquipDirect` 等价逻辑穿入对应槽（注意 `TryEquipDirect` 是战斗侧，城镇可能要镜像一份或抽公共方法）。
  2. 穿戴状态持久化：按 T0 决定加字段（`EquipmentData.equippedSlot` 或 `SaveData.equippedEquipIds`）；写回 `SaveSystem` 落盘。
  3. 进战斗时（`BattleManager` 开局装配处）读取持久穿戴映射 → 自动把城镇已穿槽位带入（战前沿用）。
- **验收**：城镇打开仓库能看到带出装备、能穿到角色、角色面板属性变化；退出重进城镇/游戏后穿戴保留；进战斗开局即带这套底装，不与"每波一抽"冲突（抽取叠加在底装之上）。
- **依赖**：T1（有数据）；T0（字段方案）。
- **风险**：城镇槽位与战斗槽位是否同一套定义；穿脱写回若不及时落盘会丢。

### T3 装备分解 / 去除（去掉不想要的）

- **文件**：`TownBackpackGrid.cs`（仓库 UI 加按钮）、复用 `EquipScrapGold`（`BattleManager.Settlement.cs:1451`）。
- **做法**：仓库每件加「分解」按钮 → 调 `EquipScrapGold(rarity, star)` 退金币/材料 + 从 `legacyEquipPool` 移除该件 + `SaveSystem.Save()` 落盘；若件已穿戴先脱再删。
- **验收**：分解后件消失、金币/材料增加、存档更新；无"白删无返还"。
- **依赖**：T1/T2（有件可分解）。
- **风险**：分解已穿戴件需先清穿戴映射，避免悬空引用。

## 四、待确认项（主人拍板，文档不替你定）

- [ ] **① 带出多少**：全带 / 每局带 1 件最好的 / 稀有度门槛（只带紫橙）/ 仓库数量上限。直接决定 T1 过滤逻辑与重复膨胀程度。
- [ ] **② 城镇仓库是否升级成"真正的装备页"**：目前读空池，UI 可能不完整，需确认补全范围。
- [ ] **③ 与跨局账号天赋的平衡红线**：带出件作为"底装层"厚度上限，避免和天赋双重叠加、玩家过早"毕业"掉留存。
- [ ] **④ 重复件策略**：默认允许同名并存（推荐，仓库是 List 天然支持），还是精确重复自动分解/合成+星（二期）。
- [ ] **⑤ 战前沿用次序**：进战斗自动带入城镇穿戴（推荐）与"每波一抽"如何叠加（抽取结果临时覆盖/旁挂，结算清零，不动底装）。
- [ ] **⑥ 职业冲突（本方案最大风险，2026-10-21 主人追问）**：装备生成按职业走（`RiftEquipGenerator.GenerateOne(StageType, PlayerJobId job, ...)`，`EquipInstance` 无 job 字段，职业亲和靠 `templateId`/`weaponKindOverride` 隐式承载）；而「随时换职业」是跨局自由切。冲突只在**城镇/切职边界**（单局内不能换职业，战斗内穿着恒合法）。解法三选一：
  - **A【推荐】按职业分库**：`EquipmentData` 加 `PlayerJobId job`（T1 转换时从 `templateId`/生成 job 捕获），城镇仓库按**当前职业**过滤 + 穿戴组**按职业分键**，切职自动切换该职 legacy 套装——既保留"带出"价值又保全换职，每职各自累积衣橱。
  - **B 只留职业无关通用件**：持久化只取 Head/Chest/Hands/Feet/Cape + 通用属性（def/HP/ms/暴击/闪避），武器与 PhyPower/MagicPower 不持久化。切职零冲突，但弱化"留住专属武器"的归属感。
  - **C 账号级被动加成（圣物式不占槽）**：遗产装备改为全职业生效的被动加成，彻底无冲突，但丢掉槽位深度与"我的剑"感（即回到"纯加成"路线）。
  - 另：与③平衡红线联动——持久通用属性会与跨局"全属性"天赋叠加，须设厚度上限。

## 五、施工红线

1. **不破坏肉鸽层**：`GridBackpackSystem.ClearRunEquipment()` 照旧；只在战斗结束**边界**接线，不动 `_items` 战斗内行为。

3. **复用现有原语**：`TryEquipDirect` / `GetEquippedInSlot` / `EquipScrapGold` 已有，不新造一套装备系统。
4. **写入必落盘**：写 `legacyEquipPool` 后必须 `SaveSystem.Save()`，否则白带。
5. **不碰**：56 字符 guid、资源 `.meta`；资源/代码/.meta 全入库（新图走正确路径，不复制兜底）。

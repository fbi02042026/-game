# 《技能可干预释放》_待办任务清单

> 2026-11-05 主人拍板方向：技能 CD 转好后弹出窗口，玩家手动点释放效果 ×1.3；
> 不点则窗口超时后按原效果自动释放（保底不变，不点不亏）。
> 目的：治「自动战斗参与感≈0」——躺平可玩、上手有收益。
> 本文档只给改造点与验收标准，不写完整代码。

## 现状（已完成）

- 玩家技能纯冷却制自动释放链路已闭环：
  `PlayerSkillPassive.TickAutoCast()`（Systems/PlayerSkillPassive.cs:202，每帧、有 GCD 早退闸）
  → `BattleManager.FindReadySkillSlot()`（Managers/BattleManager.Skills.cs:44，槽序=优先级，
  含触发条件 PlayerSkillPassive.IsTriggerMet + 蓝闸判定）
  → `BattleManager.TryUsePlayerSkill()` → `SkillCastService.TryUsePlayerSkillSlot()`（Combat/SkillCastService.cs，
  真正释放、上冷却、上膛 GCD）。
- **先例：疾风架势已是「手动窗口技」**（2026-10-27 主人拍板）：
  CD 好 + 身边有敌 → 弹 4 秒倒计时窗口，点战场空白区多打一次（×0.8）；不点不亏，超时自动结算。
  实现在 `BattleManager.Skills.cs:362-490`（#region 疾风架势手动窗口：TickGaleWindow /
  StartGaleWindow / EndGaleWindow / IsBattlefieldTap），
  UI 走主人 10-28 摆的预制体「能量槽」节点组（BattleUI.ShowGaleWindow / UpdateGaleWindow / HideGaleWindow）。
  疾风已从自动释放池摘出（BattleManager.Skills.cs:62 / :123 两处 continue）。
- 6 个玩家技能在 `Data/Source/Tables/player_skills.csv`（运行时 id 是 ally_* 别名，判定前必须
  `PlayerSkillDefs.ResolveRealSkillId` 解析成真 id，先例见 BattleManager.Skills.cs:71）。

## 目标

把「疾风窗口」模式推广到**其余 5 个玩家技能**（治愈之泉/圣盾壁垒/战意爆发/致命专注/天雷裁决）：
CD 好 + 触发条件满足 → 开一个 N 秒「就绪窗口」；窗口内玩家点 → 效果 ×1.3；
超时 → 按原效果自动放（现有行为完全保留为兜底）。疾风架势独立通道不动。

## 任务清单

### T1 · 常量（GameConfig.Combat.cs）
- 新增 `SKILL_READY_WINDOW_DURATION = 3f`（窗口秒数）、`SKILL_MANUAL_CAST_MULT = 1.3f`（手动加成）。
- 验收：常量集中一处，别处不出现裸 3f / 1.3f。

### T2 · 就绪窗口状态机（BattleManager.Skills.cs，参考疾风先例）
- 新增与 TickGaleWindow 同构的状态机（建议新 #region「技能就绪窗口」）：
  ① 未开窗：GCD 就绪 + FindReadySkillSlot 命中 → 记 pendingSlot、开窗、通知 UI；
  ② 窗口内：检测点按（点技能按钮或战场，口径见 T4 待确认）→ 携带 ×1.3 释放；超时 → 原倍率释放；
  ③ 释放后照旧走 ArmPlayerSkillGcd + RegisterCooldown，链路零改动。
- 每帧调度挂点：BattleManager.Waves.cs:1086 旁（与 TickAutoCast 同挂点、同早退口径：
  isInBattle / UnitsCanAct / BattleLootMode.Active 全部照抄）。
- 🔴 一次只开一个窗口（GCD 已保证同时只有一个就绪，别引入队列）。
- 🔴 窗口开着时若玩家在抽卡/弹窗界面：照走不暂停，超时自动放（不亏，不处理焦点）。
- 验收：不点 = 现网行为逐帧一致（回归基线）；点 = ×1.3 且正常进 CD。

### T3 · 加成倍率注入（SkillCastService.cs）
- `TryUsePlayerSkillSlot` 加可选参数 `float manualBonus = 1f`，从窗口状态机传入。
- 乘点覆盖三类（施工时按实际代码定位，此处只定口径）：
  伤害类（天雷裁决 damageMultiplier）、治疗类（治愈之泉 healPercentOfMax+healAtkMul 两段都乘）、
  buff 类（战意爆发/疾风 buffValue）——**待主人拍板 buff 是否同乘**（建议全乘，教学文案一句话讲清）。
- 验收：手动放天雷飘字伤害 ≈ 自动放 ×1.3（实测可辨）；每星递增、暴击等现有乘区不重算不丢失。

### T4 · UI 表现（BattleUI）
- 就绪窗口提示：**首选复用疾风「能量槽」预制体节点组**（ShowGaleWindow 先例，成本最低），
  或技能按钮高亮+倒计时环（二选一，**待主人拍板**）。
- 点按判定：复用 `IsBattlefieldTap()`（BattleManager.Skills.cs:476，已处理鼠标/触摸 +
  EventSystem UI 过滤）；若做成「点技能按钮」，按钮onClick直连窗口状态机即可。
- 文案：教「点」不教「走」（🔴 没有摇杆，引导/说明禁出现教摇杆教走路）；叙事性文案走 C# 常量。
- 验收：真机（微信开发者工具+真机预览）可点；UI 遮挡处点按不误触（IsPointerOverGameObject 过滤生效）。

### T5 · 与疾风窗口互斥
- 疾风窗口挂着时不开普通就绪窗口（疾风 TickGaleWindow 先调度；普通窗口调度器开头查 _galeWindowActive）。
- 反向：普通窗口挂着时疾风照常开窗（疾风是独立通道，互不吞）。
- 验收：两窗口不会同时要求玩家点同一区域；疾风行为与 10-27 版完全一致（回归点）。

### T6 · 数值与节奏复核
- ×1.3 后核对：Boss/精英战节奏是否被明显加速（尤其天雷裁决多目标 + 星级递增）；
  如过强，只调 SKILL_MANUAL_CAST_MULT，不动技能表。
- 确认自动保底路径（不点）DPS/治疗曲线与现网一致——这是「不点不亏」承诺的验收。

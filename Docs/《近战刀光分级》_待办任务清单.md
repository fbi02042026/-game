## 三、任务清单（给子模型施工，不写完整代码）

### T1 · 新增档位解析唯一出口 —— [GLM 5.3 Flash]

**新文件**：`Assets/Scripts/Config/WeaponVfxVariant.cs`（连 `.meta` 一起提交）

- `public static class WeaponVfxVariant`，对外**只有一个方法**：`public static int Resolve(UnitBase attacker)`，返回 1/2/3。
- 内部规则（顺序固定，写注释）：
  1. `attacker is Hero` → 取主手 `EquipInstance`（复用 `Hero.TryGetEquippedWeaponInstance`，见 T3 可见性）→ **先查逐武器覆盖表**（`Dictionary<string, int>`，key = `templateId`）→ 未命中按 `instance.rarity` 默认档；
  2. `attacker is Mercenary` 且 `MercRosterDefs.JobKindOf(mercId)` 属近战（Melee/Polearm/Berserker）→ `RarityPalette.ResolveMercRarity(mercId)` → 默认档；
  3. 其余（Monster / 空手 / 远程 kit / null）→ **1**。
- **默认档（待主人拍板，建议值）**：Common/Uncommon/Rare → 1，Epic → 2，Legendary → 3。只在这一处写死，调用方不许自己 if 稀有度。
- 逐武器覆盖表初始可为空表；这就是「把高级武器分开」的微调入口——以后主人说「某把橙武用刀光2」只加一行，不动调用链。
- 注释写清两件事（铁律 15）：① 解析不到武器回 1 是**设计最低档**，不是兜底另一套值；② 纯函数、无 Random、无缓存竞态。

**验收**：同武器连击 10 次档位不变；换主手武器档位跟着变；法师/弓手/怪物恒 1。

### T2 · `BattleVFXSystem` 加载链路贯穿档位 —— [GLM 5.3 Flash]（依赖 T1）

**文件**：`Assets/Scripts/Systems/BattleVFXSystem.cs`（不动 `PlaySlash` 内部，`prefabOverride` 已支持）

1. `LoadSharedKit`（1014 行）加参数 `int variant = 1`：**cacheKey 必须带 variant**（`$"{faction}/{kit}/{stage}/v{variant}"`），否则 刀光1/2 池化串味。
2. `GetSharedKitFileNames`（1059 行）加参数 `int variant`：
   - MeleeSlash + Ally：`刀光{variant}`（variant 1/2/3 → 刀光1/2/3）；
   - **删掉** `vfx_ally_melee_hit` / `vfx_melee_hit` 旧名候选（旧文件已删，留着只打死名）；
   - Enemy / Bow / Orb / Heal：**暂忽略 variant**，走原文件名（接口预留，不写死分支）。
3. `PlayAttackKit`（69-81 行近战分支）：`int variant = attacker != null ? WeaponVfxVariant.Resolve(attacker) : 1;` → `LoadSharedKit(kit, faction, "hit", variant)`。
4. `AutoLoadPrefabs`（952 行）与 `ValidateSharedKitPresence`（1000 行）用默认 variant=1（即刀光1）；**错误文案**（76/165/967/977 行）里的 `vfx_ally_melee_hit` 改成 `刀光1`，缺 刀光2/3 时 LogError 指明缺哪个文件、**不静默回退到别的刀光**。
5. 6 参重载 `PlayAttackKit`（SkillRegistry 用）**不加 variant 参数**，默认 1 → 技能刀光不随武器变（见待确认 3）。

**验收**：日志/自检只认 刀光1/2/3；删掉 刀光2 后启动自检报「缺 刀光2」且战斗中不闪回刀光1。

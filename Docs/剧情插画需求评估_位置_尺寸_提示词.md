# 剧情插画需求评估：需不需要、在哪出现、尺寸与 AI 提示词

> 日期：2026-09-17 ｜ 配套文档：`叙事V2.0_美术资源_立绘描述与生图提示词.md`

---

## 0. 先给结论（三句话）

1. **游戏现在没有"插画"这一层**，只有「全屏背景 + 立绘 + 道具叠图」三层。
2. **不需要新建插画系统** —— 你要的画面，90% 用现有的**背景层**就能解决，**零新代码**。
3. **真正需要"插画"的只有 2 个瞬间**（立绘和背景都表达不了的），而且**可以不做**。

---

## 1. 现状：游戏里的剧情画面是怎么堆出来的

`DialogueUI` 的图层，从下到上：

| 层 | 组件 | 规格 | 现在有什么 |
|---|---|---|---|
| 全屏背景 | `sceneBackgroundImage` | **576 × 1024** | 只有 **2 张**：公会大厅、会长办公室 |
| 立绘（左/右） | `left/rightPortraitImage` | 1171 × 1345 | 8 张（前台、会长×2、玩家、猎人、小梅、阿尔托、劳顿）+ 梅莉莎 |
| 道具叠图 | `storyPropImage` | 小图 | 气泡、委托书 |
| 对话框 | `dialogueBoxImage` | 720 × 236 | 有 |
| 换场景黑幕 | `_revealBlack` | 全屏 | 有（会显示地点名） |

**已挂背景的位置**：序章 6 处、第 1 章 2 处 —— 全是 `guild_hall` / `guild_office`。

**没挂背景的位置**（查 `ChapterStoryBeats.cs` 确认，一个 `.Bg()` 都没有）：

> 第 2–8 章 Boss 后剧情（N2–N7）、**第 7 章三选一**、**4 段结局演出（N8-A/B/C/T）**

⇒ 也就是说：现在你打到第 8 章结局，画面上只有**战斗背景（雪原卷轴） + 立绘**。
「黑曜结构碎成八瓣」「她坐了上去」「天亮得刺眼」这些，玩家全靠脑补。

**这就是缺口。**

---

## 2. 我的建议：走「背景」，不走「插画」

| | **背景方案**（推荐） | 插画方案 |
|---|---|---|
| 系统 | **已有**（`StoryBeat.Bg(id)`） | 需要新增一层 + 播放/淡入逻辑 |
| 代码改动 | **0 行**（只需给 beats 补 `.Bg(...)`） | 约 30 行 + UI 层改动 |
| 尺寸 | **576 × 1024** | 1080 × 1920 |
| 能不能同屏配立绘 | **能**，立绘叠在背景上，角色照样说话 | 不能，插画是全屏定格 |
| 包体 | 小 | 每张大约 3 倍体积 |
| 适合表现 | 场景、环境、氛围 | 单一戏剧瞬间的定格（大场面、非人形、群像） |

**结论**：先把 **6 张背景**补齐（4 张结局 + 2 张关键节点），这是性价比最高的一步。
**插画先不做** —— 除非你觉得「沉座合拢」这种瞬间非画出来不可（见 §7 第 3 条）。

> 顺带说一句为什么：本项目 GDD 硬约束是**剧情约占整体体验 10%，轻剧情重氛围**。
> 在自动战斗的小游戏里，一张会动的背景 + 会说话的立绘，信息效率远高于一张静态插画。

## 4. 尺寸规范

### 4.1 背景（推荐方案）

| 项 | 值 |
|---|---|
| **尺寸** | **576 × 1024**（与现有 `bg_guild_office.png` 完全一致） |
| 比例 | **9 : 16** |
| 格式 | JPG 质量 80 或 PNG-24；**不要透明底**（要铺满全屏） |
| 存放 ① | `Assets/Art/UI/Story/bg_{id}.png`（编辑器直读） |
| 存放 ② | `Assets/Resources/Story/Backgrounds/{id}.png`（运行时加载） |

> **为什么是 576×1024**：游戏设计分辨率是 **720 × 1280**，比例同为 **9:16**。
> 576/720 = 0.8、1024/1280 = 0.8 —— **等比 0.8 倍，铺满不裁不拉伸**。这个尺寸是刚好对上的，别改。

**画面构图硬约束**：对话框占屏幕下方（720×236，约屏幕底部 18%），立绘站在画面中央偏下。
⇒ **背景的视觉重心放在上半部与中部**，下半部会被对话框和立绘挡掉，别把重要信息放底下。

### 4.2 插画（只在 §7 第 3 条你选"要做"时才用）

| 项 | 值 |
|---|---|
| 尺寸 | **1080 × 1920**（9:16，1.5 倍于设计分辨率，保证高清屏不糊） |
| 格式 | JPG 质量 82 |
| 显示方式 | 全屏 `Image`，`preserveAspect` 关闭、`type=Simple`，等比 cover 裁切 |
| 需要新增 | `StoryBeat.illustrationId` + `DialogueUI.SetIllustration()` + 一层全屏 Image |

## 5. AI 提示词（前 6 张，可直接跑）

> 统一风格：**写实厚涂西幻场景**，暖金 + 深蓝，电影级逆光，笔触感。
> **所有背景都不要画人物**（人物由立绘叠加，画了会打架）。
> 分辨率出 **576 × 1024**，出完按需放大。

## 6. 落地步骤（代码要改的地方）

图到位后，三处改动即可，都在 `Assets/Scripts/Story/`：

**① `StoryBackgrounds.cs` —— 加 ID 和地名**

```csharp
public const string EndBadHome = "end_badhome";
public const string EndHappy   = "end_happy";
public const string EndBadGate = "end_badgate";
public const string EndTrue    = "end_true";
public const string GraveSeven = "grave_seven";
public const string AbyssChoice = "abyss_choice";
```

`DisplayName()` 里补中文名（**这一行不能漏**——换背景时会走「地点揭示」，
会把这里返回的字符串当作地点名显示在黑幕上；返回空字符串就会显示一片空白）：

```csharp
if (id == EndBadHome) return "公会医务室";
if (id == EndHappy)   return "裂隙出口";
if (id == EndBadGate) return "沉座";
if (id == EndTrue)    return "装备科仓库";
if (id == GraveSeven) return "无名碑";
if (id == AbyssChoice) return "深渊边缘";
```

**② `ChapterStoryBeats.cs` —— 给每个 beat 挂背景**

```csharp
var beats = new List<StoryBeat>
{
    StoryDirector.Narration("黑曜结构在你面前碎成八瓣……").Bg(StoryBackgrounds.EndHappy),
    // …后面的 beat 不用重复挂，同 id 的背景会沿用
};
```

⚠️ 只在**第一句**挂就行：`StoryDirector` 里有 `backgroundId != _introducedBg` 的判断，
同一个 id 后续 beat 会沿用，重复挂反而会触发多余的「地点揭示」黑场。

**③ 预热（可选）**

在 `ChapterStoryBeats` 或开场处加一行，避免第一次显示卡顿：

```csharp
StoryAssetLoader.Warmup(StoryAssetLoader.Backgrounds,
    StoryBackgrounds.EndHappy, StoryBackgrounds.EndBadHome, /* … */);
```

## 7. 需要你拍板的 3 件事

1. **先做几张？** 我的建议是**先做前 4 张（结局）**——那是全剧情绪最高点，
   现在完全裸奔最说不过去。做完看效果再决定补不补 5、6。

2. **要不要给 N8 之外的节点也挂？** 第 2–7 章 Boss 后的剧情现在也都是裸奔状态。
   我的建议是**至少给 N2（墓园）和 N7（三选一）挂上**——一个是"发现真相"，一个是"做抉择"，
   这两个瞬间没有画面，会明显掉质感。

3. **要不要真的做插画？** 只有两个瞬间是立绘 + 背景都表达不了的：
   - **沉座合拢**（C 结局）：需要一个「人被黑曜晶体包住」的画面，立绘做不到
   - **裂隙降临**：片头动画里已经有了，游戏内可以不重复

   ⇒ **只值 1 张，且是 C 结局专用。** 而且要做就得新加一层显示逻辑。
   我的判断是**先不做**——C 结局靠旁白「黑曜合拢的时候，她回头看了你最后一眼」已经够，
   真要加，等前 6 张背景验证完效果再说。

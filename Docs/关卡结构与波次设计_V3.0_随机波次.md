# 关卡结构与波次设计 V3.0 —— 随机波次

> 日期：2026-09-15
> 范围：正式关（Normal / Elite）的关卡模式、波次组成、每波人数、卡点与压力阀
> **V2.0 作废气**：`关卡结构与波次设计优化方案_V2.0.md` 的 §2.3 / §3.1 / §9.5 配表与「章内不重复」规则不再执行。

---

## 零、V3.0 改了什么（相对 V2.0）

| V2.0 | V3.0 | 为什么改 |
|------|------|----------|
| 模式 = **固定序列**（`A01\|A02\|A02\|A02`） | 模式 = **原型池 + 权重**（`A02:6\|A01:3\|A06:1`） | 固定序列导致同一模式每次长得一模一样 |
| **章内不重复**（抽过的移出池） | **允许重复** | 10 关 7 个模式必然重复，验收指标「重复率 0」根本不可达 |
| 先定总怪量再**切分**给各波 | **自下而上**：每波独立摇人数，总量 = Σ | 切分会被 `cap` 截断（第 9/10 关 24~28% 的局少出怪） |
| 总怪量来自 `GetStageMonsterTotal` 的 `stageNo` 分支 | 取消；改由「波数 × 每波人数」决定 | 该公式让 **第 1 关（15.3 只）比第 2 关（9.9 只）还多**，难度曲线倒挂 |
| 每波人数上限锁死 `WAVE_MONSTER_MAX = 4` | 按原型 `cap`（2~6） | 围杀要 5~6 只才有形状 |

**核心原则**：*关卡可以重复，波次永不重复。* 玩家第二次遇到「虫潮」，里面的 4 波具体长什么样、每波几只、先来什么，都和上次不同。

## 一、三层结构

```
关卡（Stage）
  └─ 模式（Mode）  ← 可重复抽，定义「这一关是什么味道」
       └─ 波次（Wave）× N  ← 波数随机，每波原型从池里按权重抽
            └─ 原型（Archetype） ← 决定进场方向 / 近远编成 / 出怪间隔 / 精英额度 / 人数区间
```

### 1.1 生成算法（进战前一次性算完）

```
1. 抽模式：候选 = 命中 chapter（含 4+ 语法）+ stageType + stageIdx ≥ minStage
           → 等权重抽 1 个（允许与上一关重复）
2. 摇波数：waveCount = Random(waveMin, waveMax + 1)
           再受压力阀 / 职业补偿修正，最后 clamp 到 [1, 刷怪点数量]
3. 逐波抽原型：按 pool 权重抽，软约束「同一原型连续出现 ≤ maxRun」
4. 逐波摇人数：count = clamp(round(countBase × countMul × chapterMul × progressMul × rand(0.85, 1.15)),
                             countMin, cap)
5. 总怪量 = Σ 各波人数（不再预设，也不再切分）
```

### 1.2 三个强度系数

| 系数 | 公式 | 范围 | 作用 |
|------|------|------|------|
| `chapterMul` | `1 + 0.03 × (chapter - 1)` | 1.00 → 1.21 | 章节越深，每波略微变厚（怪物属性另有 `chapter_stat_scale` 1.0→2.8，人数只小幅跟上） |
| `progressMul` | `1 + 0.05 × stageIdx` | 1.00 → 1.45 | 章内第 1 关 → 第 10 关，**严格单调上升**（修掉 V2.0 的倒挂） |
| `countMul` | 模式自带 | 0.9 ~ 1.3 | 模式个性：虫潮多、铁壁少 |

| 新列 | 含义 | 默认 |
|------|------|------|
| `countMin` | 本波人数下限 | 2 |

### 3.1 精英关额外规则

精英关（Elite）**每波额外 +1 精英额度**（在原型自带的 `elite` 之上），占本波最后一个名额。
例：A02 散兵（elite=0）在精英关 → 4 只里最后 1 只是精英；A06 铁卫（elite=1）→ 2 只精英。

### 3.2 Boss 关 / 引导关

- **Boss 关不配行**，继续走 `SetupBossWave` 现有逻辑（风险最低，本次不动）
- **引导关**（`tutorial_battle.csv`）不变，22 只怪的手工节奏保留

> CP1/CP2 的位置**随抽签浮动** —— 这正是「同一章两次玩不一样」的来源。

### 4.2 自适应压力阀（定版参数）

```csharp
// GameConfig.EnemyTuning
PressureStreakThreshold = 2;   // 连续 N 关「无死亡 + 通关血量 > 70%」→ 下一关波数 +1
PressureWaveCap        = 2;    // 加压上限：最多额外 +2 波
PressureMercyOnDeath   = true; // 上一关死过 → 下一关波数 -1，且首波延后 1.5s
```

- 每章开始重置；只调**波数**，不动数值（保持设计纯粹）
- 波数下限保底 `waveMin - 1`，且不低于 3

## 七、验收指标（修订版）

| 指标 | V2.0 目标 | V3.0 目标 |
|------|-----------|-----------|
| 一关波次数 | 5–6 | **3–6（随模式浮动）** |
| 单关内原型种类 | ≥3 | **≥2（波数 3 时）/ ≥3（波数 ≥4 时）** |
| 章内模式重复率 | 0（不可达） | **允许重复，但同一模式两次进关的波次序列不同（≥80% 不同）** |
| 每关总怪量 | 固定公式 | **随机，第 1 关 → 第 10 关单调递增，无倒挂** |
| 每章平均撤离/死亡 | 1.5–2.5 次 | 1.5–2.5 次 |
| 同模式不同职业通过率差 | ≥20 个百分点 | ≥20 个百分点 |

## 一、技能机制改版：能量槽 → 纯冷却制

### 1.1 规则

| 项 | 旧（能量制） | 新（冷却制） |
|---|---|---|
| 释放条件 | 能量条充满 | 该技能冷却结束 |
| 释放顺序 | 谁满放谁 | **按技槽顺序（0→3）取第一个冷却完毕的** |
| 间隔 | 无（多个同时满会连放） | **全局 GCD 1.2 秒** |
| 开局 | 能量从 0 开始攒 | **按槽位错峰给初始 CD** |
| 释放后 | 能量清零 | 重新进入自己的冷却 |

### 1.2 关键常量（`Assets/Scripts/Core/GameConfig.cs`）

```csharp
public const bool  PLAYER_SKILL_USE_ENERGY = false;   // false=纯冷却制；true 可退回旧行为
public const float PLAYER_SKILL_GCD = 1.2f;           // 任意两次玩家技能的最小间隔
public const float PLAYER_SKILL_SLOT0_OPENING_CD = 0.5f;
public static readonly float[] PLAYER_SKILL_OPENING_CD_MUL = { 0f, 0.33f, 0.66f, 1f };
```

开局错峰（每次 `LoadStage` / `StartNewRun` 都会重置）：

| 槽位 | 初始 CD |
|---|---|
| 0 | 0.5 秒（固定） |
| 1 | 自身 CD × 0.33 |
| 2 | 自身 CD × 0.66 |
| 3 | 自身 CD × 1.00 |

效果：4 个技能不会在同一秒一起转好，也不会开局 0.5 秒内全部糊脸。

### 1.3 GCD 双闸

- **早退闸** `PlayerSkillPassive.TickAutoCast()`：GCD 未到直接 `return`，省掉每帧遍历。
- **权威闸** `SkillCastService.TryUsePlayerSkillSlot()`：`if (!bm.IsPlayerSkillGcdReady) return false;`
  —— 任何调用方（自动、教程、调试）都绕不过。
- 上膛：`bm.ArmPlayerSkillGcd()` = `NextPlayerSkillCastAt = Time.time + 1.2f`。
- 用 `Time.time`（缩放时间），与 `SkillSystem` 用 `Time.deltaTime` 递减冷却**同轴**，暂停/慢放时不会错位。

### 1.4 为什么 GCD 1.2 秒够用

4 个技槽典型 CD 12~26 秒 → 合计释放频率约 `4/16 ≈ 0.25 次/秒`（平均间隔 4 秒），
远高于 GCD 的 0.83 次/秒上限。**GCD 只在两个技能恰好同时转好、或波次间隙攒了多个 CD 时才真正生效**，
正好达成"把技能之间拉开、不要瞬间全放"的目标，又不会拖慢正常节奏。

## 二、升星曲线（2026-09-15 下调）

`SkillDraftMeta.StarDamageStep = 0.18`（原 0.28）、`StarCooldownStep = 0.06`（原 0.08），线性累加，冷却倍率下限 0.6。

| 星级 | 伤害倍率（新） | 冷却倍率（新） | **等效 DPS（新）** | 等效 DPS（旧 0.28/0.08） |
|---:|---:|---:|---:|---:|
| 1 | 1.00 | 1.00 | 1.000× | 1.000× |
| 2 | 1.18 | 0.94 | 1.255× | 1.391× |
| 3 | 1.36 | 0.88 | 1.545× | 1.857× |
| 4 | 1.54 | 0.82 | 1.878× | 2.421× |
| 5 | 1.72 | 0.76 | 2.263× | 3.118× |
| 8 | 2.26 | 0.60（触底） | 3.767× | 4.933× |

**下调原因**：能量制下技能释放频率受能量积累限制，改纯 CD 制后释放次数大幅增加，
原 +28%/-8% 曲线会滚雪球，第 5 星就到 3.1 倍 DPS。

叠乘顺序（`RunDraftDirector.BuildRunSkill`）：

```
实际伤害 = 基础倍率 × 星级伤害倍率 × 流派势能倍率 × (职业亲和 ? 1.2 : 1)
实际冷却 = 基础冷却 × 星级冷却倍率 × (职业亲和 ? 0.85 : 1)   // 下限 0.6 秒
```

- 流派势能 `RunLoadout.ThemeDamageMul`：Lv1 ×1.08 / Lv2 ×1.18 / Lv3 ×1.32（同流派点数 2/5/9）。
- 职业亲和 `SkillDraftMeta`：伤害 ×1.2、冷却 ×0.85，命中时等效 **1.412 倍 DPS**。

> ⚠️ 已知限制：`SkillConfig.ToActiveSkill()` 只搬运 `damageMultiplier / baseDamage / cooldown`，
> **不含 `healPercentOfMax` / `buffValue` / `duration`**。所以治疗量和增益幅度**不吃星级**，
> 星级对治疗/增益技能只体现在冷却缩短上。要吃星级需扩展 `ToActiveSkill`，本次未做。

### 3.3 加新技能要动的地方

1. `PlayerSkillDefs.Fallback` 加 `Def`（`hasCombat = true` 才会进战斗）。
2. `SkillDraftMeta.Table` 加一行（否则落进兜底 = 稀有 / 无流派 / 无亲和）。
3. 想让它进城镇选择页：还要写进 `player_skills.csv` 并 Cook，且排在**前 6 行**。

> `player_skills.csv` 目前只有 6 行（基础技能），其余 18 个只在 `Fallback` 里。
> CSV 行按 id 覆盖 `Fallback`，CSV 里没有的 id 会被 `Append` 追加——两边不一致不会报错，但容易改错地方，**改数值前先确认它在哪边**。

## 四、顺带修掉的两个既有 Bug

### 4.1 团队增益永久叠加（严重）

`SkillCastService.ApplyTeamBuff` 原来只有攻速走计时，攻击/防御/暴击走 `attr.AddAttr` 永久写值，
表里的 `duration` 完全没被消费。能量制下不明显，**改纯 CD 后 18 秒一次永久 +50% 攻击，3 分钟能叠 10 层**。

修法：`AttrSystem` 新增定时增益层（独立于 `_attr` 的计时倍率），到期自动失效、后放覆盖先放（不叠加）：

```csharp
public void ApplyTimedBuff(AttrType type, float value, bool isPercent, float duration);
public void ClearTimedBuffs();          // 每关开局调用，防跨关残留
```

攻击 / 防御 / 暴击三系改走 `ApplyTimedBuff`；攻速沿用原有的静态计时倍率。
其它 `AddAttr` 分支保留（治疗系的 `MaxHp` 等不走这里）。

### 4.2 连锁技能半径硬编码

`SkillSystem.ExecuteChain` 原来写死 `8f`，不吃表里的 `aoeRadius`——`thunder_chain` 只是恰好也是 8，
别的连锁技填了半径也不生效。改为 `skill.aoeRadius > 0f ? skill.aoeRadius : 8f`。

## 五、战斗遮罩 zhezhao

- 节点：`BattleUI.prefab → BackpackPanel/zhezhao`（730×670，半透黑 alpha 0.588），保持原尺寸，不放大全屏。
- 开关：`BattleUI.TickBattleMask()`，每帧在 `Update()` 开头调用（不受 0.1s 节流影响），
  条件 `BattleManager.isInBattle && !BattleLootMode.Active`，带状态缓存避免每帧 `SetActive`。
- **整理阶段必须关**：否则背包格子和技槽点不动。
- **摇杆例外**：`BattleJoystick` 也是 `BackpackPanel` 的子节点，靠兄弟序压在遮罩之上。
  原 `RaiseOrganizeAbove()` 用 `SetSiblingIndex(childCount - 2)`，插入摇杆后 `childCount=6`
  会把摇杆排到 zhezhao **之前**被吞掉；改为先找 zhezhao 的 index 再 `+1`，并把 `lootConfirmButton` 最后再压一层。

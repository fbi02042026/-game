## 1. 已落地（代码已改，待编辑器验证）

### 1.1 引导关「实际怪比表里多」= 真 bug（已修）

`WavePlanner.QueueTutorialWaveCore` 补刷判据被**同帧缓存**骗了：

```
:154  aliveBefore = CountAliveMonsters()     ← 建立本帧缓存 = 0
:155  TrySpawnTutorialWave(...)              ← 刷主波（协程按 stagger 陆续出怪）
:157  if (CountAliveMonsters() == 0)         ← 仍读本帧缓存 0 → 误判"没刷出来"
:161/:166  EmergencySpawn*(n)                ← 再补一整波，数量翻倍
```

| 文件:行号 | 改法 |
|-----------|------|
| `WavePlanner.cs:157` | `== 0` → `<= aliveBefore`（主波一只都没刷出来才补刷） |
| `BattleManager.cs` | 新增 `InvalidateAliveMonsterCache()`；`SpawnMonster` 入列后、`OnMonsterDead` 时调用 |

### 1.2 回滚「引导关 −30%」

真因是 1.1 的 bug，不是数值。已回滚：`TutorialRules.MonsterCountMul` 引导侧 `0.7f → 1.0f`。**引导关人数真源 = `tutorial_battle.csv`（6/7/7/7/8，共 35 只）**，`ScaleMonsterCount()` 仅作透传。

### 1.3 玩家攻击速度 −20%（仅 Hero）

- `GameConfig.PLAYER_ATTACK_SPEED_MUL = 0.8f`
- 应用点唯一：`UnitBase.GetAttackCooldown()` 的 `this is Hero` 分支；**不用 `isAlly`**，否则拖慢佣兵与怪物

### 1.4 全部弹道 −20% + 速度真实化

六种弹道全部汇入 `BattleVFXSystem.ProjectileFlightCoroutine`：

- `GameConfig.PROJECTILE_SPEED_GLOBAL_MUL = 0.8f`
- **去掉 `maxFlightTime`（1.2s）截断** → `duration = max(minFlightTime, distance / speed)`，真实「每秒移动 N 单位」
- 不追踪、朝发射瞬间目标点直线飞行（保持现状）

### 1.5 残影改为与攻速技能绑定（不单独出现）

- `SkillCastService` 新增静态计时 `_teamAtkSpdBuffUntil`/`_teamAtkSpdMul` + `IsTeamAttackSpeedBuffActive`/`GetTeamAttackSpeedMul()`；攻速类增益改为时效倍率，**不再走永久 `AddAttr`**
- `UnitBase.GetAttackCooldown` 的 `isAlly` 分支乘 `GetTeamAttackSpeedMul()`
- `KillComboAfterimage.LateUpdate` 门控换为 `IsTeamAttackSpeedBuffActive`，删连杀倍率门控与 `IsMoving()`

> 副作用：gale_stance 由「永久 +35%」变为「6 秒 +35%」，是修 bug 的必然结果。

### 1.6 上一轮已落地（保留）

- `GameConfig.SHOW_MONSTER_STACK_LABEL = false`：关闭怪物重叠 ×N 角标
- 修 ×N 误判根因：原 `MonsterFootprintsOverlap` 只比 X 不看车道 Y，已加 Y 轴
- 簇统计静态缓冲化（原每 0.12s 分配 List/int[]/2×Dictionary/2 闭包）

## 3. 局内成长系统（核心新增设计）

> **设计原则**：变强全部发生在「局内」，撤离/死亡即清空（Roguelike）；英雄为多职业（`player_job_base_stats` 已支持），不同职业的三选一池子不同，形成「多职业肉鸽」。

### 3.1 闪避（Dodge）— 飘字表现，零新增美术

| 维度 | 设计 |
|------|------|
| 触发 | **独立闪避按钮**（屏幕右下，与摇杆、自动技能三区隔离，避免冲突）；点击即触发，不依赖摇杆手势 |
| 冷却 | 约 3s，按钮上显示冷却环/数字（复用现有冷却 UI 样式） |
| 效果 | 0.3–0.35s 无敌帧（`Hero` 上加 `invincibleUntil` 时间戳，`TakeDamage` 路径优先判）；沿当前移动/朝向短位移（直接改写坐标，无需动画） |
| 表现 | 触发瞬间在 Hero 头顶飘「**闪避!**」字（复用 `CombatJuice` 飘字/Toast），**不新增任何 sprite/动画/特效资源** |
| 实现点 | `Hero.cs` 加 dodge 状态 + `TryDodge()`；`UnitBase.TakeDamage` 前判 `invincibleUntil`；HUD 加闪避按钮 + 冷却；`FloatingText` 调用 |
| 成本 | 中（状态机 + 无敌帧 hook + 飘字调用）；美术成本 = 0 |

### 3.2 局内三选一强化（核心 build 乐趣）

- **触发时机**：每层（关）通关结算时弹一次（复用现有「宝箱三选一」弹窗）
- **强化池**（按职业区分，多职业肉鸽的关键）：
  - 通用：攻速 +%、暴击 +%、吸血 +%、范围 +%、移速 +%、最大生命 +
  - 职业专属：游侠→弹道数 +1 / 战士→格挡反击 / 法师→弹道分裂 等（取自 `player_job_base_stats` 职业标签）
- **叠加**：同一局可多次选，形成 build 雪球
- **成本**：中（高收益，直接制造 build 乐趣；弹窗与随机池已有基础）

### 3.3 佣兵招募进局内（可选，A/B 二选一）

| 方案 | 说明 | 成本 |
|------|------|------|
| A（推荐） | 把「招募佣兵」作为一个**三选一项**塞进 3.2 的强化池：选到即当场获得一名当前可用佣兵入队（数值取局内临时档，不依赖城镇养成） | 低（复用招募逻辑，去掉局外养成耦合） |
| B | 局内增设「佣兵祭坛」事件节点（替代 Rest 节点之一），花局内金币招募，可带 1–2 名 | 中 |

> 决策建议：先上 A，验证手感后再考虑 B 做事件化。

### 3.4 装备：仅局内、肉鸽、多职业（**绝不带出**）

| 维度 | 设计 |
|------|------|
| 定位 | 局内掉落/强化的装备是**消耗品**，撤离与死亡**都清空**（`GridBackpackSystem.cs:26-38`、`BattleManager.cs:1964` 现状维持） |
| 多职业 | 装备词条按职业生效/加权；不同职业「本局 build」走向不同 |
| **带出** | **取消原 G3「允许带出 1 件」提案**——严格 Roguelike，局外只沉淀天赋与建筑等级，避免削弱单局风险与肉鸽纯度 |
| 可见性 | 局内 HUD 显示「本局已获得提升」清单（原 G4），让变强可见 |

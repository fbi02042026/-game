# 多周目 / 难度 / 抗性 / 佣兵等级设计（2026-09-17）

> 触发：用户要求「普通 10 级 / 稀有 15 级 / 传奇 25 级，线拉长，让玩家玩多周目；
> 一周目后开启困难和地狱，怪更难打还会有抗性」。

---

## 一、现状核查（有几处和设想对不上）

| 项 | 以为 | 实际 |
|---|---|---|
| 难度档位 | 只有普通 | **已有 4 档**：`AdventureUI.DiffNames = {普通, 困难, 噩梦, 地狱}`，颜色和按钮都做好了 |
| 难度开启 | 一周目后 | 困难 = 通关满 3 章（`DIFF_HARD_NEED_CLEARS=3`）、噩梦 = 通关满 6 章（=6）。**地狱没有任何开启条件** |
| 地狱倍率 | — | ⚠️ `GetDifficultyStatScale` 里 `diff>=2` 返回 1.8 → **地狱和噩梦完全一样，是个空壳** |
| 怪物抗性 | — | **完全没有**。只有玩家角色面板有个 `抗性` 字段（占位 15%，逻辑里写死 `resist = 0f`） |
| 多周目 | — | **框架已有**：`chosenBranch` 通关第 8 章归零可重选支线，`ChapterStoryBeats` 里有"二周目"分支文本。但**没有周目计数器** |

**结论**：要做的不是从零造，而是——给地狱填实、加怪物抗性、加周目计数、加佣兵永久等级。

## 二、佣兵等级制（替代原"深造 Lv5"方案）

### 2.1 为什么改成等级制

上一版我提的是"深造 Lv0~5，每级 +10%"。用户要的是**按稀有度分上限**（10/15/25），
好处比 Lv5 一刀切强得多：

- **稀有度有了第二重价值**：传说不只是初始强，而是**能养得更久**（25 级 vs 10 级）
- **长线有梯度**：普通是"用完即止"的过渡，传说是"值得投资一生"的主角
- **多周目有具体抓手**：一周目养不满传说，二周目继续

### 2.2 等级效果

**每级 +4% 生命 / 攻击 / 防御**，上限按稀有度：

| 稀有度 | 等级上限 | 满级加成 | 叠加花名册成长后 |
|---|---:|---:|---:|
| 普通 | **Lv10** | +40% | 1.00 × 1.40 = **1.40** |
| 稀有 | **Lv15** | +60% | 1.15 × 1.60 = **1.84** |
| 传奇 | **Lv25** | +100% | 1.30 × 2.00 = **2.60** |

传奇养满 ≈ 普通养满的 **1.86 倍**——值得投资，但没到"不养传说就没法玩"的程度。

> ⚠️ 命名冲突：局内佣兵也有 `level`（跟随英雄等级，本局有效）。
> 建议 UI 上区分：**名册里叫「等级 Lv7」**，**战斗中叫「本局 Lv12」**。
> 存档字段用 `mercLevels`（HireId → 等级）。

### 2.3 成本曲线（拉到多周目）

`第 n 级成本 = 基础价 × (1 + 0.25 × (n-1))` —— 线性递增，越往后越贵。

基础价：**普通 150 / 稀有 250 / 传说 400**

| | Lv1 | 中段 | 满级那级 | **单名满级总计** |
|---|---:|---:|---:|---:|
| 普通 (10) | 150 | Lv5 300 | Lv10 487 | **3,187** |
| 稀有 (15) | 250 | Lv8 687 | Lv15 1,125 | **10,312** |
| 传奇 (25) | 400 | Lv13 1,600 | Lv25 2,800 | **40,000** |

**全员满级 ≈ 258,928 金**

对照八章累计产出 ≈ 99,414 金（普通难度）：

| 目标 | 需要 | 何时达成 |
|---|---:|---|
| 主力 5 名满级（2 传说 + 3 稀有） | ≈ 110,936 金 | **一周目打完 + 少量二周目** |
| 全员 22 名满级 | ≈ 258,928 金 | **约 2.5~3 个周目**（打高难度会更快） |

这正是"线拉长"想要的效果：**一周目养得满主力但养不满全部**，
且高难度金币倍率（困难 ×1.8 / 噩梦 ×3 / 地狱 ×5）让**打高难度 = 加速养佣兵**，动力闭环成立。

> ⚠️ 这些数字是**估算**，锚点来自 `EconomyDefs` 的八章 99,414 金。
> 而 `Gates.failStages` 本身就是猜的，**上线实测后第一件事就是校准这条曲线**。

## 三、难度：把地狱填实 + 改开启条件

### 3.1 开启条件

| 难度 | 现在 | 建议 |
|---|---|---|
| 普通 | 一直开 | 一直开 |
| 困难 | 通关满 3 章 | **维持**（一周目中段就要有挑战梯度） |
| 噩梦 | 通关满 6 章 | **维持** |
| 地狱 | 无（空壳） | **通关第 8 章 = 一周目完结后开启** |

> 用户说"一周目后开启困难和地狱"——困难如果也改到一周目后，前 8 章就只有普通难度，
> 中后期会太平淡。**建议只把地狱挪到一周目后**，困难/噩梦维持现有的 3 章 / 6 章。
> 如果你要的是"困难和地狱都一周目后"，回复我一句就改。

### 3.2 倍率（现在地狱 = 噩梦，必须拆开）

| 难度 | 属性倍率 | 金币倍率 | 抗性 |
|---|---:|---:|---|
| 普通 | 1.0 | 1.0 | 无 |
| 困难 | 1.35 | 1.8 | 无 |
| 噩梦 | 1.8 | 3.0 | **有（20~30%）** |
| 地狱 | **2.5** | **5.0** | **有（40~50%）** |

改动点只有 `GameConfig.GetDifficultyStatScale` / `GetDifficultyGoldMul` 里的
`if (diff >= 2)` 分支——现在 diff=3 被这个判断吞掉了，要拆成 `diff >= 3`。

### 3.3 多周目递增（让"再来一轮"有意义）

新增 `SaveData.cycleCount`（通关第 8 章时 +1）。地狱难度随周目递增：

```
地狱属性倍率 = 2.5 × (1 + 0.15 × (周目数 - 1))
```

一周目 2.5 / 二周目 2.875 / 三周目 3.25 / 四周目 3.625 …

配合佣兵等级上限（传奇 25 级 = +100%），
**玩家的成长（最多 2.6 倍）略高于地狱二周目的强度（2.875 倍 ÷ 2.5 = 1.15 倍增幅）**——
也就是说多周目会越来越吃力，但养满佣兵能跟上，**强度与成长赛跑**，不会无脑碾压也不会卡死。

## 四、抗性机制（新增）

### 4.1 抗性类型（用现成的元素体系）

现成素材：佣兵里已经有 **水系法师（H012）/ 雷系法师（H013）/ 火系法师（H014）**，
技能表 `merc_skills.csv` 里类型分类也有「物攻 / 法术 / 防御 / 恢复」。

| 抗性 | 影响谁 | 哪些佣兵吃瘪 |
|---|---|---|
| **物理抗性** | 剑盾 / 狂战 / 游侠 / 重武（13 名） | 大多数物理佣兵 |
| **法术抗性** | 法师系（5 名） | H019 星火、H020 谜面 |
| **火 / 水 / 雷抗性** | 对应元素法师 | H014 火舞、H012 小蓝、H013 紫晶 |
| 治疗 | 不受抗性影响 | —（但地狱可加"治疗量 -30%"作为额外压力） |

### 4.2 抗性给多少、给在哪

| 难度 | 抗性 |
|---|---|
| 普通 / 困难 | **0**（保证一周目流畅，不劝退） |
| 噩梦 | 20% ~ 30% |
| 地狱 | 40% ~ 50% |

**按章节主题给，每章只给 1 种**（八章主题现成）：

| 章节 | 地图 | 建议抗性 |
|---|---|---|
| 1 暮影森林 | 无 | — |
| 2 幽冥墓园 | 亡灵 | 物理 25% |
| 3 翡翠秘境 | 丛林 | 法术 25% |
| 4 晨曦草原 | 平原 | 雷 25% |
| 5 海岛遗迹 | 海洋 | 火 25% |
| 6 巨岩深窟 | 洞穴 | 物理 30% |
| 7 赤焰炼狱 | 恶魔 | 火 40% |
| 8 永霜雪境 | 冰原 | 水 40% |

### 4.3 ⚠️ 抗性会改变佣兵分类的性质——这是要提醒你的

你之前定的基调是「**用别的佣兵也能过，只是这个更轻松**」。
我的情境标签（承伤/清场/攻坚/续航/牵制）是按这个基调设计的——它们是**软优势**。

**但抗性一加，性质就变了**：

- 第 8 章冰原怪有 40% 水抗 → 带 H012 小蓝（水系）就是**硬亏**，不是"不轻松"而是"明显吃亏"
- 这会从"偏好"升级成"**准入门槛**"

这不是坏事（正是你想要的"某个佣兵在某个关卡很好用"的强化版），
但**必须配套下面三条，否则会变成挫败感**：

1. **抗性上限 50%**，绝不免疫。50% 意味着"带错人要多打一会儿"，不是"打不过"
2. **每章只给 1 种抗性**，且**该章节一定有其他能打的佣兵可解锁**（现在 22 名够覆盖）
3. **2 个佣兵位可以互补**——一个吃抗性，另一个不吃的，仍然能过
4. **UI 必须提前告知**：进关前的关卡详情要显示"本章敌人：火抗 40%"，
   否则玩家是打进去才发现，会觉得是被阴的

### 4.4 对佣兵卡面的影响

卡面要加**第二组标签**（与情境标签并行）：

```
维克·钢盾                    ← 名字
剑盾卫士 · 传说               ← 职业 · 稀有度
🛡 高压承伤 · 💚 持久续航      ← 情境标签（擅长什么局面）
⚔ 物理                      ← 伤害类型（会被什么抗性克）
```

伤害类型从 `merc_skills.csv` 的「类型分类」自动推，不用手写：
物攻 → ⚔ 物理；法术 → ✦ 法术（元素法师再细分为火/水/雷）；恢复 → ✚ 治疗。

## 五、落地顺序（建议分三步，别一次全上）

| 步骤 | 内容 | 风险 |
|---|---|---|
| **第 1 步：佣兵等级** | 加 `SaveData.mercLevels`、名册卡等级显示与升级按钮、属性乘区接进 `MercRosterDefs.ApplyCombatStats` | 低。纯增量，不动局内逻辑 |
| **第 2 步：地狱填实 + 周目计数** | 拆 `diff>=2` 分支、地狱独立倍率、加 `cycleCount`、通关 ch8 后解锁地狱 | 低。改 2 个函数 + 1 个存档字段 |
| **第 3 步：抗性** | 怪物表加抗性列、伤害计算接抗性、关卡详情 UI 预告、卡面加伤害类型标签 | **中**。改动伤害链路，且要配套 §4.3 的四条缓解措施 |

**强烈建议按这个顺序**，因为抗性改的是伤害计算核心，一旦出问题影响全局；
而前两步是纯增量，能立刻给玩家"多周目有得追"的感觉。

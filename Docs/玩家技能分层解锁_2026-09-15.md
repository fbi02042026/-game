# 玩家技能分层解锁：前期 10 / 中期 8 / 后期 6（2026-09-15）

## 0. 设计地基

**Fun Hypothesis（一句话）**
> 技能解锁是玩家在局外持续投入的第二条成长线——每一批新技能都带来**一种新的玩法**，而不是一个更大的数字。

**Design Pillars（3 条，每个决策都要过审）**

| # | Pillar | 具体含义 |
|---|---|---|
| 1 | **每批都能独立成军** | 前期 10 个必须能凑出「输出 / 治疗 / 增益」各一条，否则新手某些职业没法玩 |
| 2 | **后期强在机制，不强在数值** | 后期技能倍率与前期持平，靠机制复合取胜。玩家变强靠装备和星级，不靠技能膨胀 |
| 3 | **每个解锁途径有自己的性格** | 章节=保底白给、天赋=主动投资、商店=花钱加速、成就=炫技炫耀 |

**为什么必须分层**：改版前 24 个技能 `unlockChapter` 全是 0，等于开局全开。
结果不是"选择多"，是**选择被淹没**——局内三选一永远抽不到想要的，玩家感受不到池子在成长。

## 二、四个解锁途径

| 途径 | 数量 | 判定方式 | 写存档 | 性格 |
|---|---:|---|---|:---:|
| 章节通关 | 8 | 动态：`clearedChapterIds` / `maxUnlockedChapter` | ❌ | 保底，玩家一定能拿到 |
| 天赋树 | 2 | `SaveData.unlockedSkills` | ✅ | 主动投资，和属性节点抢资源 |
| 商店 | 2 | `SaveData.unlockedSkills` | ✅ | 花钱买时间，提前拿到 |
| 成就 | 2 | `SaveData.unlockedSkills` | ✅ | 炫技，达成即奖励 |

### 2.1 兜底章节机制（重要）

天赋/商店/成就三个途径**目前还没有对应的 UI 入口**（天赋树未挂技能节点、商店界面未建）。
为了不让这 6 个技能永远拿不到，给它们都配了**兜底章节**：

```
IsUnlocked = 已写进 unlockedSkills
          OR (unlockChapter > 0 且 已通关该章)
          OR (unlockSource == None 且 unlockChapter == 0)
```

所以实际效果是「**达成条件 或 推进到兜底章节，哪个先到算哪个**」。
等天赋节点和商店 UI 建好后，把兜底章节调高即可，不用动判定逻辑。

### 2.2 存档字段

```csharp
// SaveData
public List<StringIdEntry> unlockedSkillEntries;   // 序列化
[NonSerialized] public HashSet<string> unlockedSkills;  // 运行时
```

章节解锁**故意不写进存档**——它是纯动态判定，避免通关记录变化后状态不一致。

### 2.3 接入点（给后续实现）

| 途径 | 调用 |
|---|---|
| 成就 | ✅ 已接：`CompleteAchievement` → `PlayerSkillDefs.UnlockSkillsByAchievement(achievementId, data)` |

## 二点五、让技能「职业无关」（2026-09-15 补）

> 起因（用户原话）：「我是游侠，三选一里都没适合我的技能，我选了蛮牛冲锋我怎么释放，
> 总不能让我这个脆皮冲到怪里吧……箭雨不用我做什么，自动朝一个范围释放就行，
> 但是你这个蛮牛和剑刃就不合适了。」

这是一个**真 bug**，不是文案问题：`SkillSystem.ExecuteAOE` 原本调
`GetEnemiesInRange(caster, aoeRadius)`——**以施法者自身为中心**。
AOE 半径只有 6~9，而游侠/法师的攻击距离远大于这个数，
等于「远程职业必须走进怪堆才能放 AOE」，脆皮直接送死。

### 2.5.1 解法一：改落点（治本，已做）

```
旧：center = caster.transform.position
新：center = PickAoeCenter(caster, radius)
    = 在「施法者攻击距离内」挑一个能覆盖最多敌人的位置
      取不到（比如空场）→ 回退到施法者自身
```

- 新增 `SkillSystem.GetEnemiesInRangeAt(caster, center, range)`：按任意中心取敌
- 新增 `SkillSystem.GetCasterReach(caster)`：玩家读 `AttackRangeTable.GetJobWorld(选中职业)`，
  敌方返回 0（走旧 radius 兜底，行为不变）
- 原 `GetEnemiesInRange` 转发到 `GetEnemiesInRangeAt(caster, caster.pos, range)`，**旧行为零改动**
- `ExecuteChain` 同样改用新落点

效果：游侠放「天雷裁决」会**自动落在射程内敌人最密集的位置**，玩家不需要操作，也不需要贴脸。

### 2.5.2 解法二：近战专属分池（治标补漏，已做）

改落点能救「范围伤害」，但救不了「冲锋 / 旋风」这类**语义上就是冲进去**的技能——
落点再怎么选，游侠也不该自己撞进怪堆。所以这类技能单独打标：

```csharp
// PlayerSkillDefs.Def
public bool meleeOnly;   // 只给「强贴身」语义打标记，不要滥用
```

已标记 3 个：**bull_rush（蛮牛冲锋）/ blade_storm（剑刃风暴）/ quake_slam（震地重击）**

- `PlayerJobDefs.IsMelee(job)`：剑盾卫士 / 狂战士 / 重武者 = 近战；游侠 / 法师 / 牧师 = 远程
- `DraftPool.CollectNewSkills`：`if (def.meleeOnly && !PlayerJobDefs.IsSelectedMelee()) continue;`
- `ShopSystem.CollectGachaPool`：同一套过滤——**远程职业在商店抽卡也抽不到冲锋**

> 这是「通用池 + 近战专属池」的轻量实现：没有真的拆成两张表，
> 而是用一个 bool 在同一次过滤里分流，避免两张表不同步。

### 2.5.3 未解决（诚实）

- `meleeOnly` 目前**只有 3 个技能**。24 个里剩下的 21 个都靠「改落点」兜底，
  实际手感要打过才知道——**建议实测一次远程职业的 AOE，确认不会再出现"必须贴脸"**。
- 近战职业（剑盾/狂战/重武）的池子比远程**多 3 个**，数量略有不对等，暂不处理。

## 四、已知空洞（诚实清单）

1. **重武者后期没新技能**。重武者总共 3 个（gale_stance 前 / bull_rush 前 / quake_slam 中），后期 0 个。
   重武者玩家打到后期没有"新玩具"。**建议后续补 1~2 个重武者后期技能**。
2. **法师前期只有 1 个**（thunder_verdict，史诗）。前期法师选择偏薄，但它是全场最高倍率，作为"前期天花板"说得通。
3. **天赋树未建**，`thunder_chain` / `war_banner` 目前走兜底章节（4 / 5）。
   天赋 UI 建好后把兜底章节调高，不用动判定逻辑。
4. **所有商店价格是 [PLACEHOLDER]**（3000/8000 金币、500/4500 钻石、50/200 钻石……）。
   没有真实经济数据支撑——需要「一局金币收入」和「钻石获取速度」的实测量级才能定。
   定得太低商店形同虚设、经济通胀，定得太高玩家永远不点。**上线前必须重算**。
5. **`meleeOnly` 只标了 3 个**，其余 21 个全靠「改落点」救。实测前不敢打包票。

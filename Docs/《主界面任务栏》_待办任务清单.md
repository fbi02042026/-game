## 四、注意点（照抄给后续施工的）

1. 🔴 **改日常「今日通关」数量要两处同步**：表 `daily_clear.target_count`（展示参照）与
   `SaveData.DAILY_CLEAR_TASK_NEED`（发奖真源）。只改一个就会出现「显示 2/3 实际 3 关才发奖」。
2. 🔴 **主线 id 不能改**：旧档 `mainQuestDone` 按 id 存完成态；新行才用新 id（C?_Q5/Q6）。
3. 🔴 **日常行 id 必须小写** `daily_login`/`daily_clear`：`QuestJumpRouter.GoDaily:56` 按字面量匹配，
   写成大写 = 登录任务点击不弹登录界面。
4. **ClearStages 基线语义**：进度 = 本章累计通关 − 首次评估时已通关数。放在章初的行（need 2）第一关
   就占 1 格；章中 need 3 的行可能「接手即完成」——属预期（Tick 会补结算+Toast），不是 bug。
5. **主线奖励经济**：新增密度行 reward_stones 一律 0（战斗奖励走现有关卡/章节里程碑链），
   非战斗任务维持 1 石——别随手加石，动 8 石/天保底口径。
6. **支线≠任务表**：支线是支线岛（branchRoll1/2 派定、单 Boss 一次性），任务栏支线行只读派定状态，
   不要在 quest.csv 里加「支线任务」行。
7. **旧 QuestHudBar 保持停用**（2026-10-11 拍板 + 本次主人重申「停掉的那个统一用主界面的」），
   不要打开 `TownSceneBootstrap` 里它的挂载注释；QuestPanelUI 保留（页签已改「日常」）。
8. 表注释里的枚举口径就是代码真源：`target_type` 加新值要同时动 `MainQuestDefs.ParseType` +
   `MainQuestSystem.ProgressOf` + `QuestJumpRouter.GoMain`（三处，漏一处=点击没反应或不结算）。
9. 支线岛名/奖励改 `SideIslandDefs.cs`（草稿名主人可全部重起）；任务栏支线行文案跟着自动变。

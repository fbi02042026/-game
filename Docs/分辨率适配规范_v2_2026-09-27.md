# 分辨率适配规范 v2（2026-09-27 主人拍板）

> **本文件是「以后做分辨率适应」的唯一依据。每做一个界面、每改一次布局，都按这份过一遍。**
> 上一版见 `UI竖屏适配规范_2026-09-24.md`（只覆盖了竖屏三条规则，没有分辨率矩阵、没有边界检查项）。
> 本版补齐两样：**① 常用分辨率矩阵（谁是基准、谁必须验证）**；**② 每个界面必须过的边界检查清单**。

---

## 0. 一句话总方针

**竖版 UI 一律「按宽度对齐」：逻辑宽恒 720，多出来的高度给中间内容。**
两侧不许有任何元素溢出 720 逻辑宽 —— 溢出就是「被切」，因为父级会裁。

## 0.1 【最高约束】适配代码一律「各界面各自写」

> **2026-09-27 主人原话：「注意不要写到所有适配的文件 每个界面单独一个文件 写到单独的界面代码里 以后也是」**

**铁律**：

1. **谁要适配，就写在谁自己的脚本里** —— 例如 `AdventureUI.ApplyAdventureFit()`、`DailyLoginUI.ApplyFit()`。
   ✅ 对：`Assets/Scripts/UI/AdventureUI.cs` 里自己算自己的几何。
   ❌ 错：往 `UiLayoutStretch.cs` / `UICanvasSetup.cs` 这类**通用文件**里加某个界面的专用逻辑。

2. **通用文件只留「纯工具」**，不写任何具体界面的东西。可以留的只有两类：
   - 判定工具：`ResolveUiMatch()` / `IsThinnerScreen()` / `InferRole()` —— 不含界面名、不含具体节点名；
   - 全界面通用动作：`ApplyFillScreen` / `ApplyEnvelopeCenter` / `EnsureFitBackdrop` —— 按名字/角色泛化匹配，谁都能用。
   - 反例（**曾经有，已迁走**）：`ApplyAdventureUI` 这种带界面名的专用实现，已迁移至 `AdventureUI` 自己的文件。

3. **已单独适配的界面必须登记进制裁名单** `UiLayoutStretch.IndividuallyFitted`
   （现在是 `{ "AdventureUI", "DailyLoginUI", "RewardPopup" }`），
   否则通用规则会**再改一遍**已经调好的效果 —— 这就是「改好又坏」的经典复发路径。

4. **新增界面要做适配** → 新写一个自己的 `ApplyXxxFit()`，并加进 `IndividuallyFitted`，**不动通用文件**。

5. **一键回退**：界面自己的适配要带自己的开关（如 `EnableAdventureUiFit`）+ base 记录 / 还原能力，
   方便出问题时单独关掉，而不是去改通用逻辑。

| 5 | **1440 × 2960** | 0.4865 | 更瘦 (18.5:9) | 720 × 1480 | ✅ 主人这台机 |

| 7 | **1170 × 2532** | 0.4621 | 更瘦（iPhone）| 720 × 1558 | 抽查 |

**分档口径**（代码里已有判定，不要新造第二套）：

| 档 | 条件 | match | 逻辑宽 | 逻辑高 |
|---|---|---|---|---|
| **更瘦** | 宽高比 < 0.5625 | **0（按宽缩放）** | **恒 720** | 720 ÷ 宽高比 |
| 基准 9:16 | = 0.5625 | 1 | 720 | 1280 |
| **更宽** | > 0.5625 | 1 | 720 ÷ (宽高比 ÷ 0.5625) | 1280 |

> **判定唯一入口**：`DesignAspectLetterbox.ResolveUiMatch()` / `UiLayoutStretch.IsThinnerScreen()`。
> 界面自己不许再写一套宽高比判断（铁律 16：一个语义一个入口）。

## 2. 逻辑高换算表（写死高度前必须查）

「更瘦」档逻辑宽恒 720，但**逻辑高会变**。所以：

🚫 **禁止** 把界面高度写死成 1280（或任何固定值）。
✅ **正确** 用下列任一方式取当前逻辑高：

```csharp
// 方式 A：项目既有工具（推荐，界面里就用这个）
float uiLogicalH = DesignAspectLetterbox.ResolveUiMatch() < 0.5f
    ? GameConfig.DESIGN_WIDTH / Mathf.Max(1e-3f, Screen.width / (float)Screen.height)
    : GameConfig.DESIGN_HEIGHT;

// 方式 B：直接量根节点（更贴实测）
var rootRt = transform as RectTransform;
if (rootRt != null && rootRt.rect.height > 0f) uiLogicalH = rootRt.rect.height;
```

| 分辨率 | 逻辑高 | 比 1280 多 |
|---|---|---|
| 720×1280 / 1080×1920 | 1280 | 0 |
| 1080×2160 | 1440 | 160 |
| 1440×2960 | 1480 | 200 |
| 1080×2340 | 1560 | 280 |
| 1170×2532 | 1558 | 278 |
| 1080×2400 / 1440×3200 | 1600 | **320（最大）** |

## 3. 每个界面开工前必须过的检查项（**本节的第 1 条是本次事故的教训**）

### 🔴 必查 1 · 子节点宽度不许超出父级（本次「两边被切」的真因）

**判据**：子节点用 `sizeDelta.x`（或固定宽）时，其宽度 ≤ 父级可用宽度。

**本次实证**（`AdventureUI.prefab`）：

| 节点 | 宽度 | 父级可用宽 | 结果 |
|---|---|---|---|
| `LeftSidebar` | 170 | 720 | ✅ |
| `RightContent` | 720 − 170 = **550** | 720 | ✅ |
| `DetailPanel` | **711.4（硬编码）** | **550** | ❌ **超 161.4，两边各切 80.7** |

**为什么代码"救"不动**：`AdventureUI.FitAdventureDetailPanel` 把它改成水平 stretch 并取
`margin = max(leftMargin, rightMargin)` —— 两侧都是 **−80.7**，取 max 还是 **−80.7**，
负边距原样保留 → 继续溢出 → 继续被切。**想修必须显式 clamp 到父级宽内，不能只做"对称化"。**

✅ **正确写法**：
```csharp
// 先夹到父级可视区内，再做对称化（margin 不许为负）
float margin = Mathf.Max(0f, Mathf.Max(leftMargin, rightMargin));
```

**建议加一条自检**：界面 Show 时打印一次「子节点右边界 − 父级宽度」，> 0 就 `LogError`（报错码思路，见第 6 节）。

### 必查 2 · 顶部元素贴顶（`anchorMin.y = anchorMax.y = 1`）
### 必查 3 · 底部元素贴底（`anchorMin.y = anchorMax.y = 0`）
### 必查 4 · 中间区域有背景平铺 / 无背景则垫黑底（`EnsureFitBackdrop`）
### 必查 5 · 背景一律「整体缩放」，绝不 stretch 拉伸
### 必查 6 · 每个 Canvas 必须挂 `GraphicRaycaster` + 走 `UICanvasSetup.Apply`
### 必查 7 · 界面若已单独适配（AdventureUI / DailyLoginUI / RewardPopup），通用规则必须整块跳过
### 必查 8 · 新增界面要登记进「已适配界面名单」（见第 5 节），否则闸门 G7 会提醒
### 必查 9 · **适配代码写在自己界面的文件里，不许写进通用文件**（见第 0.1 节，闸门 G7 会拦）

## 4. 两个坑（改锚点前必读）

1. **先记录 base 再从 base 重算**：节点原始锚点未必是全拉伸（贴底栏常是 `(0,0)/(1,0)`），
   直接改锚点会让 offset 语义错位、元素跳位。照 `SafeAreaFitter.CaptureBase()` 的做法。
2. **改锚点会触发 `OnRectTransformDimensionsChange`**：必须加守卫防递归
   （`SafeAreaFitter.Apply` 的 `_applying` 标志、`AdventureUI._adventureUiApplying`）。

## 6. 边界处理的统一口径（铁律 16 一致）

- **不许静默兜底**：取不到尺寸 / 算不出宽度 → `Debug.LogError` + 用安全值继续，**不要悄悄用另一套逻辑**。
- **不许留 `xxxEnabled` 开关**：能删的旧分支直接删；必须保留的写明 `2026-09-27 主人拍板` + 根因。
- **不许写死分辨率**：任何高度/宽度都必须由第 2 节的方式推导。
- **不许新造第二套判定**：更瘦 / 更宽一律走 `ResolveUiMatch` / `IsThinnerScreen`。

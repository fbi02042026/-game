## 2. P0 — 上线前必须处理

### P0-1 体力上限成就永远不生效，且会静默吞掉体力

- **证据**
  - `Story/AdventureLogAchievements.cs:225` 发奖：`data.staminaBonusMax += r.StaminaMax`（A010 = 体力上限 +1）
  - `Systems/StaminaSystem.cs:30`：`public static int Max => GameConfig.STAMINA_MAX;` ← **不认 bonus**
  - `Systems/StaminaSystem.cs:97-101`：`if (data.stamina >= Max) { data.stamina = Max; ... }` ← 把超出部分**截断**
  - `Systems/SaveSystem.cs:180`：读档也 `if (data.stamina > GameConfig.STAMINA_MAX) data.stamina = STAMINA_MAX;`
  - `Systems/ResourceWallet.cs:60-63`：`GetMax(Stamina)` **认** bonus → 上限口径两套
- **影响**：① 成就奖励是安慰剂，玩家点了没变化；② 体力药水/邮件把体力顶到 101 时，下一次 `Tick()` 静默扣掉 1 点（玩家看到"体力莫名少 1"）
- **修法**：`Max => GameConfig.STAMINA_MAX + Mathf.Max(0, SaveSystem.Instance?.Data?.staminaBonusMax ?? 0)`；`SaveSystem.cs:180` 的钳制改用 `ResourceWallet.GetMax(Stamina)`。三处统一到一个上限函数
- **验收**：领 A010 后顶栏显示 100/101；用药水到 101，重进游戏仍是 101

### P0-2 存档损坏 → 静默重开新档，进度全丢且无留证

- **证据**：`Systems/SaveSystem.cs:119-126`，反序列化异常 → `CreateFreshSave()` → `Save()`，**立刻把坏档和备份都覆盖**
- **影响**：玩家遇到一次写入中断（低端机被杀进程）就永久失去全部进度，且客服拿不到任何原始文件；与"清档"叠加时无法区分是玩家的错还是我们的错
- **修法**：catch 里先把 `player.dat` / `player.bak` 改名成 `player.corrupt.<时间戳>` 再建新档；启动时若存在 corrupt 文件，弹一次"存档修复失败"提示并埋点
- **验收**：手工把 player.dat 改成乱码 → 启动进新档，同时目录里多出 corrupt 备份

### P0-3 「版本号一变就清空全部本地数据」开关目前是开的

- **证据**：`Systems/SaveSystem.cs:30` `public const bool WipeLocalDataOnNewVersion = true;`，注释记录 10-24 拍板打开
- **影响**：上线后**任何一次版本更新都会删光存档 + PlayerPrefs**（含设置、引导进度、广告计数）。正式包忘记关，第一个补丁包就是全体回档事故
- **修法**：出正式包前置 `false`；若仍需要"大版本清档"，改成按 `majorVersion` 判断而不是 `Application.version`
- **验收**：改版本号重新打包覆盖安装，存档仍在

### P0-4 回城没有 `Time.timeScale` 兜底，异常中断会全场定格

- **证据**：全局有 4 处写 `timeScale=0`（`Story/StoryDirector.cs:402`、`UI/BattleSettlementUI.cs:182`、`Systems/CombatJuice.cs:266`、跳过加速），但 `Managers/GameSceneManager.cs:61-107 LoadTownAsync` 与 `TownSceneBootstrap` **都没有复位**
- **影响**：结算面板 `OnDestroy`（`BattleSettlementUI.cs:110-113`）不复位；剧情被异常打断也不复位。任一情况回城后画面静止、按钮无响应，玩家只能杀进程（"卡死"类客诉的典型成因）
- **修法**：`LoadTownSceneAsync` / `LoadBattleSceneAsync` 开头强制 `Time.timeScale = 1f`；`BattleSettlementUI.OnDestroy` 补一行复位
- **验收**：结算界面弹出时直接触发回城 → 城镇可正常操作

## 3. P1 — 功能缺陷

### P1-1 商店每日限购只在读档时跨天重置

- **证据**：跨天清零写在 `Core/SaveData.cs:866-877`（`SyncRuntimeFromLists`），而该方法只在 `SaveSystem.cs:156/171/258` 调用；`ShopSystem.RemainingToday`（`ShopSystem.cs:34-41`）只读字典不比日期
- **影响**：挂机跨 0 点后继续买，限购不刷新，要重启游戏才恢复
- **修法**：`RemainingToday` 里先比对 `shopPurchaseDay != ShopDefs.TodayKey()` → 清字典

### P1-2 道具"能点、会扣、没效果"

- **证据**：`Systems/BattleBagSystem.cs:315-330` `UseItem` 只做可用性判定 + `ConsumeItem`，`useEffect` 派发是 TODO
- **现状缓解**：`item_defs.csv` 现有 60+ 行全部 `canUseInBattle=0`、`useEffect` 为空 → 当前**点不到**，不会真吞道具
- **风险**：表里一旦把某个道具标成可用，就是"用了白用还扣数量"
- **修法**：`IsUsable` 增加 `!string.IsNullOrEmpty(def.useEffect)` 条件（fail closed），未实现的 effect 直接 LogError 拒绝使用

### P1-3 离线金币整套逻辑是死链（已按主人拍板保持停用）

- **证据**：`SaveSystem.CalcOfflineGold/ClaimOfflineGold`（`SaveSystem.cs:191-206`）+ `OfflineGoldCalc` 实现完整，但**全项目零活动调用**；`UI/TownSceneBootstrap.cs:248` 已注释
- **2026-10-31 主人拍板**：先注释掉（保持现状），不接回也不删，等重新设计后再启用。类注释里已标明「请勿删除」

### P1-4 打击音效 4 个资源缺失（已按主人拍板复用项目内素材解决）

- **原证据**：`Systems/CombatJuice.cs:40-43` 加载 `Audio/SFX/hit_melee_out`、`hit_melee_in`、`hit_crit`、`dodge`；`Assets/Resources/Audio/SFX/` 下四个都不存在
- **2026-10-31 处理**：从项目特效音效库里选 4 个最贴切的复制进 `Resources/Audio/SFX/`（**只复制 wav、不带 meta**，引擎自动生成新 guid，避免重复内容 guid 问题）；**代码零改动**，`Resources.Load` 路径原样命中：
  - `hit_melee_out.wav` ← `SFX_Vefects_Sword_Slash_01.wav`（挥砍，出手/命中敌人）
  - `hit_melee_in.wav` ← `Vefects_SFX_Impact_01.wav`（打击，我方受击）
  - `hit_crit.wav` ← `SFX_Vefects_Critical_Attack_01.wav`（暴击专音）
  - `dodge.wav` ← `Vefects_SFX_Dust_Puff_01.wav`（尘土扑，闪避）
- **验收**：开一次引擎让 meta 生成 → 进战斗打怪，听出手/受击/暴击/闪避四类音效是否出现；不满意换文件即可（同目录替换）

### P1-5 存档是明文 JSON，改档零门槛

- **证据**：`Data/ContentProtection.cs:8` `Enabled = false`；`SecureCodec`（AES-256-CBC + HMAC-SHA256）**已实现且能向下兼容明文**（`TryReadPayload` 会先试解密、失败回退 UTF8）
- **影响**：金币 / 钻石 / 竞技场积分 / 已解锁佣兵都能被任意改档工具直接改，等于绕过所有广告位与商店
- **修法**：正式包把开关置 `true` 即可（旧明文档能正常读，写入变加密+MAC）。注意 key 在包内仍可被逆，属"抬门槛"而非绝对安全；真正的强校验要等云存档

### P1-6 时间作弊面（体力 / 每日 / 竞技场）

- **证据**：`StaminaSystem.Now()`、`ShopDefs.TodayKey()`、`DailyLoginSystem`、`ReviveQuota`、`SettleDoubleAd`、`ArenaRules.EnsureDay` 全部直接读本机时钟
- **影响**：改系统时间即可无限刷体力恢复、每日登录、日常任务、竞技场次数。单机 + 广告变现下这是最省力的白嫖路径
- **修法（低成本）**：存档里存 `maxSeenUtc`，发现当前时间比它小（回拨）或单次跳跃 > 6h 就冻结当日收益 + 埋点；不做服务端也能挡住绝大多数

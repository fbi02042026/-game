## 二、目标

1. 城镇领取的奖励装备**不再往仓库写装备格**，角色页「随身仓库」里看不到任何装备（主人原话「不要在仓库里」）。
   - 落地口径：凭证继续写在原有字段（`legacyEquipPool` / `logMileageGrantedKeys` / `arenaShopBowId` / `GrantKey`），**字段不删、数据不清**；改的是 `HeroVaultSystem` 不再把它们铺成装备格。
2. 领取瞬间**自动装备**：该部位为空 → 直接登记凭证 + 获得奖励弹窗；该部位已有装备 → 弹战斗内同款 `EquipReplaceConfirmUI` 让玩家确认。
3. 确认「换上新的」→ 写入新凭证、顶掉旧凭证；确认「留着旧的」→ 新件按唯一口径折金币，**绝不进仓库**。
4. 跨局保持：重开游戏 / 重进战斗，穿上的奖励装备仍在 —— 沿用现有开局 `ApplyForBattle` 凭证装配，**不改这条链**。
5. 战斗内掉落/抽奖链路（E/F）已符合要求，**保持现状不动**。
6. 老存档里已躺在仓库的冠军武器/弓：凭证保留、开局照穿，仓库不再显示 = 视觉上「迁移成已穿戴」。

## 三、任务清单（只给改造点 + 验收）

> **T0 已完成**：四项待确认已由主人 2026-11-12 拍板（见文首），无需再确认。以下为收敛后的 4 项施工任务。

### T1 统一「奖励装备发放」出口（核心，依赖无）

- **文件**：`Assets/Scripts/Systems/ItemGrantSystem.cs`（新增方法；原 `GrantEquip():47-81` 保留不删、不改造，供非奖励用途）。
- **做法**：新增「领奖励装备」入口，入参 `equipId + rarity + star + onDone`：
  1. 生成 `EquipInstance`（模板 + 词条走现有生成器）；等级真源 = `LevelSystem.PlayerLevel()`（`LevelSystem.cs:36`，读 `SaveData.playerLevel`），**不要用 `Hero.Instance.level`**（城镇常为 null）；`requireLevel` 照 `AdventureLogMileage.cs:290-291` 钳到该等级必能穿。
  2. 部位判据走唯一出口 `WeaponLoadoutRules.ResolveLogicalSlot(equip)`（`WeaponLoadoutRules.cs:70`）。
  3. **同部位旧件判定**：城镇没有 `BattleBagSystem` 穿戴态，改查现有凭证（散在 `legacyEquipPool` / `logMileageGrantedKeys` / `arenaShopBowId` / `SpecialWeapons.GrantKey`）。需新增一个只读汇总：按模板 `slotType` 归类当前已拥有的奖励装备，返回该部位旧件的 `EquipInstance`（供弹窗左右栏）。**这是 T1 唯一需要新写的判定**，不许另造一套穿戴数据。
  4. 空部位 → 登记凭证 + `RewardPopupUI.ShowClaimEquip():260` + `onDone(true)`；
     有旧件 → `UIManager.Instance.StartCoroutine(EquipReplaceConfirmUI.CoShow(新, 旧, cb))`（`UIManager.cs:9` 是 `Singleton<MonoBehaviour>`，城镇可作协程宿主），`cb=true` → 换新凭证；`cb=false` → 新件折金币。
  5. 折金口径：`GameConfig.EquipScrapGold(rarity, star)`（`GameConfig.Combat.cs:1118`）→ `ResourceWallet.Add(ResourceWallet.ResourceType.Gold, gold, save: true, notify: true)`（`ResourceWallet.cs:121`）。**不要走 `WeaponLoadoutRules.GrantScrapGold`**（那是战斗内折抽奖币专用出口，`GameConfig.Combat.cs:1129-1132` 已写明城镇折金走 `EquipScrapGold`）。
- **验收**：领一把冠军武器 → 仓库不出现、进战斗生效；同部位再领一把 → 弹「换上新装备吗？」新旧双栏；选「留着旧的」→ 旧件不变、金币增加、仓库仍无装备。
- **风险**：🔴 城镇战力对比走 `PowerCalc.EquipSwapPowerDelta` 的 `EquipPowerDelta` 卡面预估分支（`PowerCalc.cs:181-192`），弹窗文案别写成「实际换装净差」；`CoShow` 有 60s 超时按战力自动选（`EquipReplaceConfirmUI.cs:107-123`），超时回调必须照常触发 `onDone`，别把领取流程挂死。

## 3. 目标数据流（改造后）

```
merc_skills.csv 新增「耗蓝」列 (索引 22)
        │  Cook → merc_skills.bytes
        ▼
MercSkillTable.Row.MpCost  ──►  MercSkillTable.MpCostOf(skillId)   【取耗蓝的唯一出口】
                                        │
MercSkillCaster.Bind() 读取 cost ◄───────┘
        │
Update(): CD 走完?
        │ 是
        ├─► BattleManager.TrySpendMercMp(slot, cost)   【扣蓝的唯一出口；不够=不放】
        │         └─ 成功 → TryCastMercActiveSkill() → _cooldownRemain = CooldownTotal
        │
        └─► BattleManager 每帧自然回蓝 → BattleUI.UpdateSkillEnergy(slot+1, mp / MP_MAX)
                                              └─ 现有那条蓝条，语义从「充能」改为「剩余 MP 比例」
```

**约定**：只有**主动**技能谈耗蓝（`Row.IsPassive` 的跳过）；CD 与 MP 是**两个串联的闸门**，先判 CD 再判 MP。

**风险点 / 边界**
- 引导局若 MP 太紧，小白可能整场放不出几次技（新手体验）→ 可用「引导局 MP 回复加倍」或「引导局固定给满」处理，需主人定。

- 不要动 `GameConfig.PLAYER_SKILL_USE_ENERGY`（玩家技能那套纯冷却制不动，避免双入口互相影响）。

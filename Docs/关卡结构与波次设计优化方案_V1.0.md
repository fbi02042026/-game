> ⚠ **本文档已被 V2.0 取代**（`关卡结构与波次设计优化方案_V2.0.md`）。
> V1.0 未考虑战场空间上限与 6 职业差异，其中「游猎 / 围杀拉开 / 箭雨压上」等原型经实测不可落地，请勿按本版施工。保留仅供对照。

> 日期：2026-09-15
> 范围：引导关（Tutorial）+ 正式关（Normal / Elite / Rest / Boss）的玩法结构、波次原型、敌人编成、卡点设计
> 目标：**好玩、有节奏、有记忆点；同时有真实卡点，不允许无脑一路通关**

## 零、结论先行

当前项目的关卡**有"流程骨架"，没有"关卡设计"**：战斗是一张横向卷轴，玩家唯一操作是前后走位，敌人从右侧进场、均分成 3–5 波、每波 3–4 只，构成完全一样。
难度全靠数值倍率堆（章节 1.0→2.8、精英 1.3×、Boss 1.6×），**没有空间难度、没有编成难度、没有节奏**。

本方案引入三层结构，三层都可以在现有代码上以"读表 + 少量分支"实现：

| 层 | 名称 | 解决什么 | 新增文件 |
|----|------|---------|---------|
| 1 | **波次原型（Wave Archetype）** | 每波长得一样 → 8 种原型，各有空间形态与唯一解 | `wave_archetype.csv` |
| 2 | **关卡节奏模板（Stage Rhythm）** | 一关是平铺的 → 按关卡类型编排出张力弧 | `stage_rhythm.csv` |
| 3 | **卡点与压力阀（Chokepoint / Pressure Valve）** | 只靠数值墙 → 设计墙 + 自适应加压 | `stage_modifier.csv` + `GameConfig.EnemyTuning` |

配套重做引导关：从「5 步 35 只怪」改成「7 拍 22 只怪」，每拍只教一件事，最后一拍**故意打不完**来教会"撤离"。

## 一、现状体检（带代码出处）

### 1.1 关卡结构

| 维度 | 现状 | 出处 |
|------|------|------|
| 章节 × 关卡 | 8 章 × 10 关，第 10 关固定 Boss | `GameConfig.STAGES_PER_CHAPTER = 10`；`ChapterManager.cs:103` |
| 关卡类型 | Normal / Elite / Rest / Boss，进关前摇号 | `StageRoller.Roll()`；权重在 `stage_roller_weights.csv` |
| Boss 窗口 | 倒数第 3 关起可能出 Boss，出过就不再出 | `bossWindow=3` |
| 恢复关 | 每章最多 2 个 | `maxRestPerChapter=2` |
| 属性倍率 | 森林 1.0 → 冰川 2.8（8 档） | `chapter_stat_scale.csv` |
| 战斗场景 | 单场景 `Battle.unity`，16 个 `MonsterSpawn_*` 点 | `Assets/Scenes/Battle.unity` |

### 1.2 波次生成（问题核心）

```csharp
// WavePlanner.BuildCombatWaves()
total     = GameConfig.GetStageMonsterTotal(stageIdx);   // 13~28，随进度涨
waveCount = GameConfig.GetSuggestedWaveCount(total, usable.Count);
perWave   = GameConfig.DistributeMonstersToWaves(total, waveCount);   // ← 近似均分
```

- 单波人数硬限 **2–4**（`WAVE_MONSTER_MIN/MAX`），`EnemyTuning.WaveCapMax = 5`
- 波次数量 `3–9`（`STAGE_WAVE_MIN/MAX`），实际落在 **4–5 波**
- `DistributeMonstersToWaves` 是**均分**：13 只 / 4 波 → `[4,3,3,3]`

**结果：一关就是 4–5 串一模一样的 3–4 只怪。** 玩家从头到尾只有一种体验、一种解法。

### 1.3 敌人编成（问题核心）

```
// WavePlanner.PickWaveSpriteIndex()
bool wantRanged = slotIndex % 2 == 1;   // 奇偶交替 = 近战 / 远程
```

`wave_slot.csv` 16 行全是这个规则的显式化：**偶数槽近战、奇数槽远程**。
每波都是"一半砍一半射"，永远如此。没有纯远程压制波、没有纯近战冲锋波、没有精英护卫波。

- 每章 12 种怪（1–10 普通，11–12 Boss），按通关次数解锁 5 → 8 → 10（`monster_unlock_tier.csv`）
- 攻击风格 Melee / Bow / Ranged 三档（`monster_attack_style.csv`）——**有素材，没用上**
- 词缀 6 种（狂暴 / 铁壁 / 荆棘 / 迅捷 / 吸血 / 分裂），**只挂精英和 Boss，且是纯数值**

### 1.4 引导关（问题核心）

`tutorial_battle.csv` 现状 5 步：

| order | action | count | 精英 | 普通血 | 精英血 |
|-------|--------|-------|------|--------|--------|
| 1 | normal | 6 | 0 | 68–72 | — |
| 2 | normal | 7 | 0 | 68–72 | — | ← **孤儿行，Director 根本没调用** |
| 3 | flank | 7 | 0 | 68–72 | — |
| 4 | around | 7 | 1 | 68–72 | 150–176 |
| 5 | normal | 8 | 0 | 68–72 | — |

- 实际出场 **35 只怪**，第一波就 6 只 —— 但此时玩家还没拿宝箱武器、没有佣兵、没有技能
- 引导里已有的好东西（`flank` 左右夹击、`around` 围殴）**正式关一次都没用**
- 结尾强制撤离，但玩家没有"打不过才撤"的体感，只是流程叫你撤

### 1.5 玩法手段盘点（可复用、当前闲置）

| 已有系统 | 状态 |
|---------|------|
| `bilateralEnter` 左右夹击 | 仅宝箱/佣兵埋伏用 |
| `aroundAnchor` 环绕围殴 | 仅教程用 |
| `staggerOverride` 出怪间隔 | 只用默认值 |
| 车道 `BattleLaneBounds` | 只做分散，不做阵型 |
| 词缀 6 种 | 只给精英/Boss |
| 撤离机制（保留金币） | 只有教程强制用 |
| 宝箱陷阱 | 只有教程用 |
| 波次预告 UI `BattleWaveAnnounceUI` | 存在，但没播"下一波是什么" |

**结论：弹药库里全是好东西，只是从来没编排成关卡。**

## 二、第一层：波次原型（Wave Archetype）

### 2.1 设计原则

1. 每个原型必须**一眼能认出来**（空间形态 / 编成 / 预告文案三项至少两项不同）
2. 每个原型必须**有唯一最优解**，且**至少两种可行解**（可通过性 + 技巧空间）
3. 只用现有刷怪能力实现：进场方向、`bilateralEnter`、`aroundAnchor`、`stagger`、车道、精英倍率、词缀

## 三、第二层：关卡节奏模板（Stage Rhythm）

### 3.1 一张关的张力弧

用原型把"4 波一样的怪"换成有起伏的剧本。三种关卡类型各一套。

**普通关**（按关卡索引分档）：

```
索引 0–1   A01 试探 → A02 散兵 → A02 散兵                      低 → 中
索引 2–4   A01 → A02 → A03 箭雨 → A04 夹击                     低 → 中 → 高(空间) → 释放
索引 5–7   A02 → A03 → A04 → A06 铁卫 → A02                    中 → 高 → 高 → 峰 → 呼吸
索引 8–9   A02 → A04 → A03 → A06 → A05 围杀 → A08 分裂巢        连续高压，不给喘息
```

**精英关**（精英关的定义从"数值 ×1.3"改成"两波精英夹一波潮"）：

```
普通章   A02 散兵 → A03 箭雨 → A06 铁卫 → A04 夹击 → A06 铁卫(双词缀)
高章(≥5) A02 → A04 → A06 → A07 游猎 → A06 → A08 分裂巢
```

**Boss 关**（保留 4 波小怪 + Boss，但小怪改用原型）：

```
A01 试探 → A02 散兵 → A03 箭雨 → A06 铁卫 → A09 首领
```

**恢复关**：无战斗，保留。

### 3.3 人数分配改法

`GameConfig.DistributeMonstersToWaves` 现在均分，改成**按原型给权重**：

```
weightPerWave = Σ archetype.count（该波原型的人数基准）
perWave[i]    = round(total × weight[i] / Σweight)，再 clamp 到 [2, archetype.cap]
```

这样 A05 围杀自然吃掉更多怪、A01 试探只吃 2 只，**总量不变但形状变了**。

## 四、第三层：卡点与压力阀

> 用户核心诉求：**有卡点、有难度、不要一路通关**。
> 卡点必须是**设计墙**（编成 / 空间 / 机制），不是数值墙。

### 4.1 四个硬卡点

| # | 位置 | 原型组合 | 卡在哪 | 通关条件 | 失败表现 |
|---|------|---------|--------|---------|---------|
| **CP1** | 每章第 3 关 | A03 箭雨首现 | **空间墙**：不压上就被远程磨死，后退=死 | 会走位压上，或已有护盾/位移 | 掉 40% 血，不致死 |
| **CP2** | 每章第 5 关 | A06 铁卫（精英+护卫） | **目标选择墙**：铁壁减伤 25%，打错目标打不动 | 会切目标 / 有 AOE 或破防 | 大概率被迫撤离 |
| **CP3** | 每章第 7 关 | A05 围杀 + A08 分裂巢 | **数量墙**：同帧 5 只围 + 死亡分裂 | 技能循环成型 + 会集火 | 死一次 |
| **CP4** | 每章第 10 关 | A09 首领二阶 | **DPS 墙**：60% 进二阶，伤害 ×1.30 | 构筑成型 | 死 / 撤离 |

### 4.2 Boss 二阶强化（CP4 具体化）

现有 `BossPhase2HpRatio = 0.60`、`BossPhase2DmgMul = 1.30` 已经不错，补一条：

> **二阶起每 12 秒召唤一波 A02 散兵（3 只）**，最多 3 波。

这让 Boss 战从"血条更长的小怪"变成 **"输出不足就被小怪淹"** 的真实 DPS 检查，也给了佣兵/AOE 构筑存在意义。

### 4.3 自适应压力阀（关键：防止一路平推）

在 `GameConfig.EnemyTuning` 增加三个参数：

```csharp
/// <summary>连续 N 关「无死亡且通关血量 > 70%」后，下一关 +1 波（追加 A02/A04）</summary>
public static int PressureStreakThreshold = 2;
/// <summary>加压上限：最多额外加几波</summary>
public static int PressureWaveCap = 2;
/// <summary>上一关死亡过 → 下一关 -1 波且首波延后 1.5s（兜底，不惩罚到底）</summary>
public static bool PressureMercyOnDeath = true;
```

行为：
- 连胜 2 关且都健康通关 → 第 3 关波次 +1（优先追加 A04 夹击或 A05 围杀）
- 每章开始重置，避免跨章滚雪球
- 死了就减 1 波 —— **给的是缓冲，不是保送**

这是"不要让玩家一路通关"最直接的一条：越强，关卡越厚。

### 4.4 关卡词条（阶段二，可选）

每关开战前随机 0–1 个词条，风险换收益，配合**撤离机制**制造决策：

| 词条 | 效果 | 收益 |
|------|------|------|
| 裂缝涌动 | 每波 +1 只 | 金币 +30% |
| 铁律 | 全怪减伤 15% | 装备掉率 +20% |
| 疾风 | 全怪移速 +25% | 额外天赋石 |
| 富矿 | 精英 +1 | 掉落品质 +1 档 |

玩家看到词条就要判断"这局我吃不吃得下，吃不下就早撤"——**把撤离从失败按钮变成策略按钮**。

### 4.5 关卡内可选风险：宝箱陷阱（正式关版）

教程里的宝箱夹击很好，正式关复用：
- 普通/精英关 **20% 概率**中途刷出裂隙宝箱
- 开箱 = 触发 A04 夹击（4 只）+ 掉 1 件装备
- 宝箱可见但不强制 —— **贪心与安全的选择权交给玩家**

## 五、引导关重做

### 5.1 现状问题

- 35 只怪、第一波就 6 只、玩家还没武器没佣兵没技能
- 教学顺序反了：最难的在最后，中间没有喘息
- 结尾"撤离"没有动机，只是流程叫你撤
- `order=2` 是孤儿行，从没被调用

### 5.2 新结构：7 拍，22 只怪，每拍只教一件事

|----|--------|------|------|------|--------|--------|

## 七、验收指标

按 blockout 纪律，**先灰盒跑通再上美术**。本方案改动全是逻辑与配表，验收以数据为准：

| 指标 | 目标 | 怎么测 |

**灰盒签入前不做任何美术改动。** 本方案第一期的改动全部是配表 + 刷怪逻辑，正好符合这一点。

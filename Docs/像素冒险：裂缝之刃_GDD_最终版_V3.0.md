# 1. 游戏定位与核心设计理念

## 1.1 游戏定位

### 1.1.1 游戏类型

《像素冒险》是一款 2D 像素风自动冒险构筑类游戏，核心玩法融合：

- 自动战斗
- Roguelike 随机成长
- 装备构筑
- 佣兵搭配
- 长期养成
- 章节探索

玩家通过一次次冒险，在有限资源和随机环境下逐渐建立属于自己的战斗流派。

### 1.1.2 目标用户

- 核心受众：喜欢 Roguelite、装备构筑与轻度策略的微信小游戏玩家。
- 次要受众：偏好像素美术风格与碎片化游戏体验的玩家。
- 用户特征：追求每局不同体验、乐于尝试多种 Build、接受自动战斗操作模式。

### 1.1.3 目标平台

- 首平台：微信小游戏（竖屏）。
- 设计分辨率：720 × 1280（9:16，适配全面屏及刘海屏）。
- 操作方式：竖屏触控，无虚拟摇杆与攻击按钮，以自动战斗为核心。
- 后续可扩展：其他小游戏平台 / 移动端 H5，但以微信小游戏技术限制为首要约束。

### 1.1.4 核心体验

玩家在裂缝外负责：选择武器方向、配置符石、雇佣佣兵、配置主动技能。
玩家在裂缝内负责：选择路线、判断是否拾取装备、是否消耗资源强化或附魔、是否继续深入或撤离。
战斗结果用于验证 Build 选择是否正确，而非验证操作水平。

## 1.2 核心设计理念

### 1.2.1 自动战斗不是降低策略

设计目的：避免小游戏玩家长期进行高强度操作，降低操作门槛，让玩家更关注“如何培养角色”而非“如何操作角色”。

传统动作游戏：操作水平 → 战斗胜负。
《像素冒险》：冒险决策 + Build 构筑 + 资源管理 → 战斗结果。

### 1.2.2 玩家身份

玩家不是战士操作者，而是“冒险队伍指挥者”。

- 冒险前：决定使用什么武器、携带什么技能、雇佣什么佣兵。
- 冒险中：决定选择什么路线、是否进入危险节点、是否替换装备、是否消耗资源强化。
- 冒险后：整理背包与仓库、筛选装备、分解冗余物品、调整下一次冒险方向。

### 1.2.3 选择重于数值

游戏核心不是“获得更高攻击力装备”，而是“这个装备是否适合当前玩法”。

例如：玩家当前为单手剑+盾组合，掉落一把攻击更高的大剑。玩家需要考虑：更换武器会导致盾的符石与防御加成失效、攻击速度降低、生存能力下降，因此不一定更换。

## 1.3 核心循环

核心循环如下：

1. 准备冒险
2. 选择武器方向
3. 配置符石
4. 雇佣佣兵
5. 进入章节
6. 探索地图
7. 获取随机资源
8. 形成 Build
9. 挑战 Boss
10. 整理背包与仓库
11. 永久成长
12. 挑战更高难度

## 1.4 局内与局外成长

### 1.4.1 局内成长

定义：进入裂缝后的临时成长。
内容包括：当前武器、当前装备、当前符石、当前强化、当前附魔、当前佣兵。
特点：只服务当前冒险；撤离后，背包中的装备、武器与天赋石保留至玩家背包，符石保留至符石背包，金币、强化材料、附魔石等顶部资源条资源永久保留；死亡后，背包中的装备、武器与天赋石保留，符石保留，但本局获得的金币清零，强化材料与附魔石仍保留（未超出上限部分）。
设计目的：保证每次进入裂缝都有探索感，玩家不能完全依靠永久数值碾压。

### 1.4.2 局外成长

定义：永久账号成长。
内容包括：天赋、符石收藏、装备收藏、武器收藏、资源积累、公会等级。
特点：长期保留。

## 1.5 核心卖点

- 每局体验不同：随机装备、随机符石、随机路线、随机强化机会、不同佣兵搭配。
- 深度 Build 构筑：武器、符石、天赋、装备、附魔、佣兵共同决定战斗方式。
- 自动战斗低门槛：无需复杂操作，专注于策略与构筑。
- 长期收集目标：符石、装备、武器、天赋构成持续成长动力。
- 风险与收益并存：玩家需要判断继续深入还是安全撤离。

## 1.6 程序实现要点

- 以 720 × 1280 为设计分辨率，实际渲染按设备像素比动态缩放；所有 UI 坐标使用设计分辨率逻辑像素。
- 帧率目标：战斗场景 30 FPS，UI 场景 30 FPS；在高性能设备可选 60 FPS。
- 主包代码 ≤ 4 MB，分包总代码 ≤ 20 MB；首包资源 ≤ 20 MB，其余资源走远程 CDN 或分包加载。
- 核心战斗与成长支持离线运行；登录、分享、广告、排行榜、云存档需微信环境。
- 使用 `wx.setStorageSync` 做本地存档，关键数据同时上传微信云存储 KV。
- 广告仅使用激励视频 `wx.createRewardedVideoAd`，复活/体力/翻倍/刷新等点位共用同一广告实例或分类管理。

## 1.7 美术实现要点

- 以 720 × 1280 画布为基准输出全部 UI 与特效；美术原画按 2× 制作（1440 × 2560），运行时缩放 0.5。
- 关键交互元素不得小于 88 × 88 逻辑像素，满足成人指尖点击。
- 所有界面需预留刘海/状态栏安全区（顶部 ≥ 64 px，底部 ≥ 68 px）与侧边挖孔安全区。
- 主色板每场景 32 色，全局 UI 辅助色板 16 色，特效使用 ADD/MULTIPLY 混合时需单独输出透明通道。

# 2. 世界观与叙事框架

## 2.1 世界观与背景故事

游戏世界观设定在一片名为**埃索斯（Aesoth）**的古老大陆上。在最早的古语里，**Aes-oth** 意为**“从伤口呼吸的土地”**。传说创世之初，诸神与一头名为“空洞之喉”的远古灾兽在此交战，为将它永远放逐，众神撕裂了世界的皮肤，把灾兽封进大地深处。那场战争留下的伤口从未真正愈合——它们化作了一道道会呼吸的裂口，便是后世所称的**裂缝**。这些连接异世界的空间裂口内部自成生态，越往深处越危险。

王国的人民早已习惯把裂缝当作天灾，只有最古老的史诗还在低语：那不是天灾，是世界本身仍在流血。为了应对裂缝带来的威胁，王国成立了**冒险者公会**（简称**公会**）。公会总部设有**冒险者大厅**，大厅中央的**咨询台**负责登记冒险者、派发任务、回收情报。公会对外宣称裂缝只是自然灾害、可以控制，但内部高层清楚：裂缝正在扩大，且没有人知道真正的原因。

城镇“灰港”是冒险者聚集地，而**冒险者大厅**是玩家冒险身份与长期成长中心。玩家在城镇中整理资源、雇佣佣兵、准备下一次进入裂缝。

一切的开端，源于玩家小时候有一位青梅竹马——小美。几年前，小美通过了公会考核，成为正式冒险者，之后与玩家的联系越来越少。几个月前，小美与圣殿骑士阿尔托、老猎人格雷组成三人小队，接受了公会最高级别的委托，进入最大的一道裂缝调查异常。出发前，她曾给玩家写过一封信，但信被随手放进了抽屉，一直没有拆开。

## 2.2 叙事基调

叙事风格为**日式勇者动画 + 慢热悬疑 + 情感反转**。前期轻松做任务，中期逐渐不对劲，后期感情爆发。

剧情约占整体游戏体验的 10%，主要用于世界观铺垫、角色塑造与版本更新引入新内容。叙事以“轻剧情、重氛围”为主，通过环境叙事、遗留物、Boss 背景故事与关键对话推进，不依赖大段演出。

## 2.3 裂缝结构

主线裂缝以章节为单位，每一章对应裂缝的一层：

| 章节 | 裂缝层级 | 主题 | 叙事功能 |
|---|---|---|---|
| 第一章 | 森林层 | 新人任务 | 新手生存，建立基础世界观 |
| 第二章 | 墓园层 | 安息之地 | 揭示亡灵异常，埋下不安伏笔 |
| 第三章 | 雨林层 | 异常生态 | 生态异常，扩展魔法与自然体系 |
| 第四章 | 海岛层 | 搁浅的船 | 发现小美小队痕迹，剧情转向好奇 |
| 第五章 | 草原层 | 被停止的风 | 时间流速异常，玩家意识到小美在深处 |
| 第六章 | 洞穴层 | 心脏 | 直面裂缝心脏，危机感达到顶峰 |
| 第七章 | 熔岩层 | 失控的同伴 | 小美被裂缝意志侵蚀，情感冲击 |
| 第八章 | 雪原层 | 核心之人 | 抵达最深处，击败最终 Boss“裂缝意志” |

不同层级在敌人类型、地图环境、奖励倾向上存在差异，强化世界探索感。

## 2.4 主要角色设定

### 玩家

公会新来的见习冒险者。没有特殊背景，只是想找份稳定工作，顺便赚点钱。小时候有一位青梅竹马叫小美，几年前她通过了公会考核，成为正式冒险者，之后联系越来越少。

### 小美

玩家的青梅竹马，公会最年轻的正式冒险者之一。外表温和，战斗力极强。几个月前，她与圣殿骑士阿尔托、老猎人格雷组成三人小队，接受了公会最高级别的委托，进入最大的一道裂缝调查异常。出发前给玩家写过一封信，但信被玩家随手放进了抽屉。

### 阿尔托

小美的队友，年轻的圣殿骑士。正直热血，把骑士荣耀挂在嘴边，但有时候有点中二。

### 格雷

小美的队友，退休后又复出的老猎人。经验丰富，嘴硬心软，一直怀疑小美有什么事瞒着大家。

### 咨询台小姐

公会前台，位于冒险者大厅的咨询台后，负责给新人派任务。公事公办，但偶尔会透露一些不该说的事情。

## 2.5 主线剧情流程

### 第一幕：普通的新人

玩家刚通过见习考核，被分配到裂缝清理任务。咨询台小姐递来一份协议：

> “见习冒险者，欢迎加入公会。你的第一个任务是进入森林裂缝层，清理异常怪物。请注意安全，你的保险明天才生效。”

玩家没有多想，拿起武器就进去了。前几章完全是常规任务：清怪、打 Boss、回收物资、领赏金。公会没告诉玩家裂缝的真相，玩家也懒得问。

### 第二幕：不对劲

从第三章开始，裂缝里的怪物显得有些异常。它们不像普通怪物那样只是攻击，而像是在躲避什么、守护什么。

第四章，玩家在海岛海岸发现了一艘搁浅的公会船只。船舱里有补给箱，箱子上刻着小队的编号。玩家这才想起：小美好像就是这支小队的成员，但还没意识到问题的严重性。

第五章，玩家在草原层发现了一座被毁掉的风车。风车内部刻着一行字：

> “裂缝在吞噬现实。必须有人去最深处。——M”

玩家开始觉得，这事没那么简单。

### 第三幕：真相

第六章，玩家在洞穴深处看到了裂缝的“心脏”——一颗悬浮的黑色晶石。晶石周围有小队留下的战斗痕迹，还有阿尔托破损的盾牌。玩家通过通讯石把情况报告给公会，但咨询台小姐只是平静地说：

> “请继续执行任务。公会会处理。”

第七章，玩家在熔岩层找到了阿尔托和格雷。但他们并没有被困在普通怪物群里——他们倒在地上，而一个被裂缝能量缠绕的人站在他们面前。那是小美，她已经变成了裂缝意志的化身，成了这一层的守护者。

阿尔托艰难地告诉玩家：

> “我们追到这一层的时候，她已经被那股力量抓住了。它把她变成了……这种东西。”

玩家被迫与她战斗。战斗中，小美的意识偶尔冲破控制：

> “……快走……去最深处……毁掉 throne……”

击败她后，黑色能量崩散，小美倒在玩家怀里，短暂恢复意识。她终于说出了真相：

> “最深处有一座黑色 throne……裂缝意志想用它完成封印……如果让它成功，我会彻底消失。”

她把武器交给玩家，然后昏了过去。阿尔托接过小美：

> “我们会守住这里。你去吧，把她带回来。”

### 第四幕：选择

第八章，玩家独自来到裂缝最深处。黑色晶石 throne 悬浮在雪原中央，最终 Boss“裂缝意志”以巨龙形态盘踞其上。它告诉玩家：

> “你打断了封印……那个灵魂本来可以成为完美的核心……既然她不肯坐上去，那就由你来替代。”

玩家拒绝了它的交易。战斗中，裂缝意志不断变换形态，甚至变成小美的样子试图干扰玩家，但玩家没有退缩。最后，玩家跃上 throne，击碎了黑色晶石。封印失效，裂缝崩塌，玩家拼命往回跑。

### 第五幕：之后

玩家一行人活着出来了。但封印被打破，大陆各地的裂缝开始失控。公会高层震怒，小美被停职调查，玩家因为违反命令被记过。但大家都不后悔。

小美看着玩家：

> “你把一切都搞砸了。现在，我们得一起收拾烂摊子。”

玩家笑了笑：

> “反正我也习惯了。”

主线结束，但真正的冒险才刚刚开始。

## 2.6 反转与玩家情绪曲线

| 阶段 | 玩家情绪 | 关键信息 |
|---|---|---|
| 第 1–2 章 | 轻松 | 只是普通任务，偶尔提到“前几天有支小队来过” |
| 第 3–4 章 | 好奇 | 怪物行为异常，发现公会船只和遗物 |
| 第 5–6 章 | 不安 | 看到留言、裂缝心脏，意识到小美可能出事了 |
| 第 7 章 | 冲击 | 发现小美被侵蚀，被迫以 Boss 形态与她战斗 |
| 第 8 章 | 爆发 | 独自面对裂缝意志，击碎 throne |
| 结局 | 释然 + 期待 | 救出小美，但封印失效，后续玩法开启 |

## 2.7 章节任务与剧情设计

### 第一章：森林层 · 新人任务

**表面目标：** 清理裂缝入口的怪物。

**实际伏笔：** 森林里的怪物比平常更躁动，似乎在逃离更深处。

**任务流程：**

1. 击败 10 只森林怪物。
2. 调查能量异常点。
3. 击败 Boss 森之守护者。

**剧情文案：**

咨询台小姐：

> “森林层是新人练手的好地方。前几天有支正式小队路过这里，你应该不会遇到太强的敌人。”

击败 Boss 后，在地上发现一道新鲜的剑痕，但不属于玩家的武器。

> “有人比你早到一步。也许是别的冒险者。”

**奖励：** 见习短剑强化石 ×3、金币 200。

### 第二章：墓园层 · 安息之地

**表面目标：** 安抚被惊扰的亡灵。

**实际伏笔：** 亡灵不是在攻击玩家，而是在逃离某个东西。

**任务流程：**

1. 清理不安的亡灵。
2. 调查墓园深处的异常能量。
3. 击败 Boss 墓园守卫。

**剧情文案：**

格雷的笔记（可在支线中获得）：

> “这里的亡灵不敢靠近裂缝深处。那里有什么东西在吸走它们的存在。”

击败 Boss 后，玩家发现一块断掉的箭头，箭尾刻着老练的猎人印记。

> “这种手艺……不是普通猎人能做到的。”

**奖励：** 生命药水 ×3、金币 300。

### 第三章：雨林层 · 异常的生态系统

**表面目标：** 调查雨林层的生态异常。

**实际伏笔：** 雨林里的怪物 unusually large，像是在被某种力量滋养。

**任务流程：**

1. 采集 3 个异常植物样本。
2. 击败变异怪物。
3. 击败 Boss 雨林巨蟒。

**剧情文案：**

在神庙入口，玩家发现一面被斩断的盾牌碎片。

> “这是……公会骑士的盾牌？怎么会碎在这里？”

击败 Boss 后，丛林深处传来一声低沉的震动。

**奖励：** 解毒药剂 ×2、金币 400。

### 第四章：海岛层 · 搁浅的船

**表面目标：** 回收搁浅船只上的公会物资。

**实际伏笔：** 船只是小美小队的补给船，但它不应该出现在这里。

**任务流程：**

1. 搜索船只残骸。
2. 击败占据海岸的海怪。
3. 击败 Boss 海妖蟹。

**剧情文案：**

在船舱里找到补给箱，箱子上有小队的编号。玩家愣住了。

> “这个编号……小美？她不是去执行别的任务了吗？”

箱子里有一瓶药水，标签上写着：

> “给后面来的人。如果你也下来了，记得别空腹。——M”

**奖励：** 高级生命药水 ×3、金币 500。

### 第五章：草原层 · 被停止的风

**表面目标：** 恢复风车运转，稳定裂缝层。

**实际伏笔：** 草原层的时间流速异常，风车内部刻着警告。

**任务流程：**

1. 调查停止的风车。
2. 击败干扰时间流的怪物。
3. 击败 Boss 时之风车精灵。

**剧情文案：**

风车内部刻着一行小字：

> “裂缝在吞噬现实。必须有人去最深处。——M”

玩家终于确定：小美不是去执行普通任务，她在做一件危险的事。通过通讯石联系公会，但对方只是淡淡地回应：

> “请继续执行任务，不要过度解读现场痕迹。”

**奖励：** 时间沙漏（饰品）、金币 600。

### 第六章：洞穴层 · 心脏

**表面目标：** 调查洞穴深处的能量源。

**实际伏笔：** 玩家看到裂缝的“心脏”——黑色晶石，以及小队留下的战斗痕迹。

**任务流程：**

1. 深入洞穴。
2. 接近黑色晶石。
3. 击败 Boss 晶石巨像。

**剧情文案：**

黑色晶石悬浮在洞穴中央，有节奏地脉动。晶石周围散落着铠甲碎片、断箭和一张烧焦的纸条。纸条上只剩下几个字：

> “……必须有人成为核心。否则一切……”

玩家意识到，小美可能打算做一件无法挽回的事。

**奖励：** 晶石碎片（强化材料）、金币 700。

### 第七章：熔岩层 · 失控的同伴

**表面目标：** 营救被困冒险者。

**实际剧情：** 玩家在熔岩层找到了阿尔托和格雷，但他们身边站着一个被裂缝能量缠绕的人——小美。她已经被裂缝意志侵蚀，成了这一层的守护者。

**任务流程：**

1. 穿越熔岩区域。
2. 营救阿尔托和格雷。
3. 击败 Boss **裂缝化身 · 小美**。

**剧情文案：**

玩家赶到时，阿尔托和格雷倒在岩石旁，浑身是伤。而小美悬空站立，眼神空洞，身上缠绕着黑色能量。

阿尔托艰难地开口：

> “我们追到这一层的时候，她已经被那股力量抓住了……它把她变成了……这种东西。”

格雷咬着牙：

> “别犹豫。那已经不是她了。只有打醒她，才有一线生机。”

Boss 战中，裂缝化身 · 小美使用玩家熟悉的招式，但每一击都带着裂缝的扭曲能量。战斗到一半，她的声音断断续续地传来：

> “……快走……别管我……去最深处……毁掉 throne……”

击败她后，黑色能量崩散，小美倒在玩家怀里，短暂恢复意识。她看着玩家，虚弱地笑了笑：

> “你这家伙……真的追到这里来了啊。”
> “听着……最深处有一座黑色 throne……裂缝意志想用它完成封印……如果让它成功，我会彻底消失。”
> “去……毁掉它……”

她把武器交给玩家，然后昏了过去。

阿尔托接过小美：

> “我们会守住这里。你去吧，把她带回来。”

格雷把最后一瓶药水和几支箭塞给玩家：

> “这一箭，你替我射进那家伙的脑子里。”

**奖励：** 小美的武器（解锁玩家临时技能）、阿尔托头盔（外观）、格雷的箭袋（佣兵强化材料）、金币 800。

### 第八章：雪原层 · 核心之人

**目标：** 抵达裂缝最深处，摧毁黑色 throne，终结裂缝意志。

**任务流程：**

1. 穿越雪原。
2. 抵达黑色 throne。
3. 击败最终 Boss **裂缝意志**。

**剧情文案：**

玩家独自来到裂缝最深处。黑色晶石 throne 悬浮在雪原中央，最终 Boss“裂缝意志”以巨龙的形态盘踞其上。它看着玩家，声音像是从四面八方传来：

> “你打断了封印……那个灵魂本来可以成为完美的核心……”
> “既然她不肯坐上去……那就由你来替代。”

战斗开始。裂缝意志不断变换形态，有时变成小美的样子试图干扰玩家，有时变成玩家最害怕的画面。但玩家没有退缩。

战斗最后，玩家跃上 throne，用全力击碎了黑色晶石。裂缝意志发出怒吼，身躯崩解。整个裂缝开始崩塌。玩家拼命往回跑。阿尔托和格雷抱着小美在出口等玩家，四人一起逃出。

**奖励：** 小美的信物（饰品）、裂缝核心（开启后续玩法）、金币 2000。

# 3. 战斗系统

## 3.1 系统定位

战斗系统是《像素冒险》的核心反馈系统。由于采用自动移动、自动攻击、自动战斗模式，战斗重点不是操作，而是让玩家通过战斗结果验证 Build 选择是否正确。

玩家在战斗前做出的选择——武器类型、符石搭配、装备属性、佣兵配置、主动技能——都会在战斗中体现。

## 3.2 战斗规则

### 3.2.1 自动战斗逻辑

角色进入裂缝后：

1. 自动前进
2. 发现敌人
3. 进入战斗状态
4. 根据武器类型自动攻击
5. 击败敌人
6. 掉落奖励
7. 继续探索

### 3.2.2 战斗状态

- 探索状态：角色移动，寻找下一事件。
- 战斗状态：遇到敌人，停止推进，进行自动战斗。
- 结算状态：敌人全部消灭，掉落资源，继续前进。

### 3.2.3 玩家操作内容

- 点击角色头像释放玩家主动技能
- 点击佣兵头像释放佣兵主动技能
- 选择是否拾取装备
- 在特定节点进行强化或附魔
- 选择下一路线

## 3.3 战斗流程

单次战斗流程：

1. 进入战斗区域
2. 检测敌人
3. 角色进入攻击范围
4. 自动攻击
5. 敌人受到伤害
6. 敌人死亡
7. 掉落奖励
8. 继续探索

## 3.4 主动技能

### 3.4.1 技能定位

主动技能是玩家在自动战斗中的核心主动操作，由玩家点击对应头像/技能按钮释放：玩家主动技能通过点击角色头像释放，佣兵主动技能通过点击佣兵头像释放。

### 3.4.2 技能规则

- 局外选择一个玩家主动技能，进入裂缝后技能固定。
- 玩家与已雇佣佣兵的主动技能均由玩家手动点击对应头像/技能按钮释放。
- 技能拥有冷却时间与使用条件；冷却期间按钮置灰并显示倒计时。
- 部分技能需要战斗积累后释放。

### 3.4.3 技能来源

技能主要来自武器类型、单手武器组合、天赋解锁/强化、符石、特殊装备效果，不是固定职业技能。

### 3.4.4 技能类型

| 类型 | 作用 | 适合 Build |
|---|---|---|
| 输出技能 | 快速清理敌人 | 攻击型 Build |
| 防御技能 | 提高生存 | 近战 Build |
| 辅助技能 | 强化当前流派 | 攻速提升、伤害提升等 |

## 3.5 敌人设计

### 3.5.1 普通敌人

- 作用：测试玩家基础能力。
- 特点：数量多，机制简单，但细分为不同 archetypes（见 3.11）。

### 3.5.2 精英敌人

- 作用：测试 Build 完整度。
- 特点：拥有特殊能力，例如高防御、高速、回血。
- 出现比例：普通 10%，困难 20%，地狱 30%。
- 精英由普通 archetype 叠加精英词条生成，保留原 archetype 的机制特征。

### 3.5.3 Boss 敌人

- 作用：章节最终检测，检测玩家整个 Build 是否成立。
- 设计目标：不是单纯提高血量，需要机制、阶段变化、攻击压力。
- TTK 目标：普通 60–90 秒，困难/地狱 90–120 秒。
- 每章最后两种敌人固定为章节 Boss 与精英 Boss（见章节敌人组合模板）。

## 3.11 敌人 archetype 设计

### 3.11.1 设计目标

普通小怪不再使用单一“低生命低攻击”模板，而是按照功能划分为 10 种 archetypes。每种 archetype 通过基础属性修正、特殊机制与对 Build 的考验点，迫使玩家在武器、符石、装备、佣兵与技能选择上做出针对性决策。

### 3.11.2 普通小怪 archetype 表

| archetype | 定位 | 生命系数 | 攻击系数 | 防御系数 | 攻速系数 | 特殊机制 | 对玩家 Build 的考验点 |
|---|---:|---:|---:|---:|---:|---|---|
| 脆皮输出 | 高伤低防 | 0.6 | 1.4 | 0.4 | 1.1 | 无特殊机制，纯输出 | 快速击杀、控制、爆发伤害 |
| 肉盾 | 高防低攻 | 1.8 | 0.6 | 1.6 | 0.7 | 嘲讽/吸引玩家与佣兵仇恨 | 破甲、穿透、持续输出、高 DPS |
| 控制 | 限制玩家 | 0.9 | 0.8 | 0.8 | 0.9 | 攻击附带概率眩晕/定身/减速 | 韧性、净化、远程、不被近身 |
| 治疗 | 团队续航 | 0.8 | 0.5 | 0.6 | 1.0 | 周期性为范围内友军恢复生命 | 优先击杀排序、爆发、打断 |
| 召唤 | 兵力补充 | 0.7 | 0.6 | 0.5 | 0.8 | 周期性召唤低血量小怪 | 范围伤害、快速清场、资源管理 |
| 自爆 | 亡语威胁 | 0.5 | 1.2 | 0.3 | 1.2 | 死亡时对附近单位造成高额范围伤害 | 远程、风筝、生命/减伤、走位 |
| 远程 | 后排输出 | 0.7 | 1.1 | 0.5 | 1.0 | 保持安全距离攻击 | 突进、控制、高机动或远程对射 |
| 飞行 | 规避近战 | 0.8 | 1.0 | 0.4 | 1.1 | 飞行状态，部分近战攻击无法命中 | 远程攻击、对空符石/技能 |
| 刺客 | 高速切入 | 0.7 | 1.2 | 0.4 | 1.3 | 高闪避/快速接近玩家 | 命中加成、控制、生存与减伤 |
| 元素施法者 | 范围元素伤害 | 0.8 | 0.9 | 0.5 | 0.9 | 释放范围元素技能（火/冰/雷/毒） | 元素抗性、位移、打断、续航 |

说明：系数以“标准普通小怪”为 1.0 进行修正；最终属性仍需叠加章节强度系数、公会等级系数、难度系数与连续深度系数。

### 3.11.3 精英变体生成规则

精英怪由普通 archetype 叠加 1–2 个精英词条生成，精英词条 pool 包括：

| 精英词条 | 效果 |
|---|---|
| 强壮 | 生命 +50% |
| 坚韧 | 防御 +40% |
| 狂暴 | 攻击 +30%，攻速 +20% |
| 迅捷 | 攻速 +40%，移速 +30% |
| 再生 | 每秒恢复最大生命 2% |
| 元素皮肤 | 获得一种元素抗性 +50%，攻击附带对应元素伤害 |
| 分裂 | 死亡时分裂为 2 个低血量同 archetype 小怪 |
| 复仇 | 受到伤害时临时提升攻击速度 |

### 3.11.4 设计原则

- 同一章节内应包含 4–6 种不同 archetypes，避免单一化。
- 敌人组合应迫使玩家同时处理“高威胁后排”与“高血量前排”。
- 飞行与自爆类敌人专门考验远程能力与生存能力，不能靠单一近战 Build 硬解。

## 3.12 强度曲线设计

### 3.12.1 设计目标

通过明确的章节强度系数，让怪物与佣兵在玩家成长的不同阶段承担不同角色：

- 前期（第 1–3 章）：怪物强度低于玩家，提供爽快感与 Build 试错空间。
- 中期（第 4–10 章）：怪物强度逼近并略超玩家，形成压力，验证 Build 完整度。
- 后期（第 11 章以后）：怪物强度显著高于玩家，需要成熟 Build、佣兵配合与资源管理。

### 3.12.2 怪物强度系数公式

以玩家同章节期望强度为基准 1.0，怪物强度系数 `K_mon(n)`（n 为章节数）采用分段线性：

```
K_mon(n) = 0.5 + 0.10 × (n − 1)                (1 ≤ n ≤ 3)
K_mon(n) = 0.7 + 0.057 × (n − 3)                (4 ≤ n ≤ 10)
K_mon(n) = 1.1 + 0.05 × (n − 10)                (n ≥ 11)
```

| 阶段 | 章节范围 | 怪物强度区间 | 体验目标 |
|---|---|---|---|
| 前期 | 1–3 章 | 0.50–0.70 | 爽快感、熟悉武器与机制 |
| 中期 | 4–10 章 | 0.76–1.10 | 压力递增、Build 验证 |
| 后期 | 11 章以后 | 1.15–1.50+ | 困难挑战、需要成熟构筑 |

注：该系数作用于敌人基础属性（生命/攻击/防御）之前，再叠加原有的难度系数（普通 1.0 / 困难 1.4 / 地狱 2.0）与公会等级系数。

### 3.12.3 佣兵强度系数公式

佣兵作为玩家辅助，其强度相对玩家呈衰减曲线，前期明显强于玩家，中期与玩家持平，后期低于玩家，避免佣兵替代玩家角色。

```
K_merc(n) = 1.2                                 (1 ≤ n ≤ 3)
K_merc(n) = 1.2 − 0.02857 × (n − 3)             (4 ≤ n ≤ 10)
K_merc(n) = 1.0 − 0.03 × (n − 10)               (n ≥ 11)
```

| 阶段 | 章节范围 | 佣兵强度区间 | 设计意图 |
|---|---|---|---|
| 前期 | 1–3 章 | 1.20 | 降低新手门槛，帮助玩家建立 Build |
| 中期 | 4–10 章 | 1.17–1.00 | 逐步退居辅助，玩家成为主力 |
| 后期 | 11 章以后 | 0.97–0.70 | 佣兵仅提供战术补充，不能碾压 |

### 3.12.4 应用方式

- 敌人最终属性 = 敌人基础属性 × `K_mon(n)` × (1 + 章节系数) × (1 + 公会等级系数) × 难度系数 × (1 + 连续深度系数)。
- 连续深度系数 = 0.10 × 当前已通关章节数，仅在连续章节冒险中累计，撤离/死亡后清零。
- 佣兵最终属性 = 玩家同章节期望属性 × `K_merc(n)`（再按品质与武器类型修正）。
- 数值团队可根据实际测试在 ±10% 范围内微调系数，但不改变曲线形态。

## 3.6 数值参数

### 3.6.1 基础属性

| 属性 | 来源 | 说明 |
|---|---|---|
| 生命 HP | 角色基础 + 装备 + 天赋 | 归零则死亡 |
| 攻击力 ATK | 武器 + 装备 + 符石 + 天赋 | 决定基础伤害 |
| 防御力 DEF | 装备 + 符石 + 天赋 | 减法公式减伤 |
| 攻击速度 | 武器基础 + 符石 + 天赋 | 百分比加成 |
| 暴击率 | 符石 + 装备词条 + 天赋 | 上限 80% |
| 暴击伤害 | 符石 + 装备词条 + 天赋 | 基础 50% |
| 伤害加成 | 符石 + 装备套装 + 天赋 | 乘法区间 |
| 最终减伤 | 天赋 + 特殊符石 | 上限 50% |
| 元素抗性 | 装备词条 + 符石 | 对对应元素伤害减免 |

### 3.6.2 战斗公式

- 基础伤害：`Damage = max(1, ATK - DEF)`
- 暴击：`Critical Damage = Damage × (1.5 + CriticalDamageBonus)`，暴击率上限 80%。
- 最终伤害：`FinalDamage = Damage × (1 + DamageBonus) × (1 - FinalReduction) × ElementalMultiplier`
- 攻速：`AttackInterval = BaseInterval / (1 + AttackSpeedBonus)`
- 生命恢复：每秒恢复 `MaxHP × 0.5%`（基础）。

### 3.6.3 TTK 目标

| 敌人类型 | TTK |
|---|---|
| 普通小怪 | 3–5 秒 |
| 精英怪 | 7–12 秒 |
| 章节 Boss | 60–90 秒（普通）/ 90–120 秒（困难/地狱） |

### 3.6.4 难度缩放

`敌人属性 = 基础值 × (1 + 章节系数) × (1 + 公会等级系数) × 难度系数 × (1 + 连续深度系数)`

| 系数 | 数值 |
|---|---|---|
| 章节系数 | 第 n 章：`0.15 × (n - 1)` |
| 公会等级系数 | `0.02 × 公会等级` |
| 难度系数 | 普通 1.0 / 困难 1.4 / 地狱 2.0 |
| 连续深度系数 | `0.10 × 当前已通关章节数` |

说明：
- 玩家一次冒险连续打多章时，无论选哪一章，每过一章难度额外提升。
- 第一章通过后进入第二章时，当前已通关章节数为 1，连续深度系数为 0.10；第二章通过后进入第三章时，系数为 0.20，以此类推。
- 死亡或撤离后重新进入冒险，连续深度系数清零。

## 3.7 与其他系统关系

| 系统 | 关系 |
|---|---|
| 武器系统 | 武器决定攻击方式 |
| 符石系统 | 符石决定战斗流派 |
| 装备系统 | 装备提供属性提升 |
| 强化/附魔系统 | 强化与附魔改变装备数值与特性 |
| 佣兵系统 | 佣兵提供战术补充 |
| 地图系统 | 路线决定成长机会 |

## 3.8 设计原则

- 战斗核心不是操作，而是 Build 验证。
- 自动战斗降低门槛，但不降低策略深度。
- 不同 Build 应该追求不同属性组合，避免单一属性碾压。
- 失败不应让玩家感觉“全部浪费”，而是产生“差一点，需要优化 Build”的体验。

## 3.9 程序实现要点

- 战斗状态机：`Idle`（探索）→ `Engage`（索敌）→ `Attack`（攻击间隔）→ `CastSkill`（技能释放）→ `Settlement`（掉落）。
- 攻击采用时间轮：每个战斗单位维护 `nextAttackTime`，每帧比较 `Time.now` 触发命中判定。
- 命中判定使用碰撞盒（AABB），主角攻击盒大小由武器类型配置，例如单手剑 96×48、大剑/长柄武器 144×96、弓箭为投射体。
- 掉落采用对象池（Object Pool），避免频繁创建/销毁节点造成 GC。
- 示例配置表字段：

```ts
interface WeaponConfig {
  id: string;
  type: WeaponType;
  baseAtk: number;
  baseInterval: number; // 秒
  attackRange: number;      // 逻辑像素，决定 AI 索敌距离与普攻最远距离
  attackWidth: number;      // 近战攻击盒宽度；远程为 0
  attackAngle?: number;     // 扇形/锥形攻击角度，0 表示直线
  projectileSpeed?: number; // 远程投射体速度（像素/秒）
  projectileSize?: number;  // 远程投射体碰撞半径
  isMelee: boolean;         // 是否近战
  skillId?: string;
}
```

- 攻击距离/范围配置直接驱动战斗 AI：`BattleUnitAI` 在 `Engage` 状态下根据 `attackRange` 决定停止移动并进入 `Attack` 状态的距离；远程武器在敌人进入 `attackRange` 后发射投射体，近战武器在攻击帧生成对应 `attackWidth × attackRange` 的命中盒。
- 单手武器组合时，主手与副手分别读取各自的 `WeaponDriver`，同时仅允许一个攻击间隔运转，优先使用主手攻击范围进行索敌，副手在允许距离内追加特效/伤害。
- 技能释放由 `SkillButton` 状态机管理：

```ts
enum SkillButtonState { Idle, Cooling, Charging, Disabled }
interface SkillButton {
  ownerId: string;          // player 或 mercenary id
  skillId: string;
  state: SkillButtonState;
  cooldownEndTime: number;
  chargeProgress: number;   // 0–1
}
```

## 3.10 美术实现要点

- 主角 Sprite 尺寸 64 × 64 px；Boss Sprite 128 × 128 px；普通敌人 64 × 64 px；精英敌人 80 × 80 px。
- 动画帧数：待机 4 帧、移动 6 帧、攻击 6–8 帧、受击 2 帧、死亡 6 帧、技能 8–12 帧。
- 攻击特效需与武器命中帧同步，例如第 3 帧产生命中盒与闪光。
- 切图命名：`char_hero_{weapon}_{action}_{frame}.png`，如 `char_hero_dagger_attack_01.png`。

# 4. 武器系统

## 4.1 系统定位

武器是《像素冒险》最核心的战斗构筑基础。所有 Build 的形成都围绕武器展开。武器决定：

- 攻击方式
- 战斗距离
- 输出节奏
- 适合属性
- 符石方向
- 佣兵搭配

武器不是单纯数值装备，不同武器必须提供不同玩法。

## 4.2 武器类型

游戏设定以下五种武器类型：

| 武器类型 | 定位 | 攻击方式 | 攻击距离/范围 | 优势 | 劣势 | Build 倾向 |
|---|---|---|---|---|---|---|
| 单手剑 | 灵活近战核心 | 主手快速斩击；双持时两把单手剑交替攻击，可分别触发各自符石 | 96 px（近战，水平斩击盒 96×48） | 攻速快、搭配自由、连击稳定 | 单把面板较低、依赖组合 | 双剑攻速/暴击、剑盾防御/反伤、剑杖魔武 |
| 大剑 | 高爆发双手近战 | 双手重劈，范围大，可蓄力造成更高伤害 | 128 px（近战，重劈盒 144×96，可穿透 2 个目标） | 单次伤害高、范围大、压制强 | 攻速慢、无法双持、后摇明显 | 暴击爆发、范围清怪、破甲 |
| 长柄武器 | 中距离控制输出 | 直线突刺/横扫，部分带穿透 | 144 px（中程，突刺盒 160×40，直线穿透 3 个目标） | 中程安全、范围控制、连击节奏稳定 | 被近身压力大、无法双持 | 控制流、范围流、攻速戳刺 |
| 单手杖 | 魔法近战/远程辅助 | 释放元素弹道或光环；可搭配盾/剑组成魔武 | 120 px（远程/半近战，元素弹道速度 240 px/s，碰撞半径 16 px） | 元素伤害、技能强化、搭配灵活 | 普攻面板低、怕强近身 | 元素流、技能强化流、魔武结合 |
| 弓箭 | 远程持续输出 | 连续射箭，可蓄力强化单发 | 200 px（远程，箭矢速度 360 px/s，碰撞半径 12 px） | 安全距离、攻速高、暴击潜力 | 被近身后压力大 | 暴击流、攻速流、元素流 |
| 盾 | 防御/反击副手 | 主手为盾时进行盾击并触发防御特效；副手时提供格挡/减伤 | 64 px（近战，盾击盒 80×48） | 生存强、容错高、可反伤 | 单独输出极低 | 防御流、反伤流、剑盾/杖盾生存 |

单手武器（单手剑、单手杖、盾）可自由搭配：双剑、剑盾、剑杖、双盾等。组合时两把武器的属性、符石、攻击方式同时生效，但同类型符石效果不叠加。

单手组合攻击距离取主手武器攻击距离；AI 以主手范围索敌，副手在允许距离内追加特效/伤害。例如：

| 组合 | 主手 | 副手 | 有效攻击距离 | AI 行为影响 |
|---|---|---|---|---|
| 双单手剑 | 单手剑 | 单手剑 | 96 px | 快速近身连击，两把武器交替触发命中 |
| 单手剑+盾 | 单手剑 | 盾 | 96 px | 以单手剑范围进攻，盾在受击侧触发格挡/反伤 |
| 单手剑+单手杖 | 单手剑 | 单手杖 | 96 px | 近战斩击为主，副手元素弹道在中距离补刀 |
| 单手杖+盾 | 单手杖 | 盾 | 120 px | 中距离施法，盾提供近身保护 |
| 双盾 | 盾 | 盾 | 64 px | 极短距离盾击，主打防御/反伤 |

攻击距离影响战斗 AI 的站位与技能释放：远程 Build 会主动保持最远距离输出，近战 Build 会贴近目标；当敌人进入有效范围时停止移动并进入攻击状态，技能释放同样受最远距离限制，超出范围时不会触发。

1. 击败敌人
2. 武器掉落地面
3. 玩家查看
4. 弹出武器信息
5. 选择是否拾取

## 4.4 武器品质

## 4.5 数值参数

### 4.5.1 品质与强化上限

| 优秀 | +2 |

### 4.5.2 武器类型与推荐搭配

## 4.6 与其他系统关系

| 系统 | 关系 |
|---|---|
| 符石系统 | 符石按武器类型配置；单手武器组合时主副手符石同时生效（同类型不叠加） |
| 装备系统 | 装备辅助武器玩法，提供基础属性与套装效果 |
| 强化/附魔系统 | 提升武器基础属性或增加特殊词条 |
| 天赋系统 | 天赋强化武器玩法、解锁并强化武器技能，不限制武器使用 |

## 4.7 设计原则

- 不同武器必须提供不同玩法，不能仅通过数值区分。
- 武器价值来自攻击方式、适配属性、适配符石、传奇特性。
- 不存在万能武器，所有武器都有优势场景与劣势场景。
- 武器组合决定基础玩法，天赋决定成长方向，符石改变战斗机制。

## 4.8 程序实现要点

- 武器配置按类型+品质分表，避免单表过大：

```ts
interface WeaponItem {
  uid: string;
  configId: string;
  quality: Quality;
  star: number;
  affixes: Affix[];
  boundWeaponType: WeaponType;
}
```

- 武器攻击逻辑由 `WeaponDriver` 根据配置动态装配：近战使用碰撞盒，远程生成 `Projectile`。
- 武器掉落进入裂缝临时背包；玩家可选择拾取或放弃。死亡/撤离后，背包中的武器保留至玩家背包；玩家可在城镇中手动将武器移入仓库收藏或用于后续配置。
- 攻击距离/范围由 `WeaponDriver` 根据配置动态装配：近战根据 `attackRange`、`attackWidth`、`attackAngle` 在命中帧生成 `PolygonCollider` 或 `BoxCollider`；远程根据 `projectileSpeed`、`projectileSize` 生成 `Projectile` 对象池对象。
- 战斗 AI 共享 `BattleUnitAI`，通过 `attackRange` 决定 `Engage → Attack` 状态切换距离；远程单位会在 `attackRange × 0.9` 处停止并进入攻击，近战单位贴近至 `attackRange` 后攻击。

## 4.9 美术实现要点

- 武器图标尺寸 96 × 96 px，按品质加发光描边：普通白、优秀绿、稀有蓝、传奇黄。
- 地面掉落武器使用 80 × 80 px 静态图，带上下浮动动画 8 帧循环。
- 切图命名：`icon_weapon_{type}_{quality}_{id}.png`，如 `icon_weapon_dagger_rare_003.png`。

# 5. 装备系统

## 5.1 系统定位

装备系统是玩家在裂缝中进行临时成长的重要组成部分。装备承担：

- 提升基础属性
- 改变 Build 方向
- 提供套装效果
- 配合武器形成流派

装备不是“数值越高越换”，而是“是否适合当前玩法”。

## 5.2 装备分类

### 5.2.1 装备位置

| 部位 | 作用 |
|---|---|
| 头盔 | 提升生存能力 |
| 护甲 | 提升生存能力 |
| 手套 | 提升攻击或特殊属性 |
| 鞋子 | 提升移动或闪避属性 |
| 饰品 | 提供特殊属性，包括戒指、项链、护符 |

### 5.2.2 装备品质

| 品质 | 颜色 | 定位 |
|---|---|---|
| 普通 | 白 | 前期过渡 |
| 优秀 | 绿 | 属性提升 |
| 稀有 | 蓝 | 出现实用效果 |
| 传奇 | 黄 | 特殊机制 |

## 5.3 装备获取与掉落

### 5.3.1 掉落来源

- 普通怪：概率掉落普通装备
- 精英怪：提高品质概率
- 宝箱：提供随机装备
- Boss：提供高级装备

### 5.3.2 掉落规则

高品质掉落由“裂缝难度 + 天赋”共同决定。基础权重由难度配置，天赋提供额外加成。

掉落权重公式：

`实际权重 = 基础权重 × (1 + 天赋掉率加成)`

其中：

- 天赋掉率加成仅作用于稀有及以上品质。
- 不同天赋可叠加，但同类取最高值。
- Boss 宝箱额外提升一个品质等级。

### 5.3.3 难度基础权重表

| 难度 | 普通 | 优秀 | 稀有 | 传奇 |
|---|---|---|---|---|
| 普通 | 60 | 30 | 10 | 0 |
| 困难 | 40 | 38 | 20 | 2 |
| 地狱 | 25 | 38 | 30 | 7 |

### 5.3.4 天赋掉率加成示例

| 天赋名称 | 效果 | 数值示例 |
|---|---|---|
| 宝藏嗅觉 | 稀有及以上权重 +10% | 困难稀有 20 → 22，传奇 2 → 2.2 |
| 精英猎手 | 精英/Boss 掉传奇权重 +15% | 困难传奇 2 → 2.3 |
| 幸运儿 | 全局非普通权重 +5% | 困难优秀 38 → 39.9，稀有 20 → 21，传奇 2 → 2.1 |
| Boss 猎人 | Boss 宝箱品质 +1 概率 +20% | 提升后品质再升一档概率增加 |

### 5.3.5 掉落表现

裂缝内获得新装备时，装备不会自动穿到玩家身上。流程为：

1. 击败怪物
2. 装备掉落地面并短暂展示
3. 若战斗背包有空间，新装备自动进入战斗背包
4. 若该装备比当前身上对应部位更好，弹出装备对比界面；玩家可选择“装备”（替换当前穿戴部位）、“放入背包”或“丢弃”
5. 若背包已满，弹出替换界面：对比新装备与背包内指定装备，玩家可选择“替换旧装备”、“直接装备”或“丢弃”
6. 丢弃的装备直接转化为强化材料并进入顶部资源条

设计目的：避免自动替换破坏玩家已构建的 Build，让玩家基于当前玩法主动决定是否更换装备；背包满时仍保留直接装备通道，减少因空间不足错过核心装备的尴尬。

## 5.4 装备信息界面

玩家查看装备时显示：

- 装备名称、品质、类型、等级
- 属性（攻击力、生命、防御、暴击等）
- 特殊词条（例如攻击速度 +5%、受到伤害降低）
- 套装信息（如果属于套装，显示当前套装数量）
- 与当前装备的对比（增加属性、减少属性）

## 5.5 背包规则

### 5.5.1 背包定位

背包是玩家在裂缝与城镇中携带物品的核心空间。裂缝中的“战斗背包”用于临时存放冒险中拾取的装备、武器与天赋石；返回城镇后，战斗背包中的物品保留在玩家背包中，玩家可在此进行穿戴、分解或移入仓库等操作。

### 5.5.2 背包内容

| 物品类型 | 存放位置 | 说明 |
|---|---|---|
| 装备（头盔/护甲/手套/鞋子/饰品） | 战斗背包 / 玩家背包 | 拾取后按装备大小占用背包格子；裂缝内不会自动穿戴，玩家需手动选择装备或放入背包；已穿戴装备显示“已穿戴”标记，未穿戴装备显示在背包中；死亡/撤离时背包内装备被带回 |
| 武器 | 战斗背包 / 玩家背包 | 拾取后按武器大小占用背包格子；当前装备的武器显示“已装备”标记；死亡/撤离时背包内武器被带回 |
| 符石 | 符石背包 | 获取后进入符石背包，不占普通背包格子 |
| 天赋石 | 战斗背包 / 玩家背包 | 占用背包格子（1×1，可堆叠），死亡/撤离时背包内天赋石被带回 |
| 金币 | 顶部资源条 | 不占背包，进入顶部资源条 |
| 强化材料 | 顶部资源条 | 不占背包，进入顶部资源条，显示数量并受上限限制 |
| 附魔石 | 顶部资源条 | 不占背包，进入顶部资源条，显示数量并受上限限制 |

### 5.5.3 格子规则

| 物品类型 | 占用格子 |
|---|---|
| 戒指/小饰品 | 1×1 |
| 天赋石 | 1×1（可堆叠） |
| 手套/鞋子/单手剑/单手杖/盾 | 1×2 |
| 头盔/护甲/弓箭 | 2×2 |
| 大剑/长柄武器 | 2×3 |

符石不占用普通背包格子，独立存放在符石背包中。

### 5.5.4 背包满处理

战斗背包满时，获得新装备会弹出“替换/直接装备/丢弃”处理界面，玩家可以：

1. 查看新装备信息
2. 打开当前背包
3. 查看已有装备
4. 选择替换背包内旧装备、直接装备到对应部位，或丢弃新装备
5. 丢弃的装备直接转化为强化材料并进入顶部资源条

若背包有空间且新装备优于当前穿戴部位，则弹出装备对比界面，玩家可选择装备、放入背包或丢弃。

返回城镇后，玩家背包容量充足，不再出现因背包满而无法获得物品的情况。

## 5.6 装备带回规则

| 资源类型 | 存放位置 | 带回规则 |
|---|---|---|
| 装备（仅在背包中时） | 玩家背包 | 死亡/撤离时，战斗背包中的装备保留至玩家背包；未拾取的装备不保留；已穿戴装备显示已穿戴标记 |
| 武器（仅在背包中时） | 玩家背包 | 死亡/撤离时，战斗背包中的武器保留至玩家背包；未拾取的武器不保留；当前装备的武器显示已装备标记 |
| 符石 | 符石背包 | 获取后直接进入符石背包，死亡/撤离时全部保留 |
| 天赋石 | 玩家背包 | 占用背包格子，死亡/撤离时背包内天赋石保留；超出堆叠上限或背包满时按背包规则处理 |
| 金币 | 顶部资源条 | 不占背包；撤离时全部保留（含本局获得）；死亡时本局获得的金币清零，已拥有的基础金币不受影响 |
| 强化材料 | 顶部资源条 | 不占背包，死亡/撤离时均保留，受上限限制，超出上限部分不保留 |
| 附魔石 | 顶部资源条 | 不占背包，死亡/撤离时均保留，受上限限制，超出上限部分不保留 |

**重要规则：** 装备与武器只有在背包里才会保留；死亡/撤离时不会自动进入仓库，而是回到玩家背包。玩家可在城镇中手动将装备/武器移入仓库，以获得长期安全保存与收藏展示。

**死亡资源规则设计理由：** 本局获得的金币清零，是为了让死亡仍具备明确的经济风险，玩家不能无成本地“赌”高收益节点；强化材料与附魔石保留，是因为它们已绑定到装备成长循环，若死亡丢失会严重中断 Build 迭代与玩家成长节奏，且其产出已受背包空间、上限与节点随机性约束，保留可降低挫败感并维持长期养成动力。

## 5.9 设计原则

- 装备必须产生选择压力，玩家不能看到新装备直接替换；裂缝内装备不会自动穿戴，需玩家主动决策。
- 控制装备获取数量，避免仓库膨胀与装备价值降低。
- 背包限制迫使玩家在冒险过程中不断做取舍。
- 装备与武器只有在背包中才会保留，玩家需在背包与仓库之间手动管理，强化取舍与收藏策略。

## 5.10 程序实现要点

- 装备数据结构：

```ts
interface GearItem {
  uid: string;
  configId: string;
  slot: GearSlot;
  quality: Quality;
  star: number;
  baseStats: StatMap;
  affixes: Affix[];
  setId?: string;
}
```

- 掉落时生成 `LootDrop` 对象，包含 `configId`、`quality`、`affixSeed`，避免提前生成完整对象。
- 品质判定使用加权随机：`quality = weightedRandom(baseWeights.map(w => w * (1 + bonus)))`。
- 玩家背包与仓库分离：背包存放当前拥有的装备与武器；仓库需玩家手动从背包选择物品移入，提供长期安全保存、收藏展示与筛选排序。
- 仓库支持按部位/类型分页，筛选、排序、锁定、分解。
- 分解装备产出强化材料，材料数量由品质和星级决定；分解后材料进入顶部资源条，受上限限制。
- 裂缝内装备拾取与替换状态机：

```ts
enum LootHandleAction { Equip, Replace, Discard, Cancel }
interface LootHandleContext {
  newGear: GearItem;
  currentEquipped?: GearItem; // 当前对应部位已穿戴装备
  backpack: Item[];
  onAction: (action: LootHandleAction, targetUid?: string) => void;
}

// 背包有空间且新装备优于当前穿戴部位时触发对比弹窗
// 背包满时直接进入替换/直接装备/丢弃弹窗
```
- 丢弃/分解装备时立即计算材料数量并写入 `DungeonRun.resources.enhanceMaterials`，同时播放材料获得飘字。
- 已穿戴标记通过 `GearItem.equipped: boolean` 与 `WeaponItem.equipped: boolean` 维护；角色界面与背包界面读取该字段显示“已穿戴/已装备”角标。

## 5.11 美术实现要点

- 装备图标尺寸 88 × 88 px，按部位分区角标：头盔 H、护甲 A、手套 G、鞋子 B、饰品 T。
- 品质边框 96 × 96 px，中心镂空 88 × 88 px，命名：`frame_quality_{quality}.png`。
- 套装图标需额外显示套装角标：`set_marker.png`，尺寸 24 × 24 px。
- 地面掉落装备使用 72 × 72 px 静态图 + 光晕循环动画。

# 6. 强化与附魔系统

## 6.1 系统定位

强化系统与附魔系统共同承担装备成长和局内 Build 强化。二者功能必须明确区分：

- 强化：提升装备原本能力。
- 附魔：改变装备特性，增加随机词条。

简单理解：强化 = 变强，附魔 = 变特殊。

## 6.2 强化系统

### 6.2.1 强化定位

强化属于局内成长系统。玩家进入裂缝后，通过探索获得强化材料，在满足条件后进入强化房进行强化。

### 6.2.2 强化资源

强化材料来源：

- 怪物掉落
- 宝箱
- 特殊房间
- 精英奖励

强化材料不占背包，采用类似金币的资源形式显示在顶部资源栏。

### 6.2.3 强化房

强化不是随时进行，需要遇到强化房。流程为：

1. 探索地图
2. 进入强化房
3. 检测强化条件
4. 选择装备
5. 消耗材料
6. 提升星级

### 6.2.4 升星效果

升星主要提升基础属性：

- 武器：攻击力、攻击速度
- 防具：防御、生命
- 饰品：特殊属性

### 6.2.5 升星限制

| 品质 | 最高星级 |
|---|---|
| 普通 | +1 |
| 优秀 | +2 |
| 稀有 | +4 |
| 传奇 | +5 |

限制原因：避免低品质装备因为投入大量材料超过高级装备，同时增加玩家追求高品质装备的动力。

## 6.3 附魔系统

### 6.3.1 附魔定位

附魔负责增加随机词条。例如：装备原本攻击 +50，附魔后额外获得“攻击时 5% 概率造成额外伤害”。

### 6.3.2 附魔材料

附魔使用附魔石。附魔石不分类，所有附魔随机产生词条。

### 6.3.3 附魔流程

1. 获得附魔石
2. 遇到附魔房
3. 选择装备
4. 消耗附魔石
5. 随机生成词条
6. 确认是否保留

### 6.3.4 附魔结果

- 单次附魔获得一条随机词条。
- 高级装备可拥有 1–2 条词条，防止无限堆叠。

## 6.4 数值参数

### 6.4.1 强化与附魔对比

| 系统 | 作用 | 改变 |
|---|---|---|
| 强化 | 提升基础能力 | 数值 |
| 附魔 | 增加特殊效果 | 玩法 |

### 6.4.2 装备 Build 三层结构

| 层级 | 系统 | 作用 |
|---|---|---|
| 第一层 | 装备 | 决定基础方向 |
| 第二层 | 强化 | 提高强度 |
| 第三层 | 附魔 + 符石 | 形成玩法 |

## 6.5 与其他系统关系

| 系统 | 关系 |
|---|---|
| 装备系统 | 装备决定强化价值与词条空间 |
| 符石系统 | 附魔与符石共同决定 Build 玩法 |
| 地图系统 | 地图提供强化房与附魔房节点 |
| 经济系统 | 强化材料与附魔石通过裂缝掉落获取 |

## 6.6 设计原则

- 强化与附魔必须在局内进行，避免玩家提前把装备培养到最高。
- 强化 = 数值成长，附魔 = 随机惊喜，两者功能明确区分。
- 强化需要投资判断，增加冒险压力。
- 附魔随机产生词条，增加刷取动力。

## 6.7 程序实现要点

- 强化房/附魔房作为特殊地图节点，进入后切换到黑底菜单场景，暂停战斗计时。
- 强化消耗配置示例：

```ts
interface EnhanceCost {
  quality: Quality;
  star: number;
  materialCost: number;
  statGainPercent: number; // 每星提升百分比
}
```

- 附魔词条池按装备部位与品质分级，使用 `affixPool` + `seed` 保证可复现。
- 强化与附魔仅在当前裂缝生效；撤离/死亡后，强化/附魔结果随装备保留在玩家背包中。玩家可在城镇中将强化/附魔后的装备手动移入仓库。

## 6.8 美术实现要点

- 强化房背景：`bg_room_enhance.png`，尺寸 720 × 1280。
- 附魔房背景：`bg_room_enchant.png`。
- 升星动画：星星逐个亮起，持续 0.5 秒，特效 `fx_star_up.png` 8 帧。
- 附魔成功特效：`fx_enchant_success.png`，12 帧，播放一次。

# 7. 符石系统

## 7.1 系统定位

符石是《像素冒险》中连接武器类型、战斗流派与长期收藏的重要系统。符石不是普通装备强化，它代表玩家对某一种武器玩法的深入研究。

符石承担三个作用：

1. 强化武器特色。
2. 创造 Build 差异。
3. 提供长期收集目标。

## 7.2 符石装备规则

### 7.2.1 绑定武器类型与组合规则

符石绑定到武器类型，不绑定具体武器。每种武器类型拥有独立符石页签。

- 装备一把武器时，仅生效该武器类型对应的符石。
- 使用单手武器组合（如单手剑+盾、单手剑+单手杖、双单手剑）时，主手与副手武器类型的符石同时生效。
- 双持同类型单手武器（如双单手剑）时，该类型符石仅生效一次，不叠加。
- 大剑与长柄武器为双手武器，不可双持，仅生效对应类型的符石。

### 7.2.2 槽位规则

- 每种武器类型拥有独立符石页签。
- 初始 3 槽，公会 Lv5 解锁第 4 槽，Lv10 解锁第 5 槽。
- 普通符石占 1 槽，特殊/传奇符石可能占 2 槽。

### 7.2.3 切换规则

符石可在裂缝内替换，返回城镇后保留在符石背包中。

## 7.3 符石获取

### 7.3.1 获取来源

- 普通怪
- 精英怪
- 宝箱
- Boss 奖励

### 7.3.2 掉落表现

符石与装备一样采用地面掉落，流程为：

1. 怪物死亡
2. 符石掉落
3. 玩家查看
4. 获取

### 7.3.3 处理方式

- 符石获取后直接进入符石背包。
- 低品质符石可在符石背包出售获得金币。

## 7.4 符石类型

符石按玩法方向分类：

| 类型 | 效果方向 | 适合武器类型 |
|---|---|---|
| 输出类 | 攻击提升、暴击、暴击伤害 | 单手剑、大剑、长柄武器、弓箭 |
| 防御类 | 生命、防御、减伤 | 盾 |
| 回复类 | 吸血、生命恢复 | 单手剑、盾 |
| 元素类 | 火焰伤害、冰冻效果、雷电效果 | 单手杖 |
| 特殊类 | 位移、控制、召唤 | 视具体设计而定 |

## 7.5 数值参数

### 7.5.1 属性随机范围

同类型符石存在随机数值。例如吸血符石：

| 品质 | 吸血数值 |
|---|---|
| 普通 | 3% |
| 优秀 | 5% |
| 稀有 | 7% |
| 传奇 | 9% |

### 7.5.2 符石槽位解锁

| 公会等级 | 符石槽位数量 |
|---|---|
| 默认 | 3 |
| Lv5 | 4 |
| Lv10 | 5 |

### 7.5.3 章节掉落倾向

不同章节拥有不同掉落倾向，帮助玩家产生刷取目标：

| 章节 | 主题 | 掉落倾向 |
|---|---|---|
| 第一章 | 森林层 | 防御类、生命类符石 |
| 第二章 | 墓园层 | 输出类、暴击类符石 |
| 第三章 | 雨林层 | 元素类符石 |
| 第四章 | 海岛层 | 回复类、减伤类符石 |
| 第五章 | 草原层 | 控制类、攻速类符石 |
| 第六章 | 洞穴层 | 稀有输出类、元素类符石 |
| 第七章 | 熔岩层 | 传奇符石、特殊类符石 |
| 第八章 | 雪原层 | 全类型高级符石 |

## 7.6 与其他系统关系

| 系统 | 关系 |
|---|---|
| 武器系统 | 符石绑定武器类型，强化某种武器玩法 |
| 装备系统 | 装备提供基础，符石提供方向 |
| 天赋系统 | 天赋决定角色成长方向，符石改变战斗机制 |
| 地图系统 | 章节决定符石掉落方向 |
| 经济系统 | 低品质符石可出售获得金币 |

## 7.7 设计原则

- 符石绑定武器类型，不绑定具体武器。
- 符石不能全武器通用，否则会导致武器差异消失。
- 符石属性存在随机范围，提供重复刷取价值。
- 符石不可强化，价值来自随机属性与 Build 组合。
- 符石进入符石背包并全部保留，作为长期收藏目标。

## 7.8 程序实现要点

- 符石数据结构：

```ts
interface RuneItem {
  uid: string;
  configId: string;
  quality: Quality;
  value: number; // 具体数值
  slotCost: number;
  boundWeaponType: WeaponType;
}
```

- 符石背包独立存储所有已获取符石，以 `Map<WeaponType, RuneItem[]>` 保存当前各武器类型的已装备符石。
- 出售低品质符石时直接换算为金币并销毁对象，金币进入资源条。

## 7.9 美术实现要点

- 符石图标尺寸 80 × 80 px，带元素主题色：火红、冰蓝、雷紫、自然绿、奥术金。
- 切图命名：`icon_rune_{type}_{quality}_{id}.png`。
- 符石装备到槽位时播放吸附光效 `fx_rune_equip.png`，8 帧。

# 8. 天赋系统

## 8.1 系统定位

天赋属于角色界面下的长期成长系统，用于强化角色长期成长。天赋不限制武器使用，但决定武器能否发挥完整潜力，并解锁/强化武器技能。

核心设计理念：

- 武器决定基础玩法。
- 天赋决定成长方向。
- 符石改变战斗机制。

## 8.2 天赋结构

### 8.2.1 基础属性方向

天赋从角色基础属性展开，初始主要属性包括：

| 属性 | 影响 | 适合玩法 |
|---|---|---|
| 力量 | 近战攻击、重武器伤害、破甲能力 | 大剑、长柄武器、高爆发玩法 |
| 敏捷 | 攻击速度、暴击、闪避 | 单手剑、弓箭、高速攻击 |
| 体魄 | 生命、防御、抗性 | 盾、防御玩法、坦克路线 |
| 智慧 | 法术伤害、元素效果、技能强化 | 单手杖、元素玩法、魔武结合 |

### 8.2.2 天赋树结构

天赋树采用“少量基础树、大量分支”的结构：

- 核心成长：力量、敏捷、体魄、智慧。
- 中期展开：武器专精与武器技能（单手剑、大剑、长柄武器、单手杖、弓箭、盾）。
- 后期展开：跨属性高级天赋与组合技能（例如力量 + 敏捷 = 战斗大师，智慧 + 敏捷 = 魔武刺客，力量 + 体魄 = 守护战士；单手剑+盾 = 钢铁壁垒，单手剑+单手杖 = 魔剑士）。

## 8.3 天赋解锁与成长

### 8.3.1 解锁规则

- 天赋不是一开始全部开放，随着章节推进逐渐开放新的天赋区域。
- 高级能力不能直接获得，需要多个方向培养。

### 8.3.2 成长阶段

| 阶段 | 开放内容 | 目标 |
|---|---|---|
| 前期 | 基础属性成长（力量、生命、攻击提升）与基础武器技能解锁 | 快速体验所有武器 |
| 中期 | 武器专精（单手剑、大剑、长柄武器、单手杖、弓箭、盾）与技能强化 | 确定流派 |
| 后期 | 跨属性高级天赋与单手组合技能 | 形成独特 Build |

### 8.3.3 跨天赋前置示例

| 专精/技能 | 前置需求 | 效果 |
|---|---|---|
| 单手剑专精 | 单手武器基础 + 敏捷 | 攻速提升、连击增加、解锁单手剑主动技能 |
| 大剑专精 | 力量 + 体魄 | 高伤害、大范围、霸体、解锁大剑主动技能 |
| 长柄武器专精 | 敏捷 + 体魄 | 突刺范围提升、控制效果、解锁长柄主动技能 |
| 单手杖专精 | 智慧 | 元素伤害提升、技能强化、解锁单手杖主动技能 |
| 弓箭专精 | 敏捷 | 射程/攻速提升、解锁弓箭主动技能 |
| 盾专精 | 体魄 | 格挡/减伤、解锁盾击/防御主动技能 |
| 魔武融合 | 单手武器 + 智慧 | 单手剑/单手杖攻击附带元素能力 |
| 暴击大师 | 敏捷 + 攻击强化 + 暴击节点 | 暴击率与暴击伤害大幅提升 |

## 8.4 数值参数

### 8.4.1 天赋与武器关系

- 没有对应天赋：可以使用武器，但只能发挥基础效果，无法释放该武器类型的主动技能。
- 拥有对应天赋：解锁该武器类型的主动技能，并可强化技能效果、缩短冷却、附加机制。

例如：玩家装备单手剑，没有单手剑专精时只能进行普通斩击；拥有单手剑专精后解锁主动技能“迅捷连斩”，并可通过后续天赋提升伤害、增加攻击次数、附加流血效果。

### 8.4.2 天赋对属性的影响

天赋可影响以下属性：

- 生命 HP
- 攻击力 ATK
- 防御力 DEF
- 攻击速度
- 暴击率
- 暴击伤害
- 伤害加成
- 最终减伤
- 元素抗性

### 8.4.3 天赋对掉落的影响

部分天赋专门提升裂缝掉落品质，与难度系数共同决定最终掉落：

| 天赋名称 | 类型 | 影响范围 | 数值示例 |
|---|---|---|---|
| 宝藏嗅觉 | 全局 | 稀有及以上权重 +10% | 困难稀有 20 → 22，传奇 2 → 2.2 |
| 精英猎手 | 精英/Boss | 传奇权重 +15% | 困难传奇 2 → 2.3 |
| 幸运儿 | 全局 | 非普通权重 +5% | 困难优秀 38 → 39.9，稀有 20 → 21，传奇 2 → 2.1 |
| Boss 猎人 | Boss 宝箱 | 品质额外 +1 概率 +20% | 稀有→传奇等概率提升 |

掉落权重计算示例（困难难度 + 宝藏嗅觉 + 精英猎手，击败精英怪）：

```
普通：40
优秀：38 × 1.10 = 41.8
稀有：20 × 1.10 = 22
传奇：2 × 1.10 × 1.15 = 2.53
```

Boss 宝箱在上述结果基础上再执行一次品质 +1 判定。

### 8.4.4 武器技能解锁与强化

- 每种武器类型在天赋树中拥有独立的“武器技能”节点，学习后解锁该武器类型的主动技能。
- 单手武器组合时，默认使用主手武器类型的主动技能；学习组合天赋（如“剑盾壁垒”）后，可解锁组合专属技能。
- 升级武器技能天赋可：降低冷却时间、提升技能伤害/治疗/防御效果、增加附加效果（如击退、元素附魔、连击段数）。
- 武器技能在战斗中通过点击角色头像释放，冷却与效果由天赋等级决定。

## 8.5 与其他系统关系

| 系统 | 关系 |
|---|---|
| 武器系统 | 天赋强化武器玩法、解锁并强化武器技能，不限制武器使用 |
| 符石系统 | 天赋决定成长方向，符石改变战斗机制 |
| 装备系统 | 装备词条补充天赋与武器形成的属性方向 |
| 战斗系统 | 天赋提供的被动能力在自动战斗中生效 |
| 掉落系统 | 部分天赋直接提升高品质掉落概率 |

## 8.6 设计原则

- 不存在固定职业，玩家通过武器组合、属性成长、天赋方向形成职业玩法。
- 天赋不限制武器使用，但强化特定武器玩法并解锁/强化对应武器技能。
- 高级专精需要属性前置，鼓励多方向培养。
- 天赋树采用少入口、多分支、多关联的结构。
- 前期快速体验，中期确定方向，后期形成 Build。

## 8.7 程序实现要点

- 天赋树使用静态配置表：

```ts
interface TalentConfig {
  id: string;
  name: string;
  maxLevel: number;
  requireIds: string[];
  requireAttr?: { str?: number; agi?: number; vit?: number; int?: number };
  effects: TalentEffect[];
}
```

- 天赋效果以 `Modifier` 列表作用于战斗属性计算，支持加法与乘法。
- 掉落加成天赋在 `DropService` 中读取玩家当前激活天赋，计算最终权重。

## 8.8 美术实现要点

- 天赋树节点图标 96 × 96 px，连线 8 px 宽度像素线。
- 已解锁节点高亮，未解锁节点灰色，可升级节点播放呼吸边框动画。
- 切图命名：`icon_talent_{branch}_{id}.png`，连线 `talent_line_active.png` / `talent_line_inactive.png`。

# 9. 佣兵系统

## 9.1 系统定位

佣兵系统是酒馆下的辅助系统，用于补充玩家战斗能力、提供剧情内容与互动事件。佣兵不是永久伙伴或可培养角色，而是玩家根据当前冒险需求与信任关系临时雇佣的战斗辅助单位。

### 9.1.1 佣兵设计目标

玩家进入不同章节、使用不同武器、形成不同 Build 时，需要考虑“我现在缺什么”，然后选择对应佣兵。同时通过信任值推进个人故事，解锁特殊事件。

### 9.1.2 系统归属

佣兵系统属于酒馆，是酒馆的核心功能之一。

## 9.2 酒馆看板娘与佣兵入口

- 酒馆拥有自己的看板娘 NPC，负责接待、传闻与支线故事引导。
- 看板娘提供佣兵招募入口、信任值总览与今日传闻。
- 点击看板娘可查看酒馆功能菜单：佣兵、支线故事、传闻、神秘商人、随机事件。

## 9.3 佣兵武器类型

佣兵按所持武器划分为 5 种武器类型，每种类型对应明确战术定位、基础属性倾向与雇佣消耗区间。武器类型决定佣兵的攻击距离、输出节奏与对玩家 Build 的补充方向。攻击距离直接影响佣兵 AI 的站位：近战佣兵贴近敌人，远程佣兵保持安全距离，辅助/治疗佣兵以玩家为中心在中距离活动。

| 武器类型 | 定位 | 基础属性倾向 | 攻击距离 | 雇佣消耗区间（金币） | 适合玩家 Build |
|---|---|---|---|---|---|
| 双刀 | 近战高速输出 | 高攻速、中攻击、低防御 | 96 px | 400–12000 | 盾、长柄、缺乏近战输出的 Build |
| 刀盾 | 近战防御/坦克 | 高生命、高防御、低攻速 | 64 px（盾击） | 500–10000 | 弓箭、单手杖、脆皮 Build |
| 法杖 | 魔法辅助/治疗 | 低攻击、中生命、技能效果 | 120 px（治疗/元素弹道） | 600–15000 | 双刀、弓箭、需要续航的 Build |
| 弓箭 | 远程物理输出 | 中攻击、高攻速、低防御 | 180 px | 400–13000 | 近战、缺乏远程输出的 Build |
| 长柄 | 中距离控制 | 中攻击、中生命、控制技能 | 144 px | 500–11000 | 需要控场、聚怪的 Build |

雇佣消耗区间按品质与公会等级浮动：普通品质取下限约 30%，优秀品质约 60%，稀有品质约 100%，传奇品质可超出区间上限。

## 9.4 佣兵雇佣与信任值

### 9.4.1 雇佣流程

1. 进入酒馆
2. 查看可雇佣佣兵
3. 查看佣兵属性、信任值与个人故事解锁进度
4. 支付金币
5. 佣兵加入队伍
6. 显示在队伍 UI
7. 进入裂缝

### 9.4.2 信任值

- 佣兵取消属性培养，改为信任值成长。
- 信任值通过多次雇佣、完成佣兵个人事件、赠送礼物提升。
- 信任等级提升后解锁：个人故事章节、酒馆互动事件、特殊战斗事件、专属台词。
- 信任值不重置，跨冒险保留。

### 9.4.3 个人故事与互动事件

- 每名佣兵拥有独立的个人故事线，分多个章节。
- 故事线在酒馆中通过对话或简短剧情演出呈现。
- 互动事件：在酒馆点击佣兵触发随机对话、礼物请求或小游戏。
- 特殊事件：信任值达到阈值后，在裂缝中可能触发佣兵专属援助事件。

### 9.4.4 雇佣消耗

- 佣兵需要消耗金币雇佣。
- 不同品质佣兵价格不同。
- 佣兵品质由公会等级与酒馆等级共同决定。

### 9.4.5 取消规则

- 玩家可以取消已雇佣佣兵。
- 取消后金币不退还。
- 设计目的：避免玩家反复试错、无限切换佣兵。

### 9.4.6 生命周期

佣兵只存在当前一次冒险。流程为：

1. 酒馆雇佣
2. 进入裂缝
3. 参与战斗
4. 完成裂缝或死亡
5. 佣兵离队

## 9.5 战斗规则

- 佣兵进入裂缝后自动跟随玩家。
- 佣兵自动攻击，玩家不直接控制其移动与普通攻击。
- 佣兵主动技能由玩家点击佣兵头像/技能按钮释放，冷却与效果由佣兵配置决定。
- 佣兵无升级、无属性培养、无装备。

## 9.6 数值参数

### 9.6.0 佣兵强度曲线

佣兵强度相对玩家呈衰减曲线，具体系数见 3.12.3：

| 阶段 | 章节范围 | 佣兵强度系数 K_merc | 说明 |

| 前期 | 1–3 章 | 1.20 | 佣兵明显强于玩家，帮助新手建立 Build |

佣兵基础 DEF = 玩家同章节期望 DEF × K_merc(n) × 武器类型防御修正

| 系统 | 关系 |

| 武器系统 | 不同武器类型需要不同佣兵补充短板 |

## 9.8 设计原则

- 佣兵不是永久伙伴，每次冒险前重新选择。
- 佣兵取消属性培养，通过信任值、剧情解锁与特殊事件提供长期目标。
- 佣兵属于酒馆，符合世界观中“酒馆是佣兵聚集地点”的设定。
- 雇佣消耗金币且取消不退款，让玩家招募前认真考虑。
- 佣兵自动战斗，不增加玩家操作负担。
- 佣兵的作用是服务当前 Build，而非替代玩家角色。

## 9.9 程序实现要点

- 佣兵配置：

```ts
interface MercenaryConfig {
  id: string;
  weaponType: MercenaryWeaponType; // 双刀/刀盾/法杖/弓箭/长柄
  type: MercenaryType;             // 保留输出/防御/辅助/控制定位标签
  quality: Quality;
  baseStats: StatMap;
  aiType: string;
  skillId?: string;
  hireCost: number;
}

interface MercenaryTrust {
  mercId: string;
  trustValue: number;
  trustLevel: number;
  unlockedStoryIds: string[];
  specialEventTriggered: boolean;
}
```

- 佣兵 AI 使用与敌人共享的 `BattleUnitAI`，通过 `faction = Player` 区分阵营。
- 雇佣时扣除金币并写入当前裂缝上下文；死亡/撤离后佣兵不保留。
- 信任值写入 `PlayerData.mercenaryTrust`，长期保留。
- 个人故事与互动事件由 `TavernDialogueService` 根据 trust level 驱动。
- 佣兵技能按钮与玩家技能按钮共用 `SkillButton` 数据结构，通过 `ownerId` 区分；`SkillUIManager` 负责在战斗 HUD 中按雇佣佣兵数量动态生成头像+技能按钮。

## 9.11 特殊佣兵：老盾（新手引导佣兵）

### 9.11.1 角色定位

- **名称**：老盾
- **武器类型**：刀盾
- **角色定位**：近战坦克 / 新手之友
- **外观**：中年壮汉，手持破旧刀盾，盔甲上有明显修补痕迹。
- **性格**：话不多、讲义气、喜欢喝酒、对新人意外地有耐心。

### 9.11.2 解锁方式

- 玩家在新手引导第一章中，使用「治愈之泉」救治受伤的老盾后，老盾正式解锁。
- 解锁后，老盾会永久出现在酒馆的佣兵招募列表中，作为玩家可雇佣的第一个佣兵。
- 老盾的信任值从 1 级开始（因新手引导中已被救过一次，初始信任值不为 0）。

### 9.11.3 战斗能力

| 属性 | 数值特点 |
|---|---|
| 生命 | 高于普通刀盾佣兵 10% |
| 攻击 | 低于普通刀盾佣兵 10% |
| 防御 | 与普通刀盾佣兵持平 |
| 攻速 | 较慢 |

**主动技能：坚守阵线**

- 效果：老盾举起盾牌，嘲讽周围敌人 3 秒，期间自身防御提升 50%。
- 冷却：20 秒
- 自动释放逻辑：玩家或老盾自身生命低于 60%，且周围有 3 只以上敌人时自动释放；玩家也可手动点击老盾头像释放。

### 9.11.4 雇佣消耗

- 老盾作为新手友好佣兵，雇佣消耗显著低于同品质佣兵。
- 首次雇佣免费（新手引导中已经组队一次，视为试用）。
- 后续雇佣消耗：金币 200（普通品质基准价的 50%）。

### 9.11.5 信任值与个人故事

老盾拥有独立的个人故事线，通过多次雇佣和完成个人事件提升信任值。

**信任等级 1 —— 欠债的人**
- 解锁条件：新手引导中救下老盾。
- 酒馆对话：
  > “你那瓶药水不便宜吧？改天请你喝酒。”

**信任等级 2 —— 老佣兵**
- 解锁条件：累计雇佣老盾 3 次。
- 酒馆对话：
  > “我带了二十年新人，你是我见过第一个敢用治疗药水救佣兵的。”

**信任等级 3 —— 裂缝里的规矩**
- 解锁条件：累计雇佣老盾 5 次，或完成老盾个人事件「护送任务」。
- 特殊事件：在裂缝中，当玩家生命低于 30% 时，老盾有概率触发「舍身掩护」，自动挡在玩家身前吸收一次致命伤害。

**信任等级 4 —— 酒馆的约定**
- 解锁条件：累计雇佣老盾 10 次。
- 酒馆对话：
  > “等这趟活干完，我请你喝灰港最好的麦酒。说定了。”

### 9.11.6 设计目的

- 让新手引导中的救佣兵事件有长期价值，老盾成为玩家早期最稳定的队友。
- 刀盾坦克定位能弥补新人玩家生存不足的痛点，降低前期失败率。
- 通过信任值和低成本雇佣，培养玩家使用佣兵系统的习惯。
- 老盾的存在不影响后期佣兵多样性，随着公会等级提升，玩家会接触到更多类型和品质的佣兵。

### 9.11.7 程序实现要点

- 老盾的解锁状态写入 `PlayerData.tutorialFlags.rescuedOldShield = true`。
- 解锁后，`TavernMercenaryService` 将老盾加入可招募池，并标记为 `isUnlocked = true`。
- 老盾首次雇佣免费通过 `hireCost = 0` 且 `firstHireFree = true` 实现。
- 老盾的「舍身掩护」特殊事件通过 `MercenarySpecialEventTrigger` 监听玩家生命值触发。

# 10. 地图与裂缝系统

## 10.1 系统定位

地图与裂缝系统是《像素冒险》的核心玩法承载系统，负责提供冒险流程、随机探索、风险选择、资源分配与章节推进。玩家通过进入裂缝（Dungeon）完成一次独立冒险，在有限路线中做出资源决策，最终挑战章节 Boss，验证当前 Build 的完整度。

裂缝分为主线裂缝与活动裂缝两类：

- **主线裂缝（Main Rift）**：以章节为单位的固定裂缝序列，承载长期剧情推进与核心成长。
- **活动裂缝**：包含异境、悬赏、深渊、限时活动（详见第 15 章）。

## 10.2 核心规则

### 10.2.1 章节结构

一次完整冒险由连续章节组成，结构如下：

- **第一章**：每次冒险固定出现，作为玩家起点，用于熟悉当前 Build、获取初始资源。
- **第二章起**：从对应阶段章节池中随机抽取，未解锁章节不会进入池子。
- **最终章节**：固定为 Boss 章节，击败后进入结算。

每个章节内部采用节点式随机路线，包含入口、若干节点与 Boss 节点。

### 10.2.2 节点类型

| 节点类型 | 说明 | 主要奖励 |
|---|---|---|
| 普通战斗节点 | 基础推进节点，敌人配置标准 | 金币、装备、基础资源 |
| 精英节点 | 高难度战斗，敌人拥有强化属性或特殊能力 | 更高品质装备、符石概率提升 |
| 宝箱节点 | 奖励节点，无战斗 | 装备、符石、金币 |
| 商店节点 | 资源交换节点 | 装备、道具、特殊资源 |
| 事件节点 | 随机事件，含风险与选择 | 可能获得奖励或承担风险 |
| Boss 节点 | 章节终点，击败后触发奖励阶段 | 高品质装备、稀有符石、特殊奖励 |

### 10.2.3 路线选择

每个章节内部不采用完全线性或完全开放地图，而是节点式路线。玩家每完成一个节点，在有限分支中选择下一节点。

路线设计遵循风险收益对等原则：

- 安全路线：资源少，风险低。
- 危险路线：资源多，风险高。

不同 Build 适合不同路线。例如低血量高输出 Build 不适合连续精英战，而高防御 Build 可以选择高风险路线。

### 10.2.4 章节特色与敌人组合模板

不同章节拥有不同敌人类型、地图环境、奖励倾向与装备掉落倾向，服务于装备、天赋、符石成长。例如：

- 第一章：偏向掉落防御与生命属性装备，帮助玩家建立基础生存能力。
- 第二章：偏向掉落攻击与暴击属性装备，支持流派形成。
- 第三章及以后：开始出现高级 Build 资源，如元素符石、稀有装备、高品质套装。

#### 章节敌人组合模板

每章敌人池上限为 12 种，固定模板如下：

```
前 8 种：普通小怪 archetypes
中 2 种：精英变体（由前 8 种普通 archetype 叠加精英词条生成）
后 2 种：章节 Boss + 精英 Boss
```

| 位置 | 数量 | 类型 | 作用 |
|---|---|---|---|
| 前 8 种 | 8 | 普通小怪 archetypes | 维持战斗节奏、资源产出、机制教学 |
| 中间 2 种 | 2 | 精英变体 | 测试 Build 完整度，掉落高品质装备 |
| 最后 2 种 | 2 | 章节 Boss + 精英 Boss | 章节 climax，验证构筑 |

设计约束：

- 同一章节内普通 archetypes 不得少于 4 种，避免战斗单调。
- 精英变体必须选自本章普通 archetype，保持主题一致性。
- 章节 Boss 与精英 Boss 机制需与前 8 种 archetypes 形成呼应（例如沼泽章 Boss 召唤毒蛙与治疗藤蔓）。
- 后续章节可替换 1–2 个普通 archetype 为新的环境专属 archetype，逐步扩展敌人库。

## 10.3 冒险流程

一次标准冒险流程如下：

1. 从冒险者大厅进入“冒险”模块。
2. 选择主线章节（含难度：普通 / 困难 / 地狱）。
3. 进入战斗准备：选择武器、配置符石、雇佣佣兵。
4. 进入章节，探索节点式路线，完成战斗、精英、宝箱、商店、事件节点。
5. 在路线分支中根据当前 Build 与血量选择下一节点。
6. 击败章节 Boss，进入 Boss 奖励整理阶段。
7. 通过传送门撤离，进入战斗统计界面。
8. 选择返回城镇或继续下一章。

**注意**：删除“关卡选择”层级，流程统一为“冒险 → 选择章节 → 战斗准备 → 战斗 → 结算”。

## 10.4 数值与参数

### 10.4.1 难度缩放公式

裂缝敌人属性采用动态难度缩放：

```
敌人属性 = 基础值 × (1 + 章节系数) × (1 + 公会等级系数) × 难度系数 × (1 + 连续深度系数)
```

| 系数 | 公式 / 数值 |
|---|---|---|
| 章节系数 | 第 n 章：0.15 × (n − 1) |
| 公会等级系数 | 0.02 × 公会等级 |
| 难度系数 | 普通 1.0 / 困难 1.4 / 地狱 2.0 |
| 连续深度系数 | 0.10 × 当前已通关章节数 |

说明：
- 连续深度系数在一次冒险中累计，第一章通过后进入第二章时系数为 0.10。
- 玩家可主动选择继续深入或撤离；撤离后再次进入冒险，连续深度系数从 0 重新计算。
- 该系数同样适用于异境、深渊等连续挑战玩法中的多层/多章推进。

难度提升不仅影响敌人生命与攻击，还影响精英怪比例、敌人组合与奖励品质。

### 10.4.2 精英比例与模式解锁

| 难度 | 精英怪比例 | 解锁条件 |
|---|---|---|
| 普通 | 10% | 默认开启 |
| 困难 | 20% | 通关主线第 5 章 |
| 地狱 | 30% | 困难模式通关第 10 章 |

### 10.4.3 掉落参数

掉落由难度基础权重与天赋加成共同决定：

| 难度 | 普通 | 优秀 | 稀有 | 传奇 |
|---|---|---|---|---|
| 普通 | 60 | 30 | 10 | 0 |
| 困难 | 40 | 38 | 20 | 2 |
| 地狱 | 25 | 38 | 30 | 7 |

Boss 宝箱额外提升一个品质等级。

天赋加成规则见 8.4.3。

### 10.4.4 章节规模

| 参数 | 数值 |
|---|---|
| 单章节节点数 | 约 10 个 |
| 每章体力消耗 | 10 点 |
| 单局冒险时长 | 约 10–30 分钟 |

## 10.5 与其他系统的关系

- **与符石系统**：章节决定符石掉落方向，节点奖励提供符石获取来源。
- **与装备系统**：地图节点是装备的主要来源，精英与 Boss 节点提升掉落品质。
- **与强化 / 附魔系统**：地图内提供强化房与附魔房节点，消耗强化材料与附魔石。
- **与佣兵系统**：不同章节对佣兵类型有不同需求，玩家需在酒馆根据章节特点配置佣兵。
- **与死亡撤离系统**：地图推进深度决定玩家已获收益与潜在未来收益，影响撤离决策。
- **与经济系统**：进入裂缝消耗门票与体力，裂缝产出金币、装备、符石等资源。

## 10.6 设计原则

- **选择重于移动**：地图核心不是移动探索，而是每次路线选择都是一次资源决策。
- **风险收益对等**：高风险节点提供更高品质奖励，玩家需根据当前状态判断。
- **不固定重复路线**：每次冒险从第一章开始，后续章节随机抽取，节点路线随机生成。
- **Boss 验证构筑**：Boss 不是单纯数值检测，而是对玩家整个 Build 机制、输出、生存的验证。
- **同一美术，参数区分**：普通、困难、地狱模式共享同一章节美术，通过战斗参数与标识区分难度。

- 章节配置：

# 11. 死亡与撤离系统

## 11.1 系统定位

死亡与撤离系统负责连接裂缝探索、装备获取、符石成长、难度挑战、经济与体力消耗。核心目标是在玩家失败后不造成惨重损失，同时让玩家认真对待每一次继续挑战的决策。

本系统不采用传统 Roguelike 的死亡惩罚：

- 不丢失已放入背包的装备。
- 不丢失已放入背包的武器。
- 不丢失已获得符石。
- 不丢失天赋石、强化材料与附魔石（未超出上限部分）。
- 死亡时本局获得的金币清零；撤离时金币全部保留。

死亡与撤离的本质惩罚是：消耗已支付的门票与体力，并失去后续探索机会以及未拾取的地面掉落。

## 11.2 核心规则

### 11.2.1 死亡规则

当角色 HP 归零时触发死亡（Defeat）。

**保留内容：**

- 战斗背包中的装备
- 战斗背包中的武器
- 背包中的天赋石
- 符石背包中已获得符石
- 强化材料与附魔石（未超出上限部分）
- 已获得特殊奖励

保留的装备、武器与天赋石在返回城镇后保留在玩家背包中，不会自动进入仓库。符石保留在符石背包中。强化材料与附魔石保留在资源条中。

**清零内容：**

- 本局裂缝中获得的金币全部清零（玩家已拥有的基础金币不受影响）

**消失内容：**

- 当前裂缝进度
- 未拾取的地面掉落（直接销毁，不进入处理流程）
- 当前战斗状态
- 临时增益效果
- 超出资源条上限的资源
- 连续深度系数清零

**消耗内容：**

- 裂缝门票
- 章节体力

**死亡结算流程：**

1. 角色 HP 归零。
2. 直接弹出死亡结算界面。
3. 未拾取装备直接销毁，不进入“拾取/替换/丢弃”处理流程。
4. 本局获得的金币从资源条中扣除。
5. 展示本局成果与带回背包。
6. 确认后返回城镇。

### 11.2.2 撤离规则

玩家在章节节点可主动结束冒险并带回收益（Extract）。

- 撤离时机：非战斗状态下，在已完成节点处可选择撤离。
- 撤离结果：保留当前战斗背包中的装备、武器与天赋石，资源条中的金币、强化材料与附魔石，以及符石背包中的符石，结束本次冒险；返回城镇后，背包中的装备、武器与天赋石保留在玩家背包中，不会自动进入仓库。
- 撤离消耗：已支付门票与已消耗体力不返还。
- 撤离时，场景中未拾取的装备先进入“拾取/替换/丢弃”处理界面；玩家可选择替换背包内旧装备、直接装备到对应部位，或丢弃；玩家需处理完所有未拾取装备后，才进入最终结算界面。
- 在处理界面中选择丢弃的装备直接转化为强化材料并进入顶部资源条。
- 撤离保留金币（含本局获得）。

**撤离结算流程：**

1. 玩家在节点点击撤离。
2. 弹出“拾取/替换/丢弃”处理界面，列出场景中所有未拾取装备。
3. 玩家逐个选择拾取入包、替换背包内装备、直接装备到对应部位，或丢弃。
4. 拾取/替换/直接装备时按背包规则进行；丢弃时直接转化为强化材料。
5. 所有未拾取装备处理完毕后，进入最终结算界面。
6. 结算界面展示本局成果，确认后返回城镇。

撤离设计目的：让玩家在血量危险或已获得高价值资源时拥有风险控制能力。

### 11.2.3 复活规则

死亡后提供一次广告复活机会（IAA 点位）：

- 复活后恢复 30% HP。
- 每局仅限一次。
- 复活后继承当前裂缝进度与战斗状态。

## 11.3 结算流程

游戏不设置传统失败界面，死亡与撤离最终都进入战斗统计界面，但前置处理不同：

**死亡结算：**

1. 角色 HP 归零。
2. 直接弹出死亡结算界面。
3. 未拾取装备直接销毁，不进入处理流程。
4. 本局获得的金币从资源条中扣除。
5. 展示本局成果与带回背包。
6. 确认后返回城镇。

**撤离结算：**

1. 玩家主动撤离。
2. 先进入“拾取/替换/丢弃”处理界面，处理场景中所有未拾取装备。
3. 丢弃的装备转化为强化材料进入资源条。
4. 处理完毕后进入最终战斗统计界面，展示本局成果。
5. 确认后返回城镇。

**统计界面统一内容：**

- 击杀数量、精英击杀、Boss 伤害、受到伤害、战斗时间。
- 获得金币、天赋石、符石、装备数量。
- 强化次数、附魔次数、丢弃转化材料数量。
- 展示最终战斗背包，仅查看不可操作。
- 战斗背包中的装备、武器与天赋石保留在玩家背包中，符石保留在符石背包中。
- 撤离时资源条资源全部保留；死亡时本局获得金币清零，强化材料与附魔石仍保留（未超上限部分）。
- Boss 通关后额外提供“返回城镇”或“进入下一章”选项。

## 11.4 数值与参数

| 项目 | 规则 |
|---|---|
| 死亡保留 | 背包内装备、武器、天赋石、强化材料、附魔石（未超上限）、符石、特殊奖励保留 |
| 死亡清零 | 本局获得的金币清零（已拥有的基础金币不受影响） |
| 死亡失去 | 当前进度、未拾取掉落（直接销毁）、战斗状态、临时增益、超上限资源、连续深度系数 |
| 死亡消耗 | 门票、体力 |
| 死亡结算 | 直接弹出结算界面，未拾取装备不进入处理流程，本局金币扣除 |
| 撤离保留 | 背包内装备/武器/天赋石、资源条资源（含金币）、符石保留；未拾取装备经处理后保留 |
| 撤离消耗 | 门票、体力 |
| 撤离结算 | 先处理未拾取装备（替换/直接装备/丢弃），再进入最终结算界面 |

| 复活后状态 | 继承当前进度与战斗状态 |

### 11.4.1 死亡压力来源

由于玩家不会掉落已有资源，死亡压力来自：

1. **门票成本**：死亡后若收益低于门票，本次探索亏损。
2. **体力成本**：每次进入章节消耗体力，死亡后体力不返还。
3. **失去未来收益**：已获稀有资源后若死亡，将失去后续更高价值奖励。

## 11.5 与其他系统的关系

- **与地图系统**：地图推进深度决定潜在收益与死亡风险。
- **与经济系统**：门票与体力是死亡的核心成本来源。
- **与装备系统**：背包中的装备与武器保留在玩家背包中，玩家可在城镇手动移入仓库。
- **与符石系统**：符石全部保留，死亡不会损失长期收集成果。
- **与商业化系统**：广告复活为 IAA 核心点位之一。

## 11.6 设计原则

- **不惩罚已有资源**：死亡不会清空已放入背包的装备/武器、符石与资源条资源，降低挫败感。
- **用成本控制节奏**：通过门票与体力消耗让玩家评估继续挑战的风险。
- **失败推动优化**：失败后通过战斗报告引导玩家调整符石、天赋、技能与装备，而非单纯提升等级。
- **统一结算体验**：取消传统失败界面，所有结束方式进入同一统计流程，强调“本局成果”而非“失败”。

## 11.7 程序实现要点

- 裂缝上下文数据结构：

```ts
interface DungeonRun {
  runId: string;
  chapterId: string;
  difficulty: Difficulty;
  backpack: Item[];
  resources: ResourceMap;
  acquiredRunes: RuneItem[];
  killedEnemies: number;
  mercenary?: MercenaryConfig;
}
```

- 死亡/撤离时调用 `SettlementService.run(dungeonRun)`：将 `backpack` 中的装备与武器合并到 `PlayerData.backpack`；撤离时将 `resources` 中的金币、天赋石、强化材料、附魔石合并到 `PlayerData.resourceBar`（受上限限制），死亡时本局获得的金币清零，仅合并天赋石、强化材料、附魔石；将 `acquiredRunes` 合并到 `PlayerData.runeBag`。仓库不自动写入，仅通过手动管理界面由玩家将物品从背包移入。
- 结算界面仅展示快照，不修改数据；点击确认后再执行写入，避免误操作丢失。
- 广告复活需在死亡判定与结算界面之间插入 `AdRevivePrompt`；观看成功后恢复 HP 并回到战斗状态机。
- 撤离与死亡结算状态机：

```ts
enum SettlementPhase {
  DeathImmediate,      // 死亡直接结算
  ExtractLootHandle,   // 撤离先处理未拾取装备
  FinalSettlement      // 最终统计界面
}
interface SettlementService {
  startDeath(run: DungeonRun): void;      // 进入 DeathImmediate
  startExtract(run: DungeonRun): void;    // 进入 ExtractLootHandle
  resolveLoot(action: LootHandleAction, targetUid?: string): void;
  finishLoot(): void;                     // 进入 FinalSettlement
  confirmSettlement(): void;              // 写入玩家数据并返回城镇
}
```
- 未拾取装备列表在 `ExtractLootHandle` 阶段从 `DungeonRun.unpickedLoot` 中读取；处理完毕后清空该列表。
- 丢弃装备时调用 `DropService.convertToMaterials(gear)`，按品质/星级计算材料数量并累加到 `run.resources.enhanceMaterials`。

## 11.8 美术实现要点

- 结算界面背景 `bg_settlement.png`，尺寸 720 × 1280。
- 统计数字使用 36 px 像素字体，标签 24 px。
- 死亡/撤离标题使用不同颜色：撤离绿色、死亡暗红色。
- 物品展示格子 96 × 96 px，品质边框叠加。

# 12. 资源经济系统

## 12.1 系统定位

资源经济系统负责控制游戏内各类资源的产出、消耗与循环，维持长期成长动力。通过控制资源保存规则、产出渠道与消耗出口，形成“挑战—获取—筛选—强化—再挑战”的闭环。

## 12.2 核心规则

### 12.2.1 资源分类

游戏内资源按保存规则分为两类：

| 分类 | 包含资源 | 保存规则 |
|---|---|---|
| 永久资源 | 天赋、符石、金币、天赋石、强化材料、附魔石 | 跨冒险永久保留；符石存入符石背包，天赋石占用背包格子；撤离时资源条资源全部保留；死亡时本局获得金币清零，强化材料与附魔石仍保留（未超上限） |
| 手动存储资源 | 装备、武器 | 拾取后进入战斗背包，死亡/撤离后保留在玩家背包；玩家可手动移入仓库 |
| 裂缝临时状态 | 当前 HP、临时 Buff、裂缝进度 | 仅当前裂缝有效，死亡/撤离后清空 |

### 12.2.2 资源获取

| 资源 | 主要来源 | 说明 |
|---|---|---|
| 金币 | 裂缝掉落、Boss 奖励、每日工资、金币裂缝、出售符石/装备 | 不占背包，进入顶部资源条 |
| 装备 | 普通战斗、精英、宝箱、Boss 掉落、裂缝商店、神秘商人 | 拾取后进入战斗背包，死亡/撤离后背包装备保留在玩家背包 |
| 武器 | 普通战斗、精英、宝箱、Boss 掉落、裂缝商店、神秘商人 | 拾取后进入战斗背包，死亡/撤离后背包武器保留在玩家背包 |
| 符石 | 裂缝掉落、裂缝商店、神秘商人、Boss 奖励 | 获取后进入符石背包，全部保留 |
| 天赋石 | 裂缝掉落、Boss 奖励、活动、委托 | 占用背包格子（1×1，可堆叠），死亡/撤离时背包内天赋石保留 |
| 强化材料 | 裂缝掉落、装备分解 | 不占背包，进入顶部资源条，显示数量并有最大值上限 |
| 附魔石 | 裂缝掉落、Boss 奖励、裂缝商店、神秘商人 | 不占背包，进入顶部资源条，显示数量并有最大值上限 |
| 体力 | 自然恢复、广告恢复、天赋 | 控制每日冒险次数 |

### 12.2.3 资源消耗

| 消耗项 | 说明 |
|---|---|
| 门票 | 进入裂缝消耗金币 |
| 佣兵雇佣 | 在酒馆支付金币雇佣佣兵 |
| 强化 | 消耗强化材料提升装备星级 |
| 附魔 | 消耗附魔石刷新装备词条 |
| 神秘商人购买 | 购买装备、符石、材料 |
| 神秘商人刷新 | 广告刷新获取新商品 |

## 12.3 经济闭环

```
挑战裂缝
  ↓
获得装备 / 武器 / 符石 / 金币 / 材料
  ↓
装备筛选（保留优秀装备，分解重复装备，将珍藏移入仓库）
  ↓
强化材料 → 强化装备
  ↓
符石替换 / 出售低品质符石
  ↓
调整武器 Build
  ↓
提升挑战能力
  ↓
提升公会等级
  ↓
解锁更多玩法
  ↓
挑战更高难度裂缝
```

## 12.4 数值与参数

### 12.4.1 货币参数

- **与裂缝系统**：裂缝是所有资源的主要产出场景。

- **与装备系统**：装备可分解为强化材料，形成内部循环。
- **与符石系统**：低品质符石可直接出售获得金币，是资源回收渠道之一。
- **与死亡撤离系统**：背包与资源栏规则决定死亡时的资源保留量。
- **与商业化系统**：IAA 为经济系统提供额外入口。

## 12.6 设计原则

- **资源分类管理**：资源条资源（金币、强化材料、附魔石）永久保留并受上限限制；天赋石占用背包格子并保留；符石进入符石背包；装备与武器保留在玩家背包，玩家手动决定哪些移入仓库。
- **背包与仓库分离**：战斗背包承担冒险中的取舍压力；仓库是手动管理的安全存储与收藏展示空间。
- **金币为核心流通货币**：门票、佣兵、神秘商人均消耗金币，形成稳定需求。
- **体力控制节奏**：通过体力上限与自然恢复控制每日总收益与游戏时长。
- **广告不制造长等待**：广告仅用于加速成长，不阻断核心玩法。

# 13. 冒险者大厅与城镇

## 13.1 系统定位

城镇“灰港”是玩家的安全区域，承担局外成长、队伍配置、资源管理与冒险准备功能。所有战斗玩法从城镇出发，冒险结束后返回城镇整理资源。

城镇的核心为冒险者大厅场景，底部固定导航提供五个一级模块的快速切换：公会、角色、冒险、酒馆、冒险日志。

## 13.2 核心规则

- 城镇内无战斗，所有功能交互均为非战斗交互。

## 13.3 冒险者大厅场景结构

# 14. 主线章节与敌人设计

## 14.1 敌人系统

### 定位

敌人系统是战斗反馈的核心来源，通过普通小怪、精英怪与 Boss 三类敌人，分别测试玩家的基础生存能力、Build 完整度与机制理解能力。普通小怪进一步细分为 10 种 archetypes（详见 3.11）。

### 规则

- 普通小怪：数量多、机制简单，但细分为脆皮输出、肉盾、控制、治疗、召唤、自爆、远程、飞行、刺客、元素施法者 10 种 archetypes。
- 精英怪：由普通 archetype 叠加 1–2 个精英词条生成，拥有特殊能力，如高防御、高速、回血、范围攻击等，用于测试 Build 完整度。
- 章节 Boss：具备多阶段机制与攻击压力，用于提供章节 climax 与高品质掉落。
- 每章敌人池最多 12 种：前 8 种普通 archetypes + 中间 2 种精英变体 + 最后 2 种 Boss/精英 Boss。
- 不同章节拥有不同敌人类型与环境主题，形成差异化体验。

### 流程

1. 角色自动探索裂缝并遭遇敌人。
2. 普通小怪以波次形式出现，自动战斗处理。
3. 精英节点触发高强度战斗，玩家可通过技能释放与 Build 调整应对。
4. Boss 节点进入阶段化战斗，击败后开启 Boss 宝箱。

### 数值/参数

| 敌人类型 | 定位 | 机制特征 | 掉落倾向 |
|---|---|---|---|
| 普通小怪 | 基础战斗单位 | 低生命、低攻击、简单 AI | 金币、普通装备 |
| 精英怪 | Build 检测点 | 特殊词条：高防/高速/回血/范围 | 更高品质装备、符石概率 |
| 章节 Boss | 章节终点挑战 | 多阶段、机制技能、高伤害 | Boss 宝箱（品质+1） |

敌人属性严格遵循主线章节难度缩放公式，精英怪比例随难度提升而增加。

### 与其他系统关系

- **武器类型**：不同武器对群体/单体、近战/远程敌人有不同效率。
- **符石与天赋**：提供抗性与针对性增益，影响对精英与 Boss 的应对能力。
- **装备词条**：元素抗性、最终减伤等属性直接作用于敌人伤害计算。
- **佣兵**：防御型佣兵可分担 Boss 压力，辅助型佣兵可提升续航。

### 设计原则

- 敌人不是单纯数值障碍，机制差异驱动玩家调整 Build。
- 精英怪应让玩家意识到“当前 Build 是否完整”，而非“攻击力是否足够”。
- Boss 战需控制 TTK，避免过长导致疲劳或过短失去阶段感。

### 设计原则

- 每章通过环境色调与敌人类型传递差异化体验。
- 奖励倾向服务于当前阶段主流 Build 需求，同时保留随机性。
- Boss 设计需与章节主题呼应，避免重复套用同一模型。

## 14.3 程序实现要点

- 敌人配置：

```ts
interface EnemyConfig {
  id: string;
  type: EnemyType;
  baseStats: StatMap;
  skills: string[];
  lootTable: string;
  eliteModifiers?: string[];
  bossPhases?: BossPhase[];
}
```

- 精英怪生成时从 `eliteModifiers` 池随机抽取 1–2 个词条。
- Boss 阶段切换以 HP 百分比触发，每阶段可更换技能与动画。

## 14.4 美术实现要点

- 普通敌人 Sprite 64 × 64 px；精英敌人 80 × 80 px 并带红色描边/发光；Boss 128 × 128 px。
- 敌人动画：待机 4 帧、移动 6 帧、攻击 6 帧、受击 2 帧、死亡 6 帧。
- 切图命名：`enemy_{chapter}_{id}_{action}_{frame}.png`。

# 15. 活动裂缝

## 15.1 异境

### 定位

异境是每日轮替的限时主题裂缝，用于产出特定资源或测试特定 Build，作为主线裂缝之外的日常内容补充。

### 规则

- 解锁条件：公会等级达到 10 级。
- 每日刷新一个或多个主题异境，主题不同则奖励倾向与敌人配置不同。
- 异境内部保留裂缝基本规则：节点、精英、Boss、宝箱、撤离与死亡结算。
- 部分异境会对武器类型或属性方向进行限制，以测试特定 Build 的极限。

### 流程

1. 玩家在“冒险”模块选择“异境”。
2. 选择目标异境，确认进入条件。
3. 完成异境挑战，结算奖励。
4. 奖励按资源规则分配：装备/武器/天赋石进入战斗背包，符石进入符石背包，金币/强化材料/附魔石进入资源条；低品质符石可在符石背包直接出售。

### 数值/参数

| 异境类型 | 主题示例 | 轮换规则 | 主要产出 | 特殊限制 |
|---|---|---|---|---|
| 资源异境 | 巨树异境、蒸汽异境 | 每日刷新 | 金币、强化材料、附魔石 | 无武器限制 |
| 武器专精试炼 | 单手剑/大剑/长柄武器/单手杖/弓箭/盾试炼 | 按武器类型轮替 | 对应武器类型符石、强化材料 | 仅可使用指定武器类型 |
| 世界 Boss 异境 | 梦魇异境、云上海岛 | 周期刷新 | 稀有符石、高级装备、特殊材料 | 高难挑战 |

异境不采用主线章节的固定门票梯度，具体体力/门票规则由运营配置，原则上作为高价值日常内容控制参与次数。

### 与其他系统关系

- **公会等级**：控制异境解锁与可出现的品质上限。
- **武器/符石系统**：武器专精试炼直接驱动玩家完善不同武器类型的符石配置。
- **神秘商人**：异境产出可补充强化材料与符石缺口。

### 设计原则

- 通过主题轮换保持每日新鲜感，避免玩家形成固定刷取路线。
- 限制型异境用于展示不同武器类型的 Build 可能性，而非强制玩家培养全部武器。
- 奖励设计需与主线掉落形成互补，避免替代主线成长价值。

## 15.2 悬赏

### 定位

悬赏是每日刷新的短周期挑战任务，玩家通过公告板或冒险入口接取，完成指定目标后领取奖励。

### 规则

- 解锁条件：公会等级达到 5 级。
- 每日刷新 3–5 个悬赏目标，目标包括击杀特定怪物、收集物品、完成章节等。
- 悬赏不消耗体力，但部分高价值悬赏有次数上限。
- 奖励包括金币、强化材料、声望与公会经验。

### 流程

1. 在冒险者大厅公告板或“冒险”模块查看今日悬赏。
2. 选择目标并确认接取。
3. 进入对应裂缝或完成指定行为。
4. 返回领取奖励。

### 数值/参数

| 悬赏类型 | 目标示例 | 奖励 |
|---|---|---|
| 普通悬赏 | 击杀 20 只哥布林 | 金币、公会经验 |
| 精英悬赏 | 击败 3 只精英怪 | 材料、声望 |
| 特殊悬赏 | 通关某章节不死亡 | 稀有符石、传奇碎片 |

### 与其他系统关系

- **公告板**：悬赏任务的主要发布入口。
- **裂缝系统**：悬赏目标驱动玩家重复挑战特定章节或节点。
- **经济系统**：悬赏提供稳定的金币与材料产出。

### 设计原则

- 悬赏目标应覆盖不同 Build 与章节，避免单一化。
- 奖励与难度匹配，低难度悬赏提供日常资源，高难度悬赏提供稀有奖励。
- 悬赏不应替代主线成长，而是补充日常活跃。

## 15.3 深渊

### 定位

深渊是无限层数挑战玩法，记录玩家最高层数，按月重置排行榜与奖励，为毕业玩家提供长期目标。

### 规则

- 解锁条件：公会等级达到 15 级。
- 玩家从第 1 层开始向上挑战，层数越高难度越高。
- 每 5 层进行一次奖励结算，层数越高奖励越丰厚。
- 进度保存：玩家退出后，下次可从已到达层数继续挑战。
- 每月 1 日重置排行榜与挑战进度，并根据上月最高层数发放结算奖励。

### 流程

1. 玩家在“冒险”模块选择深渊。
2. 进入当前已解锁的最高起始层。
3. 击败该层所有敌人后进入下一层。
4. 每 5 层触发一次奖励结算，玩家可选择继续或撤离。
5. 每月重置后，根据排行榜名次发放限定奖励。

### 数值/参数

| 项目 | 规则 |
|---|---|
| 解锁条件 | 公会 Lv.15 |
| 奖励结算 | 每 5 层结算一次 |
| 进度保存 | 退出后可从已到达层数继续 |
| 重置周期 | 每月 1 日重置排行榜与进度 |
| 排行榜维度 | 最高层数、通关时间 |

深渊难度在主线敌人属性公式基础上叠加“探索深度系数”，具体系数由数值运营根据版本平衡配置。

### 与其他系统关系

- **公会等级**：解锁深渊并影响基础难度系数。
- **天赋/武器/符石收藏**：局外成长是挑战更高层数的核心支撑。
- **排行榜**：提供社交竞争与月度目标。

### 设计原则

- 以参数化缩放替代无限制作新关卡，控制内容成本。
- 月度重置防止层数差距固化，给予新玩家追赶窗口。
- 奖励以荣誉性外观与稀有材料为主，避免直接出售战力。

## 15.4 限时活动

### 定位

限时活动是周期性或节日限定的大型裂缝与任务集合，用于引入版本新内容、提升短期活跃与补充限定奖励。

### 规则

- 活动通常持续 7–14 天，包含独立任务链、特殊章节或限定异境。
- 活动内容通过主界面“活动”快捷入口与酒馆公告板同时曝光。
- 活动奖励包括限定外观、称号、资源包与传奇武器碎片。

### 流程

1. 活动开启后，玩家通过公告或入口查看活动规则。
2. 完成活动任务或挑战活动裂缝，积累活动货币或积分。
3. 在活动商店中兑换限定奖励。
4. 活动结束后，未兑换货币按固定比例转换为金币。

### 数值/参数

| 项目 | 规则 |
|---|---|
| 活动周期 | 7–14 天，节日/版本/联动按需开启 |
| 入口 | 主界面“活动”悬浮按钮、酒馆公告板 |
| 奖励类型 | 外观、称号、资源、传奇武器碎片 |
| 货币处理 | 活动结束后按比例转换为金币 |

### 与其他系统关系

- **商业化**：活动常与 IAA 奖励翻倍、外观展示联动。
- **主线/异境**：活动裂缝复用现有章节结构与美术资源，降低开发成本。
- **冒险日志**：活动剧情与世界观可通过冒险日志归档。

### 设计原则

- 活动内容应服务于世界观与世界氛围，避免与主线叙事脱节。
- 奖励需具备稀缺性与展示性，但不应破坏经济平衡。
- 活动任务难度需覆盖不同公会等级的玩家。

## 15.5 程序实现要点

- 异境/悬赏/深渊/活动共用 `DungeonRun` 数据结构，通过 `mode` 字段区分。
- 异境与悬赏每日配置由服务端下发，本地缓存 1 天；深渊排行榜通过微信好友排行榜或开放数据域实现。
- 悬赏任务状态使用独立 `BountyTask` 结构，记录接取、进度与领取状态。
- 活动系统支持 `ActivityConfig` 配置，活动时间区间、任务、商店独立配置。

## 15.6 美术实现要点

- 异境入口图标 120 × 120 px，带倒计时标签。
- 悬赏任务卡片 600 × 144 px，带目标进度条。
- 深渊层数数字使用 48 px 像素字体，居中显示。
- 活动弹窗尺寸 600 × 800 px，圆角 16 px，标题 36 px。

# 16. 美术风格与视觉规范

## 16.1 美术风格定位

### 定位

《像素冒险》采用 2D 像素美术风格，呈现名为“埃索斯大陆”的破碎世界。美术服务于“轻剧情、重氛围”的叙事基调，通过环境叙事与 Boss 背景故事推进世界观。

### 规则

- 整体视觉为复古像素与现代光影结合的“精致像素”风格。
- 城镇“灰港”为安全区域，采用暖色调与稳定构图，传递归属感。
- 裂缝章节根据主题采用差异化色调：森林绿、矿洞灰、遗迹金、湿地紫等。
- 敌人、武器、装备、符石需具备清晰轮廓与可读性，确保自动战斗中信息传达准确。

### 流程

1. 根据章节主题与敌人类型确定主色调与场景元素。
2. 制作武器、装备、特效、UI 切图与动画；玩家形象、佣兵形象、怪物动画为已有资产，直接复用现有资产，无需额外制作。
3. 在战斗场景中进行可读性测试，调整对比度与特效强度。
4. 根据 UI/UX 需求输出图标、按钮与界面切片。

### 数值/参数

| 项目 | 规格 |
|---|---|
| 屏幕方向 | 竖版 |
| 设计分辨率 | 720 × 1280（适配 16:9 及以上全面屏） |
| 角色 Sprite | 64 × 64 像素 |
| Boss Sprite | 128 × 128 像素 |
| 普通敌人 Sprite | 64 × 64 像素 |
| 精英敌人 Sprite | 80 × 80 像素 |
| 地块尺寸 | 32 × 32 像素 |
| 帧率目标 | 30 FPS，关键动作 4–8 帧 |
| 色板限制 | 每场景主色板 32 色，全局辅助色板 16 色 |
| 特效粒子 | 8–16 帧循环，限制同屏粒子数 ≤ 64 |
| 字体 | 像素风格点阵字体，正文 20–28 px，标题 32–48 px |

### 与其他系统关系

- **UI/UX**：美术风格决定界面切片的 9-slice、按钮与图标的像素表现。
- **音效与音乐**：视觉主题直接影响场景 BGM 与音效氛围。
- **商业化**：外观皮肤需严格遵循美术规格，确保与基础资源风格统一。

### 设计原则

- 可读性优先：战斗信息必须在复杂特效中保持清晰。
- 一致性优先：同一场景内的色调、透视与像素密度保持一致。
- 复用优先：通过调色与元素组合生成新章节，控制美术成本。

## 16.2 安全区与适配规则

- 设计画布：720 × 1280 px。
- 安全内容区：顶部 ≥ 64 px（状态栏/刘海），底部 ≥ 68 px（Home 指示条），左右 ≥ 24 px（挖孔/圆角）。
- 实际可用内容区：约 672 × 1148 px。
- UI 布局采用锚点适配：顶部 HUD 锚定上边缘，底部导航锚定下边缘，中间内容可滚动。
- 背景图可延伸至全屏，但关键按钮/文字必须在安全区内。

- 主色板：每场景 32 色，包含底色 8 色、主体 16 色、强调 8 色。
- UI 辅助色板：全局 16 色，包含品质色 4 色（白/绿/蓝/黄）、按钮色 4 色、文字色 4 色、警告色 1 色。
- 特效色：按元素单独制定，保证对比度。
- 所有 Sprite 优先使用索引色，便于统一调色与压缩。

## 16.7 程序实现要点

- 纹理打包：使用 TexturePacker 或引擎图集，按场景/系统分组，单图集 ≤ 2048 × 2048。
- 远程资源：大图/音乐/活动资源放 CDN，启动时按需下载；本地缓存按 LRU 清理。
- 资源加载：首包仅包含前 3 章与核心 UI，后续章节与深渊资源通过分包或远程加载。

## 16.8 美术实现要点

- 所有美术资源按 2× 输出，运行时缩放 0.5，保证在高分辨率手机上清晰。
- 像素字体使用 BitmapFont，避免系统字体破坏风格。
- 特效贴图使用 PNG-8 或压缩纹理，控制单张 ≤ 256 × 256。
- 角色换装采用分层 Sprite：身体、武器、头盔、护甲，通过图层叠加减少资源量。

# 17. UI/UX 设计

## 17.1 信息架构

### 定位

UI 信息架构为所有系统提供稳定的入口归属，避免功能重复导航，确保玩家在竖版小游戏端能够快速完成“准备—冒险—成长”循环。

### 规则

- 底部固定导航五个一级模块，顺序固定为：**公会、角色、冒险、酒馆、冒险日志**。
- 全局快捷入口悬浮于主界面两侧：邮件、公告、活动、排行榜、福利、设置。
- 场景内交互仅承担当前模块功能，不重复承担跨模块跳转。

### 流程

1. 启动游戏后进入冒险者大厅主界面。
2. 玩家通过底部导航切换长期养成模块。
3. 通过“冒险”模块选择主线章节或活动裂缝（异境、悬赏、深渊、限时活动）。
4. 通过全局快捷入口处理邮件、公告、活动、排行榜与设置。

### 数值/参数

| 一级模块 | 核心功能 |
|---|---|
| 公会 | 冒险者大厅、咨询台小姐、公告板、执照大厅、武器库、公会档案 |
| 角色 | 属性、装备（武器/防具/饰品/装备详情）、技能、天赋、外观 |
| 冒险 | 主线（章节选择/进入冒险）、活动裂缝（异境/悬赏/深渊/限时活动） |
| 酒馆 | 佣兵、信任值/个人故事/互动事件、支线故事、酒馆传闻、神秘商人、随机事件 |
| 冒险日志 | 怪物、Boss、装备、道具、佣兵、世界设定、剧情、成就、探索统计 |

### 与其他系统关系

- **商业化**：活动、排行榜、福利等入口直接承载 IAA 曝光。
- **战斗系统**：战斗内 UI 取消虚拟摇杆与攻击按钮，突出自动战斗的决策属性。
- **结算系统**：所有冒险结束统一进入战斗统计界面，不设置传统失败界面。

### 设计原则

- 一级导航顺序一经确定不再轻易调整，保持玩家认知稳定。
- 高频功能（如进入裂缝、领取工资）控制在 2 步以内触达。
- 避免在场景内重复放置底部导航已存在的入口。

## 17.2 核心界面清单

### 定位

核心界面清单覆盖玩家从城镇准备到裂缝结算的全流程，确保每个系统都有明确的信息展示与交互边界。

### 规则

- 每个界面需明确：信息展示区域、操作区域、返回/关闭路径。
- 装备信息界面需提供当前装备与新装备的对比。
- 背包满时弹出装备信息界面，允许直接分解。
- 战斗统计界面只展示成果，不提供整理背包或更换装备等操作。

### 流程

玩家按以下界面路径完成一次完整冒险：

冒险者大厅主界面 → 冒险 → 章节选择 → 战斗准备 → 战斗界面 → 掉落拾取/装备判断 → Boss 奖励 → 战斗统计 → 返回冒险者大厅

角色装备流程：

角色 → 装备 → 选择已拥有装备 → 穿戴

### 与其他系统关系

- **佣兵系统**：酒馆与队伍 UI 共同完成佣兵的雇佣、查看与取消。

# 18. 音效与音乐

## 18.1 音效系统

### 定位

音效系统为自动战斗提供即时反馈，强化武器打击感、技能释放感与资源获取感，同时不干扰玩家的策略判断。

### 规则

- 音效分为：武器音效、技能音效、受击音效、环境音效、UI 音效。
- 同一武器类型的基础攻击音效保持一致，便于玩家建立听觉认知。
- 精英怪与 Boss 拥有独立的受击与技能预警音效。
- 掉落金币与装备拾取需有明显但短促的反馈音。

### 流程

1. 角色自动攻击触发对应武器音效。
2. 玩家点击角色头像释放技能时触发技能音效。
3. 敌人受击/死亡触发受击与死亡音效。
4. 拾取金币、装备、符石触发对应拾取音效。
5. 打开界面、点击按钮触发 UI 音效。

### 数值/参数

| 音效类型 | 格式 | 声道 | 采样率 | 备注 |
|---|---|---|---|---|
| 武器音效 | OGG / WAV | 单声道 | 44.1 kHz | 按武器类型分类 |
| 技能音效 | OGG / WAV | 单声道 | 44.1 kHz | 按技能效果分类 |
| 受击音效 | OGG / WAV | 单声道 | 44.1 kHz | 区分普通/精英/Boss |
| 环境音效 | OGG | 立体声 | 44.1 kHz | 循环播放，音量较低 |
| UI 音效 | OGG / WAV | 单声道 | 44.1 kHz | 短促，避免重复疲劳 |

### 与其他系统关系

- **武器系统**：不同武器类型对应不同攻击音效库。
- **技能系统**：技能音效与角色头像点击操作同步。
- **掉落系统**：拾取音效强化资源获得反馈。

### 设计原则

- 音效长度控制在 0.5 秒以内，避免自动战斗中产生听觉堆叠。
- 关键技能与 Boss 预警音效需具备辨识度。
- 提供总音量、音乐、音效独立调节开关。

## 18.2 音乐系统

### 定位

音乐系统负责营造场景氛围，区分城镇安全区域与裂缝探索区域，并在 Boss 战中提升紧张感。

### 规则

- 每个主要场景配置独立 BGM：城镇、裂缝探索、精英战斗、Boss 战、深渊、活动。
- BGM 采用无缝循环，切换场景时平滑过渡。
- Boss 战音乐需具备阶段变化，与 Boss 阶段机制同步。
- 广告播放时音乐自动静音，广告结束后恢复。

### 流程

1. 进入城镇播放城镇 BGM。
2. 进入裂缝后切换为裂缝探索 BGM。
3. 遭遇精英怪时叠加紧张层或切换精英战斗 BGM。
4. 进入 Boss 节点切换为 Boss 战 BGM，并随阶段推进变化。
5. 返回城镇或进入结算后恢复城镇音乐。

### 数值/参数

| 音乐类型 | 场景 | 格式 | 码率 | 循环方式 |
|---|---|---|---|---|
| 城镇 BGM | 灰港、冒险者大厅、酒馆 | OGG | 128 kbps | 无缝循环 |
| 裂缝探索 BGM | 主线/异境/活动普通节点 | OGG | 128 kbps | 无缝循环 |
| 精英战斗 BGM | 精英节点 | OGG | 128 kbps | 无缝循环 |
| Boss 战 BGM | 章节 Boss/世界 Boss | OGG | 160 kbps | 分阶段循环 |
| 深渊 BGM | 深渊高层 | OGG | 128 kbps | 随层数变化 |
| 活动 BGM | 节日/联动活动 | OGG | 128 kbps | 活动期间循环 |

### 与其他系统关系

- **美术风格**：音乐风格与像素奇幻世界观保持一致。
- **商业化**：广告播放期间音乐与音效需统一静音。
- **战斗系统**：Boss 战音乐阶段变化与 Boss 阶段机制绑定。

### 设计原则

- 音乐以氛围营造为主，不抢夺音效反馈空间。
- 同一裂缝内音乐切换需自然，避免突兀中断。
- 提供音乐开关与独立音量调节。

## 18.3 程序实现要点

- 音频文件使用 OGG 格式，单首 BGM ≤ 2 MB，音效 ≤ 100 KB。
- 使用音频对象池，避免频繁 `createInnerAudioContext`。
- 广告播放前调用 `AudioManager.muteAll()`，广告结束 `resumeAll()`。

## 18.4 美术实现要点

- 音效触发需与动画关键帧对齐，命中帧播放受击音效。
- 提供音效开关图标 `icon_sound_on.png` / `icon_sound_off.png`，尺寸 48 × 48 px。

# 19. 商业化设计

## 19.1 广告变现（IAA）

### 定位

广告变现定位为“加速成长”手段，不用于制造长等待或强制卡关，所有广告点位均围绕玩家的主动需求设计。

### 规则

- 体力恢复：观看广告恢复 30 体力，每日 5 次。
- 奖励翻倍：通关后金币奖励 ×2，每日 3 次。
- 失败复活：死亡后观看广告可复活一次并恢复 30% HP。
- 神秘商人刷新：每日免费刷新 1 次，观看广告额外刷新 3 次。

### 流程

1. 玩家在对应界面触发广告入口（体力不足、结算翻倍、死亡复活、神秘商人刷新）。
2. 系统展示激励视频广告。
3. 广告完整观看后，立即发放对应奖励。
4. 若广告未完整观看，则不发放奖励。

### 数值/参数

| 广告点位 | 奖励内容 | 每日次数 | 触发时机 |
|---|---|---|---|
| 体力恢复 | 30 体力 | 5 次 | 体力不足时 |
| 奖励翻倍 | 通关金币 ×2 | 3 次 | 主线/异境通关结算时 |
| 失败复活 | 复活并恢复 30% HP | 1 次 | 死亡结算前 |
| 神秘商人刷新 | 额外刷新神秘商人商品 | 3 次 | 酒馆神秘商人界面 |

### 与其他系统关系

- **体力系统**：体力恢复广告直接补充每日冒险次数。
- **经济系统**：奖励翻倍广告提升金币产出效率。
- **神秘商人**：刷新广告扩展玩家获取稀有商品的机会。
- **战斗系统**：失败复活广告提供一次额外挑战机会。

### 设计原则

- 所有广告均为激励视频，玩家主动选择观看。
- 广告奖励不应破坏核心经济循环，仅作为补充。
- 复活广告限制为 1 次，避免失败机制被完全绕过。

## 19.2 程序实现要点

- 微信小游戏激励视频 API：

```js
const rewardedVideoAd = wx.createRewardedVideoAd({ adUnitId: 'xxxx' });
rewardedVideoAd.show().catch(() => {
  rewardedVideoAd.load().then(() => rewardedVideoAd.show());
});
rewardedVideoAd.onClose(res => {
  if (res && res.isEnded) { grantReward(); }
});
```

- 广告实例按点位复用，避免重复创建。
- 广告加载失败时降级为“今日次数已达”或“网络异常，请稍后重试”。
- 记录每日广告次数到本地与服务端，防止篡改。

## 19.3 美术实现要点

- 广告入口按钮尺寸 160 × 64 px，带播放图标与奖励文案。
- 按钮文案示例：“看视频 +30 体力”、“金币 ×2”。
- 复活弹窗需明确提示“观看视频复活一次”，并提供放弃选项。

# 20. 微信小游戏技术限制与开发规范

## 20.1 包体与分包

| 帧率 | 30 FPS 默认，可选 60 FPS | 低性能设备自动降帧 |

## 20.3 登录与账号

- 使用 `wx.login` 获取 code，换取玩家 openid，作为账号唯一标识。
- 用户信息通过 `<button open-type="getUserInfo">` 获取，禁止强制授权。
- 首次登录时创建云端存档；本地存档优先，登录后比对时间戳合并。
- 离线状态下允许使用本地存档继续游戏，联网后自动同步。

## 20.4 分享

- 使用 `wx.showShareMenu` 开启转发，自定义分享标题与图片。
- 分享点：通关炫耀、获得传奇装备、深渊层数、活动邀请。
- 分享参数携带 `query`，用于统计与召回奖励。
- 避免诱导分享，遵守平台审核规范。

## 20.5 存档与网络

- 本地存档：`wx.setStorageSync('player_data_v1', data)`，关键字段加密或签名校验。
- 云存档：通过微信云开发 `database` 或 `callContainer` 存储，字段包含 `uid`、`data`、`timestamp`、`checksum`。
- 冲突解决：以时间戳最新的存档为准；若本地更新时间晚于云端且未联网，保留本地，联网后上传。
- 关键操作（广告奖励、排行榜、购买/兑换）必须服务端校验。

## 20.6 网络/离线逻辑

- 核心战斗、裂缝流程、背包整理完全支持离线。
- 广告、云存档、排行榜、活动配置、神秘商人每日刷新需要网络。
- 网络恢复时：
  1. 拉取云端存档比对。
  2. 拉取活动/神秘商人配置。
  3. 上报离线期间产生的可上报数据（如广告次数、成就进度）。
- 弱网环境下，广告加载超时 5 秒，提示玩家切换网络。

## 20.7 推荐技术栈

- 引擎：**Unity**（2D / URP / 微信小游戏适配）。
- 架构：纯客户端，无独立游戏服务器；登录、分享、广告、排行榜、云存档通过 Unity 微信小游戏 SDK 或 C# 调用 `wx` API。
- 语言：C#（运行时逻辑），Lua/JSON（配置表）。
- 状态管理：全局单例 `GameState` + `PlayerData`。
- 资源管理：Unity Addressable Assets System 分组加载 + 远程资源缓存。
- 数据持久化：本地 `wx.setStorageSync` 为主存档；关键数据可选同步至微信云存档/云开发 KV。
- 广告 SDK：微信激励视频 `wx.createRewardedVideoAd`。
- 排行榜：微信开放数据域 + 好友排行榜。
- 商业化：纯 IAA（激励视频），无 IAP。

## 20.8 性能与合规 checklist

- [ ] 主包代码 ≤ 4 MB，首包资源 ≤ 20 MB。
- [ ] 中低端设备战斗 30 FPS 稳定。
- [ ] 运行时内存峰值 < 200 MB。
- [ ] 所有广告点位使用激励视频，不强制观看。
- [ ] 分享功能不诱导、不欺骗。
- [ ] 存档本地 + 云端双保险，支持离线游玩。
- [ ] 用户授权仅使用必要 scope。
- [ ] 广告奖励、排行榜等关键操作服务端校验。

# 21. 开发、测试与附录

## 21.1 开发计划

### 定位

开发计划将设计文档中的系统按依赖关系与风险程度排序，分阶段交付可验证版本。

### 规则

- Pre-Alpha：验证核心战斗循环与自动战斗 AI。
- Alpha：完成城镇、冒险者大厅、主线前 5 章、装备/强化/附魔/符石基础循环。
- Beta：加入异境、深渊、商业化 IAA、排行榜与完整 UI/UX。
- Launch：内容调优、运营活动、性能优化。

### 流程

1. 完成原型验证后进入 Pre-Alpha。
2. Alpha 阶段重点验证 Build 多样性与战斗公式。
3. Beta 阶段接入广告、排行榜与服务器云存档。
4. Launch 阶段根据数据反馈持续迭代。

### 数值/参数

| 阶段 | 核心内容 | 里程碑 |
|---|---|---|
| Pre-Alpha | 自动战斗、武器攻击逻辑、敌人 AI | 核心循环可玩 |
| Alpha | 城镇、冒险者大厅、主线 1–5 章、装备/强化/附魔/符石 | 完成首次内部测试 |
| Beta | 异境、深渊、商业化 IAA、排行榜、完整 UI | 微信小游戏付费测试 |
| Launch | 运营活动、性能优化、分包优化 | 正式上线 |

### 与其他系统关系

- **测试要点**：每个阶段需配套对应测试计划。
- **商业化**：Beta 阶段必须完成 IAA 接入与合规测试。
- **美术/音效**：Alpha 阶段完成核心美术与音效资源，Beta 阶段补齐活动与深渊资源。

### 设计原则

- 先验证核心玩法，再扩展外围系统。
- 每个阶段都应有明确的可玩目标与验收标准。
- 商业化系统不得晚于 Beta 阶段接入，确保有足够时间调优。

## 21.2 测试要点

### 定位

测试要点覆盖玩法、数值、商业化与技术稳定性，确保设计规范中的数值与规则在落地后保持一致。

### 规则

- 战斗公式测试：验证减法伤害、暴击、攻速、最终伤害公式的正确性。
- 经济循环测试：验证门票、工资、掉落、分解、强化消耗的长期平衡。
- 商业化测试：验证广告奖励发放、每日次数限制、网络异常处理。
- 难度测试：验证不同公会等级与章节下的 TTK 与玩家通过率。
- 平台适配测试：验证 720 × 1280 分辨率、安全区、分包、内存、帧率。

### 流程

1. 单元测试：战斗公式、属性计算、掉落随机。
2. 集成测试：裂缝流程、结算流程、商业化流程。
3. 平衡测试：邀请目标玩家进行多轮试玩，收集 TTK 与经济反馈。
4. 回归测试：每次版本更新后验证核心数值未被破坏。

### 数值/参数

| 测试类别 | 测试要点 | 通过标准 |
|---|---|---|
| 战斗公式 | 伤害、暴击、攻速、最终减伤、元素抗性 | 与公式计算误差 ≤ 1% |
| TTK | 普通小怪、精英、Boss 的战斗时长 | 落在设计规范区间 |
| 经济循环 | 金币产出、门票、工资、强化消耗 | 7 日/30 日收支符合预期 |
| 掉落概率 | 普通/困难/地狱难度下各品质掉落 | 大样本概率与设计表一致 |
| 商业化 | 广告奖励、每日限制、网络异常 | 100% 正常发放与降级 |
| 难度缩放 | 章节系数、公会等级系数、难度系数 | 随章节推进体感难度递增 |
| 存档与进度 | 撤离、死亡、深渊层数、公会等级 | 数据持久化正确 |
| 性能 | 同屏敌人、特效、加载时间、内存 | 中端设备 30 FPS 稳定，内存 < 200 MB |
| 微信小游戏 | 包体、分包、安全区、广告、分享 | 符合平台审核与性能要求 |

### 与其他系统关系

- **主线章节/深渊**：难度测试与 TTK 测试的核心场景。
- **商业化**：广告测试需与微信广告 SDK 集成验证。
- **UI/UX**：界面流程测试确保玩家能顺畅完成全部核心操作。

### 设计原则

- 数值测试优先于内容量测试，确保“选择比数值更重要”的体验成立。
- 失败分析系统需基于真实测试数据校准提示内容。
- 所有广告相关功能必须通过合规性与奖励正确性测试。

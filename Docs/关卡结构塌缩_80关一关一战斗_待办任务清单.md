## 2. 目标

- 全局 **1~80 关**，**10 关一章**，**一关 = 一场战斗**（彻底废掉「节」层，令每关 `subs=1`）。
- 每章第 **5 关小 boss（10 号 xiaoboss）**、第 **10 关大 boss（11/12 真 Boss）**。
- 主线只承载剧情，紧凑推进、不拖沓；满级 60 靠任务 / 困难 / 活动 / 无限裂隙多渠道，主线经验照常发、不配平。
- 复用现成骨架：`grand`（每章 10 个）即新结构的「关」，`sub` 即要删的「小关卡」。**方案 = 令 subs=1 + 把 boss 判定从「末节」迁移到「关号」**。

## 3. 核心矛盾（为什么不能只把 subs 改成 1）

`ActSubsPerGrand` 从 `{5,8,10,…}` 改全 1 会踩三个崩点，必须同批改掉：

1. **除零 NaN**：`GameConfig.Combat.cs:794` `row = idx*9/(subs-1)`，subs=1 分母为 0 → 静默返回最弱档，怪物 / 装备数值全塌且不报错（浮点除零不抛异常，最难查的那类坏）。
2. **全 Boss 塌缩**：所有 `stageIdx == subs-1` 判定在 subs=1 时变成 `0==0` 恒真，散落在波次 / 金币 / 宝箱 / 属性共 7 处 → 80 关全 Boss 战、全发 Boss 金与钻石箱。
3. **真 Boss 造型消失**：真 Boss（11/12）`minWave=9`，subs=1 后 stageIdx 恒 0，`0>=9` 永远不成立 → 大 boss 只会出 10 号 xiaoboss。

---

## 4. boss 放置方案

新增**单一出口** `ActProgressionDefs.TypeOfGrand(章内关号 1~10)` + `BossKindOfGrand`，所有判定点统一调用，避免散落多入口对不上：

- 关号 **5** → 小 boss：取池只选 **10 号 xiaoboss**
- 关号 **10** → 大 boss：取池只选 **11/12 号真 Boss**
- 关号 **3、8** → 精英（默认保留精英体验，主人未提，可一句话去掉）
- 其余 → 普通关

boss 波取池传 `poolIdx=9`（满足真 Boss `minWave=9`），让所有 boss 入池，再按上面关号规则定点挑造型。

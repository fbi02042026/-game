## 2. 第 1 站：佣兵好感度 · 检查结果

### 2.1 涉及文件与调用链

- 界面：`Assets/Scripts/UI/MercFavorUI.cs`（预制体 `Resources/Prefabs/Town/佣兵好感.prefab`）
- 系统：`Assets/Scripts/Systems/MercFavorSystem.cs`
- 配置：`Assets/Scripts/Config/MercFavorDefs.cs`（好感上限 60 = 6 心 × 10；每日 3 次；特殊 +5 / 普通 +2；礼物 20 种 2/4/8）
- 存档：`Assets/Scripts/Core/SaveData.cs`（`mercTrust` 本体、`favorGifts` 礼物仓、`favorTalkedToday`/`favorTalkDayKey` 日键、`favorBondClearedIds`）

调用链（赠礼）：
`Button.onClick`（MercFavorUI.cs:794）→ `OnGiftClicked`（953-965）→ `MercFavorSystem.GiveGift`（167-175）→ `SaveData.ConsumeFavorGift`（1581）+ `SaveData.AddMercTrust`（1519）→ `SaveSystem.Save()` → `RefreshAll()`。

调用链（对话）：
`OnTalkClicked(slot)`（936-951）→ `MercFavorSystem.Talk`（83-97）→ `EnsureTalkDay` / `CanTalk` → `AddMercTrust` → 第 3 次聊完 `GrantRandomGift`（内部再 Save 一次）→ 外层 `SaveSystem.Save()` → `RefreshAll()`。

### 2.2 已知风险点核查

| 风险 | 实际结论 | 位置 |
|---|---|---|
| 好感到顶后仍可赠礼 | **是，会白扣礼物并把好感顶到 68** | GiveGift 167-175；AddMercTrust 1524 只钳下限 |
| 好感到顶后仍可对话 | **是，同样溢出** | Talk 83-97 |
| 赠礼扣资源与好感增长是否原子 | 单线程内顺序执行，无异常抛出风险；但**顺序是「先扣礼物再涨好感」**，一旦以后给 AddMercTrust 加上限钳制，也不会回滚礼物 → 必须先判上限再扣 | GiveGift 171-174 |
| 资源不足时的提示 | **无提示**：`OnGiftClicked` 拿到 -1 只 `RefreshGifts` 静默刷新（958） | MercFavorUI.cs:958 |
| 跨天 / 读档后好感保持 | 保持；对话次数按 `favorTalkDayKey` 本地日历日 0 点清零 | 32-41、1119 |
| 界面数字与存档不一致 | 一致，读口统一 `GetFavor` | MercFavorUI.cs:624/715/724 |

### 2.3 最小修法（仅报告，未落地）

1. **上限闸（一处，最省）**：`MercFavorSystem.GiveGift` 与 `Talk` 在扣资源前判 `IsBondOpen(d, hireId)`，已满返回 -1（-1 现有语义就是「不可执行」），UI 侧给一句 Toast「好感已满，羁绊地图已开放」。
   备选：`SaveData.AddMercTrust` 内部 `Math.Min(FavorMax, …)` 钳上限——但这会把「满值后送礼」变成「扣礼物、零增长、不提示」，体验更差，不建议单靠它。
2. **无礼物点击提示**：`OnGiftClicked` 的 `gain < 0` 分支加 Toast，别静默。
3. 说明：`Talk` 已满时是否也拦，需要主人拍板（见 2.5）。

### 2.4 可优化点

- `RefreshGifts`（735-800）每次刷新对 20 条礼物各 `Resources.Load` 一次图标；引擎有缓存，但可先按 `GetFavorGiftCount>0` 过滤再 Load，省无谓查询。
- 赠礼按钮在「好感已满」时仍可点（视觉上没灰），只靠代码拦的话仍会闪现错误反馈。
- `_giftTemplate` 旧定位路径（753-769）仍保留「模板宽当步进」的过渡逻辑，结构已建好时可删，减少两条路径。

### 2.5 需要主人手动确认（编辑器/真机各 3~5 条）

1. 把某佣兵好感改到 60（或反复赠礼攒满），再点礼物图标 → 看是否仍扣礼物、数字是否变 68/60。
   *期望*：应拦下并提示「好感已满」。
2. 好感 55 时送 1 个珍品（+8）→ 看是否显示 63/60、爱心第 6 颗是否溢出。
3. 点一个数量为 0 的礼物槽（若界面还留着）→ 看是否有任何反馈。
4. 聊完第 3 次后立刻再点答案 → 看按钮是否全变「今日已聊」、好感是否还涨。
5. 改系统日期到明天后重开界面 → 看 3 次是否恢复、已聊记录是否清空。

## 3. 任务清单

### R1 三张道具图路径替换
- **文件**：`Assets/Scripts/UI/EndlessRunGame.World.cs:74-76`（`SP_COIN` / `SP_CHEST` / `SP_PORTAL`）、`:243-250`（`LoadPropSprites`）
- **做法**：三个常量按 §2 映射表换值；`LoadPropSprites` 里「取不到直接 `LogError`」的既有行为**保持**，不改成兜底、不删日志。
- **验收**：进本无 `[跑酷] …图缺失` 三条 LogError；金币 / 宝箱 / 门三处 prop 视图 `SetActive(true)` 且 `sr.sprite != null`。
- **依赖 / 风险**：仅常量改动；路径含中文与下划线，注意与 `.meta` 文件名逐字一致。

### R2 道具按目标逻辑高度缩放
- **文件**：`EndlessRunGame.World.cs:819-831`（`EnsurePropView`），可参照 `EndlessRunGame.cs:240-248` `ComputeFgGeometry` 同款公式
- **做法**：现 `localScale` 写死 `_wRenderScale`(0.7)。改为按图原始像素高算 `s = 目标逻辑高度 / sprite.rect.height`，再 `s *= _wRenderScale`；目标建议：金币 48、宝箱 72、传送门 160（逻辑 px，真机可调，写进 `run_track.csv` 更优但本期可先常量）。
- **验收**：三者与 32×32 怪、160px 平台比例协调；金币拾取距离 `COIN_PICKUP_PX`、宝箱 100m 锚点、传送门黑屏判定**完全不变**。
- **依赖 / 风险**：🔴 立绘/门图原始尺寸比怪大 10~40 倍，不缩放会糊成巨物；缩放只进 `transform.localScale`，`logicX` / `logicY` / 判定半径一个都不乘。

### R3 玩家立绘
- **文件**：`Assets/Scripts/UI/EndlessRunGame.cs:252-262`（`BuildPlayer`）
- **做法**：`sr.sprite = MercPortraitSprites.GetStand("player")`；按目标高 96~120 逻辑 px 算缩放（同 R2 公式，再叠 `_renderScale`）；立绘 pivot 默认中心，而 `_playerGo` 的 y 是地面顶 → **挂子节点做脚底对齐**（子节点上移半个渲染身高），禁止改原图 pivot、禁止改 `_playerGo` 的判定坐标。取不到立绘 `LogError`，不兜底。
- **验收**：看得见玩家；跳跃随 `ApplyPlayerPos` 的 y 动；落地脚底贴平台顶面；碰撞 / 掉沟判定坐标与改前一致。
- **依赖 / 风险**：`MercPortraitSprites` 有缓存与 `DeviceParity.ReportMissing`，不要绕过它自己 `Resources.Load`。

### R4 佣兵立绘
- **文件**：`Assets/Scripts/UI/EndlessRunGame.Queue.cs:143-155`（`CreateMerc`）、`:17` / `:150` 注释
- **做法**：`sr.sprite = MercPortraitSprites.GetStand(id)`，id 从固定小数组（如 `H001/H002/H003`）轮换即可；同样按 R2 公式缩放 + 脚底对齐；**不读 / 不写 `SaveData.hiredMercs`**，佣兵仍只在内存。同步更新文件头「立绘接入是待确认项」的过时注释。
- **验收**：天降 0.35s、跳=顶替、往后跳出、受击往前弹飞四种表现都能看见；槽位 x 与延迟跟跳不变。
- **依赖 / 风险**：🔴 `EnqueueMerc()` 目前**无调用方**（`Queue.cs:31`），一局里仍不会有佣兵加入 —— 见 §5，本次不擅自加触发点。

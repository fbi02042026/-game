1. 编译零红字（Console 无 error CS）——「改了没生效」先查 Editor.log。

   - `Tools → 诊断 → 悬空 GUID 探针`（只看报告，不自动修）

### 2.3 判定口径

- **功能用例**：实际行为 = 预期 → PASS；偏差 → FAIL 并记「复现步骤 + 截图 + 日志行」。
- **数值用例**：必须写出期望数值（从配表读取），不写「数值合理」。
- **日志判定**：任何一次测试全程 LogError 计数必须为 0（认不出模式 fail-closed 的 LogError 属预期行为时单独标注）。

## 八、优化方案

### 8.1 测试体系三阶段落地（先定金字塔比例再写用例）

**比例**：EditMode 纯逻辑 50% / PlayMode 行为 20% / 冒烟与人工验收 30%。

| 阶段 | 内容 | 验收 |
|---|---|---|
| 一（1~2 天） | 建 `Assets/Tests/EditMode` + Tests.asmdef（仅引用 Assembly-CSharp）；把 §七 前三行的公式/规则/两套账写成 NUnit 用例；随机种子固定（System.Random 可注入处传入固定种子） | 用例可 `Tools` 外命令行跑，全绿 |
| 二（3~5 天） | PlayMode 冒烟：Boot→Town 加载、3 场景切换、一局假人战斗；把 §四 A8/ B5 这类「跨界污染」写成运行时断言 | 一条命令跑完冒烟 |
| 三 | 门禁：打包脚本（CliAndroidBuild）后置一步「跑 EditMode + 冒烟，失败即阻断」，**不放行开关**；接 `check_test_matrix.py` 出覆盖报告 | 门禁失败能拦住出包 |

### 8.2 可测性改造（只做最小增量，不动没问题的地方）

1. **随机注入**：抽卡/掉落/词缀掷档处，若直接 `UnityEngine.Random`，加一个可选种子入口（默认行为不变）。
2. **时钟注入**：每日刷新/体力恢复/广告配额处提供 `Func<DateTime>` 可覆盖点，测试可模拟跨天。
3. **结算落账收口**：确认局外落账只有单一出口（配合铁律「单一出口」），便于断言。

### 8.3 性能优化候选（测出数据再动手，禁止先加码调数）

- 战斗场景出怪峰值 GC Alloc（先采样再优化，避免拍脑袋）。
- 城镇 UI 弹窗反复 Instantiate（PoolManager 已有，核对覆盖面）。
- 纹理压缩已走 ASTC 工具，出包前核对未压缩残留。
- 首包体积：Art 下第三方特效 Demo 场景确认不进包。

### 8.4 流程优化

1. 把本文档 §三 冒烟 + §四 待验收项合并进 `Tools → 自检 → 主路径验收清单`（MainPathPlaytestChecklist），做到「出包前一键出清单」。
2. 遗留缺陷挂账：BattleUI.prefab:3626 + CharacterUI ×3 悬空 m_Sprite（只报告不清理，现行拍板）。
3. 每轮真机验收结果回填本文档 §四 表格（PASS/FAIL+日期），FAIL 项当天写进待办文档。

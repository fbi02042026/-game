### 1.5 为什么正常路径不会踩（设计对照）

- 正常收尾三条路都会清构筑：主动撤离 `TriggerEvacuation`（BattleManager.Death.cs:29-53）→ `EndRunLoadout` → `RunLoadout.Clear()`；阵亡 `OnHeroDead`（同文件 :19）；通关回城 `EndRunAndReturnToTown`（Settlement.cs:1820-1831）。
- 「进下一章」故意不清（Settlement.cs:1796 注释，主人 10-05 拍板「这时不清零」）。
- **只有异常结束会漏**：直接杀进程 / 停 Play 模式时若人已回城（无战斗快照），或新档/引导期路径 —— 构筑永久残留，且**没有任何 UI 提示**（`RunLoadout.HasResumable()` 全项目无调用方）。

## 3. 任务清单（改造点 + 验收，不写完整代码）

### T1【必改·今天实际踩的坑】引导期中断分支补清本局构筑

- 文件：`Assets/Scripts/Systems/BattleStateSaver.cs:222-227`
- 改造点：`if (!StoryProgress.TutorialDone)` 分支内 `ClearSaveStatic()` 之后补 `RunLoadout.Clear()`；注释说明「引导期/新档不继承任何旧局构筑」
- 验收：新档（或清除存档后）进城 → 进战斗，Editor 日志出 `[RunLoadout] 开新局：job=X`（非「继续上一局」）；场上只有玩家；顶栏抽奖币条 = 200
- 依赖：无。风险：低（引导期本来就不该有构筑；内存模式引导局不受影响，`Clear()` 对 MemoryMode 走 EndMemoryMode）

### T2【必改】「清除存档」按钮同步清本局构筑

- 文件：`Assets/Scripts/Systems/SaveSystem.cs:269-295`（`DeleteLocalSaveAndReset`）
- 改造点：删档流程里补 `RunLoadout.Clear()`（与 `BattleStateSaver.ClearSavedState()` 并列，一行）
- 验收：登录界面点「清除存档」→ 进城镇 → 进战斗 = 新局 + 启动金 200；PlayerPrefs 不再有 `RiftRunLoadout_v1`

- 依赖：无。风险：低

### T3【建议改·防呆】残留构筑不再静默续局

- 现状：`RunLoadout.HasResumable()`（RunLoadout.cs:192-197）已实现但**全项目无调用方**；异常结束的残留局下次进战斗被无声续上
- 改造点（候选，建议①）：① 进战斗入口（冒险页选章 / `StartNewRunInternal` 开头）判 `HasResumable()` → 走通用确认弹窗（标题 + 正文 + 「继续上一局 / 开始新的一局」双按钮，`StaminaConfirmPopup` 口径，层级 TownConfirm(910)）；② 维持静默续局但在入口面板顶行加一条常驻提示
- 验收：人为制造残留构筑（停 Play 不退局）→ 再进战斗必先问过玩家；选「开始新的一局」走 `RunLoadout.Clear()` 后 `BeginNew`
- 依赖：弹窗走项目既有通用弹出，**禁手搓运行时建树确认框**（2026-10-21 主人拍板口径）；若选①涉及交互/美术需先问主人
- 风险：中（动到进战斗入口流程，回归重点：引导局第一战不能弹这个框——`Rules.Active` 时跳过）

### T4【待主人拍板】续局 0 抽奖币怎么补

- 现状：`resumed=true` ⇒ 不补启动金（RunDraftDirector.cs:73-83，2026-10-05 拍板「开始金币是每局的，不是每关的」）；且局内钱包 `currentGold` **跨会话不落盘** ⇒ 续上的局入口面板全灰（截图：普通 97 抽不了）
- 候选：① 续局也补一份启动金（与 10-05 拍板不冲突——那条本意是「不是每关」，跨会话重进等于新的一局）；② 续局时从战斗快照把 `currentGold` 带回来（钱包跟局一起续）；③ 保持现状，入口面板加明确文案「本局抽奖币已用完，通关后可继续获得」
- 验收（ whichever ）：续局进关抽奖面板余额 > 0 或有明确说明；**不得双发**（`countsAsEarned=false` 口径保留，结算差额不含启动金）
- 风险：中（动经济口径，必须主人拍板再动）

### T5【待确认】续局不同步当前职业

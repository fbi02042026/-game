## 二、埋点：不用自己买服务器

**结论：现阶段完全不需要服务器。**

### 2.1 微信小游戏（首发平台）—— 用官方「We 分析」，免费

| 能力 | 说明 | 成本 |
|---|---|---|
| 基础数据自动采集 | 访问、留存、页面路径、会话时长、性能/崩溃，**零代码** | 免费 |
| 自定义事件上报 | 「事件分析」，代码里调一次上报接口即可 | 免费额度约 5000 条/日 |
| 场景分析（漏斗） | 「场景 + 行为分支」模型，适合看"关卡失败后玩家选了什么" | 免费 |
| 漏斗 / 路径 / 留存 / 分群 | 后台现成看板 | 免费 |
| 专业版 | 更长数据保存周期、API 拉取、更高额度 | ¥388/年 |

**主人关心的三个指标，We 分析都能直接看**：会话时长（自动）、留存（自动）、
后期广告（自定义事件 + 广告平台上报）。

### 2.2 TapTap —— 用 TapDB，也是 SDK 直报、不用服务器

TapSDK 里的 **TapDB** 模块：客户端 SDK 初始化后自动上报，后台有看板，
主要面向 Android / iOS / Unity 原生包。
**微信小游戏端是否支持需确认**（TapAD 归因文档提到"小游戏请参考小游戏数据接入"，
说明 Tap 侧有小游戏方案，但 TapDB 的小游戏适配要查证）。

### 2.3 建议路线

1. **首发微信小游戏 → 直接开 We 分析**（后台点一下开通，零成本，今天就能用）
2. 上 TapTap Android 端时再接 TapDB —— 两套并存没问题，反正都不要服务器
3. 真到"多渠道统一看数 + 自定义 BI"那一步，再考虑神策/友盟/GrowingIO（有免费额度），
   现在做是过度设计

### 2.4 要埋的事件（最小可用集，8 个）

| 事件 | 关键参数 | 回答什么问题 |
|---|---|---|
| `session_start` / `session_end` | 时长（秒） | **在线时长**（主人核心） |
| `stage_start` | 章节、关卡、战力 | 卡在哪一关 |
| `stage_end` | 胜负、时长、重试次数 | 难度曲线 |
| `chapter_reach` | 章节号 | 关卡进度分布 |
| `diamond_change` | 收支类型、数量、余额 | 经济健康（配合钻石方案） |
| `ad_slot_click` | 哪个位、是否付费 | 后期广告位设计依据 |
| `tutorial_step` | 第几步 | **新手流失点** |
| `quest_complete` | 任务 id | 主线牵引效果 |

### 2.5 技术风险点（要派工查证）

Unity（团结）转微信小游戏后，C# 调 `wx.*` 需要 JS 桥：
- 若团结自带微信 SDK 封装 → 直接用
- 否则要写一个 `.jslib` 桥接 `wx.reportEvent`
**建议封装一层薄 C# 门面**：`Analytics.Track(name, params)`，
以后换平台/换 SDK 只改这一处。

## 十二、职业数值为什么是小数 / 计算有没有问题（主人问的）

**结论：公式链路没问题，但有两处「看得见的取整偏差」。**

### 链路全是 float，不会丢精度
`AttrSystem`（float）→ `DamageFormula.BuildAttackRaw / FinalHit`（float）→ `UnitBase.currentHp`（**float**，UnitBase.cs:107）
→ 掉血精确扣到小数。**小数本身不会算错。**

### 但玩家看到的是整数（两处）
| 位置 | 代码 | 现象 |
|---|---|---|
| 人物面板攻击力 | `CharacterUI.cs:342` `FormatAttrWithTalent(atk, ..., roundInt: true)` | 6.8 显示成 **7** |
| 伤害飘字 | `UnitBase.cs:1221` `Mathf.RoundToInt(finalDamage)` | 实际扣 4.8，飘字显示 **5** |

累积效应：打 10 下每下显示 5，血条实际只掉 48 —— 玩家会觉得"数字对不上"。自动战斗里没人细算，但**刀数会漂**。

### 另外一个真问题：下限 1 会吃掉小数
`FinalHit = Max(1, raw - DEF)`。攻 6.8 打防 6 的怪 → 0.8 → **强制抬到 1**。
小数在"低攻 vs 高防"区间被下限抹平，这时候小数和整数没区别。

### 女仆建议（未动手，等主人话）
- 想要**直观**：把 6 个职业基础攻击改成整数（7 / 8 / 4 / 4 / 7 / 4），飘字与面板天然对得上，代价是 DPS 精度粗一点。
- 想要**可调**：保持小数，但把 `SpawnDamageText` 的 `int` 改成 `float` + `ToString("F0")` 只影响显示，扣血仍用精确值（现状已是如此，其实**不用改**）。
- 不建议动：下限 1 与 float 链路。

## 1. 卡面视觉规格

### 1.1 设计原则：一屏一个焦点，三层信息，多一个字都不放

主人要极简（原话「太复杂了…简单点方便玩家理解」）。所以开奖卡**只承载 3 层信息**，属性明细一律不放在这里（属性明细在 `EquipReplaceConfirmUI` 和背包里看）：

- **L1 是什么** → 图标 + 类型行（获得装备 / 招募佣兵 / 获得技能 2/4 / 获得金币）
- **L2 是哪个** → 名字行（品质色）
- **L3 好不好** → 价值行：**「品质词 · 战力 +N · 称赞词」一行写完**（与策划 B-2 同口径，**一行不多**）

### 1.2 卡片尺寸与定位

| 项 | 现值 | 建议值 | 理由 |
|---|---|---|---|
| 卡片尺寸 | 300 × 132 | **460 × 156** | 与策划 B-2「固定三行」对齐：三行不需要 168 那么高，压到 156；宽度反要**加**到 460 —— 第 3 行是「传说 · 战力 +320 · 势不可挡」这种长串，且 §6.2 要求关键数字 ≥ 24 px，宽度核算见 §1.3。720 宽里占 64% |
| 锚点 | (0.5, 1.0) 上中 | **(0.5, 0.5) 正中** | 上锚点在高瘦屏（H=1600）会把卡推到离顶 230，与顶部 HUD 抢位；正中锚点在所有屏型上都稳定 |
| anchoredPosition.y | −230 | **+150** | 屏幕中线上方 150，落在视觉重心区；1280 与 1600 两档都安全，不压顶栏 HUD |
| 卡底 | #0A0A0D @0.94（固定） | **按品质档变**（见 §2.3） | 深底衬托品质色，让"亮"这件事本身携带信息 |
| 吃射线 | 否 | **否（保持）** | 连抽时不挡按钮 |

## 2. 稀有度视觉语言

### 2.1 ⚠ 口径收敛（我 v1 写错了，这版以代码真源为准）

v1 我写「色相 5 档跟内容走」，**核对代码后是错的**，这里更正。三处真源交叉验证：

| 真源 | 位置 | 结论 |
|---|---|---|
| `DraftPool.MapRarity(Rarity)` | L811 | 装备 `Legendary`**和 `Epic`** → `SkillRarity.Legendary`；`Rare`**和 `Uncommon`** → `SkillRarity.Rare`；其余 → `Common` |
| `DraftPool.RarityBucket(SkillRarity)` | L299（概率公示的桶） | `Epic → "传说"`。注释写着主人 2026-10-05 拍板「没有『史诗』品质」 |
| `EquipReplaceConfirmUI` | L207 / L331 注释 | 旧写法走 `MapRarity` 会把「史诗(紫)」说成「传说」，所以替换弹窗**改走了另一套** |

三者结论一致且指向：**卡面品质只有三档 —— 普通 / 稀有 / 传说。紫装 = 传说（橙金），绿装 = 稀有（蓝）。**

> **卡面品质词与颜色必须走 `MapRarity` → `SkillRarityUtil.DisplayName` + `RarityPalette.Get(SkillRarity)`。**
> **不要**用 `RarityPalette.Get(Rarity)` 直接取装备的 5 档色 —— 那会让紫装在开奖卡上是紫色「史诗」，在概率弹窗里却是橙色「传说」，**两个屏幕打架**。

（与策划冲突 #4「三档 vs 五档」就此关闭：以 `MapRarity` 为准，三档，**不需要改任何枚举，也不需要程基岩动数据**。）

**顺带报一个视觉一致性 bug（需程基岩修，非我的活）：**
概率弹窗的「传说」色走 `DraftPool.QualityColor`（L312） = `(1, 0.62, 0.25)` = **`#FF9E40`**；
开奖卡的「传说」色走 `RarityPalette.Legendary` = `(1, 0.72, 0.20)` = **`#FFB833`**。
**同一个「传说」在两个屏幕上两个颜色。** `QualityColor` 是 `RarityPalette` 类注释里点名的「曾散着 5 份硬编码色表」的残留之一，建议一并收敛到 `RarityPalette`（见 §2.6）。

### 2.3 🔀 演出档判定：双通道取 Max（合并策划 C-2）

策划 C-2 要求「情绪强度按**实际战力增量**分档，不按稀有度分档」—— 这条**我完全同意**，
但纯按增量分档会出事：一件传说如果替换后战力只涨了 20，就会拿到 0.60 s 的"冷处理"，
**而建立「传说」这个概念恰恰依赖它的演出峰值**（策划 F-2 自己也是这么论证 pity 的）。

**合成方案：两个通道各算一档，取最大值。**

```
演出档 = Max( 品质档 , 增量档 )

品质档：普通=1  稀有=2  传说=3
增量档：PraiseOf(delta) 低档=1  中档=2  高档=3     // 阈值现成：PraiseMidAt=300 / PraiseHighAt=700
```

- 传说 + 增量小 → `Max(3, 1) = 3` → **峰值保住**（策划红线 4 ✓）
- 普通 + 增量大 → `Max(1, 3) = 3` → **也拿到高档演出**（策划 C-2「低端卡不挫败」✓）
- 传说 + 增量大 → `3` → 同上（无叠加，不做成"超传说"）

**但有一项不参与取 Max，永远只跟品质走：全屏闪 + 震屏。**
理由：金色全屏闪是**传说的专属视觉签名**，如果普通高收益也能触发，这个签名就废了。
普通高收益拿到的是「光晕 + 更长停留 + 更响的音效 + 更强的称赞词」，峰值依然明确，**只是不闪屏**。

### 2.4 ⚠ 关键约束：低端卡不要演出得像"失败"

这是主人痛点里最容易被改坏的一环。明确规定：

1. **普通卡也必须有弹入过冲**（1.06，与稀有的 1.12 只差 0.06）—— 有"弹出来"的活力，不像"贴上去"。
2. **普通卡也必须有音效** —— 沉默 = 惩罚感。
3. **普通卡的第 3 行也要亮** —— 即使只有 `战力 +5`，也照样显示绿色 `战力 +5` + 称赞词「小有长进」。**绝不写"安慰奖""未获得""可惜"一类字**。
4. **禁止任何向下/消极的形态**：不许向下位移、不许灰化下调动效、不许叹气式缩放（缩小消失）、不许打叉、不许"×"。
5. **金币卡（安慰奖）重构成"折扣"语义** —— 见 §2.6。
6. 三档的差别应该是 **"更亮 / 更响 / 更久"**，而不是 **"有 / 没有"**。
7. **称赞词按增量走、不按品质走**（策划 C-2）。普通装备若属性给力，照样显示「实力大增」—— 玩家学到的是「看数字」而不是「看颜色」。

### 2.5 成本 / 资源 / 指标

- **成本：低**。全部是 `DraftPrizePopupUI` 里已有字段的参数调整（边框宽度、光晕 offset/alpha/频率、停留时长、scale 曲线），外加 3 个 `CombatJuice.Shake` / `BattleScreenFlash` 调用点。
- **需要新资源：否**（若想要柔和光晕而非硬边外扩，见 §9 可选升级）。
- **指标：留存 + 广告变现**。传说档有明确峰值 → 抽奖行为被正强化 → 局内抽奖次数↑ → 单局时长↑ → 广告曝光位↑。

### 2.6 金币安慰奖卡（策划 C-4 · 含我对他方案的 3 处修正）

策划 C-4 的方向我完全同意：**金币卡不能走稀有度色**，否则 `Rarity = SkillRarity.Common` 会把它染成白灰 = 视觉上的"最差一档"。但执行上有 3 个问题必须修正：

**修正 ①　色值不要从 `QualityColor` 取，要进 `RarityPalette`**

策划写「色值参考 `DraftPool.QualityColor` 里金币那档 `(1, 0.85, 0.35)`」。
`QualityColor` 是**第三套硬编码色表**（`RarityPalette` 类注释点名要收敛的对象），且它的传说色 `#FF9E40` 与 `RarityPalette` 的 `#FFB833` 已经打架（§2.1）。
→ **做法**：`RarityPalette` 新增 `public static readonly Color Gold = new Color(1f, 0.85f, 0.35f, 1f);`，让 `QualityColor` 与 `ShowDrawPrizeCard` **都转发到它**。这样概率弹窗与开奖卡的金币色自动同源，且符合「色值只问 RarityPalette」。

**修正 ②　金币金 `#FFD959` 与传说金 `#FFB833` 太近，必须靠形态区分**

两个都是黄，`#FFD959` 甚至比 `#FFB833` 更亮 —— 光看颜色玩家会误以为"抽到金币 = 抽到传说"，**这会稀释传说的峰值**，与策划 F-2 的意图正好相反。
→ **强制三件事**（缺一不可，都不是可选项）：
- 第 1 行类型词 = `获得金币`（文字通道，最可靠）
- **必须带 `icon_gold.png` 图标**（形态通道）—— `Resources/UI/Icons/Common/icon_gold.png` **已存在**，零新资源
- **无光晕、无全屏闪、无震屏**（策划已要求，我加一条：光晕是传说的视觉签名，金币不能碰）
- 名字行用**淡金 `#FFE9A8`** 而非饱和金，与传说的 `#FFB833` 拉开明度

**修正 ③　第 3 行三个数字太多了，且与 P1-3 重复**

策划 C-4 写第 3 行 = 「回血 40 · 下一抽再补 48」——**三个数字挤一行**（`金币 +40` / `回血 40` / `再补 48`），是四张卡里信息密度最高的，与"极简"冲突。

## 3. 揭晓演出视觉规格（毫秒级时间轴）

### 3.1 前摇方案：因策划的 1.5 s 上限，我撤回 v1 的推荐

策划 C-1 定了一条硬约束：**总时长 ≤ 1.5 s**（不拖连抽节奏）。
把我的 v1 方案 B（250 ms 翻牌前摇）代进去算：

```
前摇 250 + 弹入 220 + 传说停留 1100 + 淡出 180 = 1750 ms  ❌ 超 250 ms
```

要留前摇，就只能砍传说停留（1.10 → 0.85 s）—— 但策划明确要求**传说 1.10 s 不动**（红线 4），我同意这条优先级更高。

**→ 结论：前摇砍掉，改列 P2。** 理由有二：
1. 策划 **P0-2（卡先弹、Toast 后弹）** 已经修掉了更大的那个问题 —— Toast 抢跑剧透。**揭晓的"未知间隙"主要由"不剧透"提供，不是由翻牌动画提供的。**
2. 1.5 s 上限是连抽节奏的硬约束，比"多 0.25 s 的仪式感"重要。

## 5. 期待感的视觉铺垫（抽卡前）

主人原话里「对抽中的东西有期待感」的另一半是：**还没抽的时候就得有期待**。

### 5.1 ⚠ 先拆掉一个反期待的设计

`BattleEntryDraftPanel` L291 `CountdownFontSize = 120`，一个 **120 px 的金色倒计时数字常驻在 map 正中间**（L1037 挂在 `_mapRt` 上，`rt.anchoredPosition = Vector2.zero`）。

问题：① 抢走屏幕正中的视觉焦点，抽奖预告反而没地方放；② 常驻大数字 = 持续催促，与"期待"情绪相反；③ 30 s 全程可见，玩家在第 3 秒就学会了忽略它。

| 项 | 现值 | 建议 |
|---|---|---|
| 字号 | 120 | **56** |
| 位置 | map 正中心 | **右上角**（锚点 (1,1)，`(−24, −24)`） |
| 常态色 | `#FFE070` | `#A8AEBC`（灰，弱化） |
| 最后 5 秒 | 无变化 | **变 `#FF6B6B` + 放大到 84 + 每秒一次 1.15 缩放脉冲** |
| 前 25 秒 | 常驻显示 | 建议**只显示数字不显示边框**，或进一步：前 20 s 完全隐藏，后 10 s 才出现 |

成本：**低**（改 2 个常量 + 加一个 color 分支）。

### 5.2 按钮态

| 态 | 视觉规格 | 成本 |
|---|---|---|
| **可抽（默认）** | 按钮外框 **2 px 品质色呼吸光**：alpha 0.35 ↔ 0.70，周期 1.2 s | 低（一个 `Image` + 协程，或用 `Outline` 改色） |
| **按下** | scale 1.0 → 0.92（40 ms）→ 1.0（60 ms） | 低 |
| **币不够** | ① 价格数字变 `#FF6B6B`；② 价格下方那行小字切换成 16 px `还差 40`；③ **按钮保持原图不动**（`interactable = false` 的 disabledColor 保持现状）<br>⚠ **禁止**：抖动、打叉、"×"、灰化到看不清 —— 那是在惩罚玩家，不是提示 | 低 |
| **免费可抽** | 那行小字显示 `免费一次`（`#FFB833`）+ 按钮外框**金色呼吸**（周期 0.9 s，比常态快） | 低 |
| **本拍已抽完（引导局锁）** | 现状置灰即可，**不加任何额外提示** | — |

#### 🔀 价格下方那行小字：**互斥单槽，不是两行**（合并策划 P1-3）

策划 P1-3 要加「下一抽 88」，我要加「还差 40」。**放在同一块地方就是两行小字 = 信息过载**（他自己标注的风险）。
→ **做法：同一个 Text 节点，按状态互斥切换，永远只显示一条。**

| 状态 | 该行显示 | 颜色 |
|---|---|---|

- 三条互斥，**任何时刻只显示一条**，不叠加。
- 成本：**低**（一个 Text + 一个三分支）。

### 5.3 攒币进度的可视化

「还差 40」这行字要**实时更新**，且金币变化时要有反馈：

- 战斗内金币数字变化时（`BattleManager.AddRunGold`）：**数字跳动** scale 1.00 → 1.18 → 1.00，180 ms；数字色短暂变 `#FFB833` 再回落。
- 目的：让"钱在涨"被看见 → 让"再打两波就能抽"成为可见的进度条。
- 成本：**低**。

| 底色 | `#242433` @0.92 | `#2A2438` |
| 边框 | 无 | **2 px `#FFB833`** |
| 内容 | 一个「!」38 px | **两行**：上 `!` 34 px `#FFB833`；下 **`传说 0.6%`** 14 px `#FFD98A` |
| 位置 | 普通按钮右侧 38 px | 不变 |

> ⚠ 我 v1 写的「传说 5%」是**占位值，作废**。真实值必须走 `DraftPool.BuildOddsRows()` 现取（策划实测第 1 关 ≈ **0.6%**），**绝不写死**。

**为什么放「!」按钮而不是「普通按钮下方」**：策划 P1-3 也要在价格下方加一行「下一抽 88」。
如果把概率也塞到价格下方，那一块会变成**两行小字**，是他自己担心的"信息过载"。
→ **分工**：价格下方那一行**只放价格相关信息**（见 §5.2 互斥规则）；概率挂到「!」按钮上，两者隔着一个按钮，不打架。

成本：**低**（改 `BuildOddsButton` 一个 Text + 加一个 Text + 加边框 Image）。
指标：**在线时长**（知道有大奖 → 抽奖次数↑ → 局内时长↑ → 广告曝光↑）。

### 5.6 成本 / 资源 / 指标

- **成本：低**（全部是改常量 / 加 1~2 个 Text / Image）。
- **需要新资源：否**。
- **指标：在线时长 + 广告变现**（抽奖次数是局内时长与广告位的直接前置）。

## 6. 可访问性

**定级：Standard（标准级）。**

理由：本项目是单人离线向 Roguelite、无实时对抗、无文字剧情依赖，不需要 Comprehensive/Exemplary；但**抽奖是主玩法且用颜色编码稀有度**，所以「色觉障碍友好」与「小屏可读性」是**基础要求，不是锦上添花**（我的职责边界里可访问性是硬性项）。UX 规格（由文策渊产出）**必须引用本分级**。

### 6.1 色觉障碍：三重通道，绝不只靠颜色

| 通道 | 普通 | 稀有 | 传说 | 金币（特判） |
|---|---|---|---|---|
| ① **文字**（主通道） | 第 3 行「普通」 | 「稀有」 | 「传说」 | 第 1 行「获得金币」+ 第 2 行「金币 +40」 |
| ② **边框粗细** | 2 px | 3 px | 4 px + 2 px 白外描边 | 2 px |
| ③ **光晕**（有/无 + 频率） | 无 | 外扩 14 px，4 Hz | 外扩 22 px，6 Hz | 无 |
| ④ **图标**（形态通道） | 装备/技能/佣兵图标 | 同左 | 同左 | **`icon_gold.png`（必需）** |

**收敛到三档后，色觉风险大幅下降**：只剩 `#CCD1DB`（灰白）/ `#59ADFA`（蓝）/ `#FFB833`（橙金）—— 蓝与橙金对红绿色盲**可辨**，是安全组合。`RarityPalette` 这套色相选得好，不必改。

**新增风险点：金币 `#FFD959` 与传说 `#FFB833` 都是黄，色觉上极易混淆。**
→ **强制：金币卡必须同时带 `icon_gold` 图标 + 第 1 行「获得金币」文字**，且**无光晕**（光晕是传说的签名）。详见 §2.6 修正 ②。

**验证方式（低成本）**：团结 Game 视图 + 任一在线色盲模拟器（Coblis）截 3 张：正常 / 红绿色盲 / 蓝黄色盲，检查三档是否仍可区分。**成本：低（一次截图）**。

### 6.2 小屏可读性下限（逻辑像素，720 宽基准）

| 项 | 下限 | 本文档取值 | 结论 |
|---|---|---|---|
| 正文最小字号 | **16 px** | 第 1 行 16 / 面板价格小字 16 | ✅ |
| 名字字号 | **≥ 28 px** | 30 | ✅ |
| 关键数字（战力 +N） | **≥ 24 px** | 24（第 3 行整行字号，卡宽因此定 460 而非 440） | ✅ |
| 触摸目标 | **≥ 88 × 88** | 抽奖按钮 140×190 ✅；「!」按钮 58×58 ❌ → **改 88×88** | 需改 1 处 |
| 文字对比度 | **≥ 4.5:1** | 见下表 | ✅ |

### 6.3 动效安全

- 提供 **「减少动效」开关**：关闭震屏 + 全屏闪 + 光晕脉动，保留弹入与淡出（保证信息仍可读）。
- 实现：一个 `static bool ReduceMotion`（挂到现有设置存档位）。
- 成本：**低**。
- ⚠ 光敏癫痫安全：**全屏闪每 30 s 至多 1 次**（与 §3.4 连抽保护共用同一个节流器），单次 ≤ 300 ms，峰值 alpha ≤ 0.45。**这是硬约束，不是建议。**

以下 4 项**只用现有资源 + 少量代码**，不改 prefab、不建美术、不新增任何图片文件。合计约 **100~130 行**，一个下午可完成。

#### V-1 · 卡体放大居中 + 金币卡补图标 ⭐（建议并进 P0-1 一起做）

#### V-2 · 传说档爆点：接震屏 + 全屏闪 0.28 → 0.42 + 边框白闪 ×3

- **成本：低** · **新资源：无** · **指标：留存**

#### V-3 · 「!」按钮升级为「传说 0.6%」+ 金边 + 58→88

- **成本：低** · **新资源：无** · **指标：在线时长 → 广告变现**

#### V-4 · 币不够显示「还差 40」+ 价格变红；倒计时 120 px → 56 px 挪右上角

- **成本：低** · **新资源：无** · **指标：在线时长**

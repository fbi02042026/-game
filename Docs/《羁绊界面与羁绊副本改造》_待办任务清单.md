### T1 界面自适应 + 整体放大
- **文件**：`Assets/Scripts/UI/MercFavorUI.cs:114-118`（Awake）、`Assets/Resources/Prefabs/Town/佣兵好感.prefab:619-647`
- **根因**：`Panel` 写死 `m_SizeDelta 600×900`、`m_LocalScale (1,1,1)`、`m_AnchorMin/Max 0.5`、`m_AnchoredPosition (-4,0)` → 720×1280 下只占 83% 宽 / 70% 高。`Assets/Scripts/Core/UICanvasSetup.cs:30-37` 的 ApplyPopup 已给 Canvas 挂 CanvasScaler（ScaleWithScreenSize + MatchWidthOrHeight + `DesignAspectLetterbox.ResolveUiMatch()`），所以问题不在 Canvas 层。
- **做法**：照 `Assets/Scripts/UI/BattleSettlementUI.cs:241-277 FitPanelUniformScale()`，按设计分辨率算出 s，运行时只给根 `Panel` 的 `localScale` 赋 `(s,s,1)`；幂等（重复 Show 不叠乘）。不改任何子节点的坐标 / 锚点 / SizeDelta。
- **验收**：720×1280 与瘦屏 / 宽屏下界面等比放大、不裁切、不溢出；左列头像仍可滚动；问题气泡仍压在半身像框上；视觉仍是 prefab 那一套效果。
- **依赖 / 风险**：`MercFavorUI.BuildLeftRoster` 与 `_rosterClipH` 是按运行时 `rect` 实测的本地几何，父层 scale 变化后必须实测回归；`BuildQuestionBubble` 用绝对坐标 (73,325) / sizeDelta(338,44)，随父整体缩放理论上不错位，需截图确认。

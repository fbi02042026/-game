# UI 竖屏适配规范（2026-09-24 主人拍板）

> 以后**每个界面、每次改动都优先按这份规范对齐**，做完打勾。

---

## 一、总方针

| 屏幕类型 | 判定 | 处理方式 |
|---|---|---|
| **竖屏（比 9:16 更瘦或相等）** | `screenAspect ≤ 0.5625` | **宽对齐**：逻辑宽恒 720，多出来的高度给中间 |
| **更宽屏（平板等）** | `screenAspect > 0.5625` | **高对齐 + 左右黑边**（现状即可，本轮不改） |

- 设计基准：`GameConfig.DESIGN_WIDTH = 720`、`DESIGN_HEIGHT = 1280`（9:16 = 0.5625）
- 竖屏宽对齐由 `DesignAspectLetterbox.ResolveUiMatch()` 返回 **0（宽度匹配）** 实现，**已经是对的，不要动**
- 更瘦屏（如 1440×2960，aspect 0.4865）逻辑分辨率会变成 **720 × 1480**，上下各多出约 100

## 二、竖屏三条落地规则

1. **上面的往上移**：顶栏类节点锚定到顶（`anchorMin.y = anchorMax.y = 1`）
2. **下面的往下移**：底部操作区 / 底栏类节点锚定到底（`anchorMin.y = anchorMax.y = 0`）
3. **中间填掉**：
   - 该区域**有背景图** → 用背景**平铺铺满**（`ApplyEnvelopeImage`，已有 `AspectRatioFitter` EnvelopeParent 方案）
   - **没有背景** → 垫一层**黑底**（运行时补 Image 纯黑），以后看效果再换成美术底图

**实现方式铁律**：一律**运行时在代码里改锚点 / 补底图，绝不改 .prefab**
（与 `SafeAreaFitter` 头部注释口径一致：本类组件都是运行时 AddComponent，不碰预制体；预制体里摆好的美术效果为准）

## 三、改锚点的两个坑（必须遵守）

1. **先记录 base 再从 base 重算**：节点的原始锚点未必是全拉伸（贴底栏常是 `anchorMin=(0,0)/anchorMax=(1,0)`），直接改锚点会让 offset 语义错位、元素跳位。照 `SafeAreaFitter.CaptureBase()` 的做法来。
2. **改锚点会触发 `OnRectTransformDimensionsChange`**：加守卫防递归（`SafeAreaFitter.Apply` 里的 `_applying` 标志）。

## 四、验收

| 分辨率 | 期望 |
|---|---|
| 1440 × 2960（18.5:9 竖屏） | 顶栏贴顶、底部贴底、中间被背景或黑底填满、两侧不裁 |
| 1080 × 1920（9:16 基准） | 与现状一致，无变化 |
| 1536 × 2048（3:4 平板） | 高对齐 + 左右黑边，本轮不变 |

## 五·补、AdventureUI 专用适配（通用上下拆分管不了，单开一套）

**为什么单开**：AdventureUI 不是「上中下三块」结构，通用 `ApplyVerticalSplit` 按中心分界会误判，所以主人点名按它自己的布局改。

**实测几何**（`Tools/prefab-analysis/dump_ui_tree.py` 导出，父 = 根 stretch 全屏，逻辑宽恒 720，逻辑高 H：9:16 是 1280，1440×2960 是 1480）

| 节点 | 预制体原始 | 瘦屏改造后 |
|---|---|---|
| `RightContent` | anchor(0,0)-(1,1)，offMin(170,574.15) offMax(0,-98.15) | 水平改右锚定(1,0)-(1,1)，矩形完全不变 |
| `MapRoot` | anchor y=(1,1) pivot(0.5,1)，右溢出 35，高固定 654 | 右溢出 → 0；高拉伸到 `H-98.15-14-(DetailPanel顶+16)`（H=1480 时 **870.75**） |
| `DetailPanel` | 单点锚(0.5,0)，硬编码 711.4×481.1，底距 113 | 左右 stretch（边距对称 4.3）+ 底部锚定贴底，高度 481.1 不变 |

**瘦屏（H=1480）最终分区**（bottom-origin）：DetailPanel 0~481.1 → 地图 497.1~1367.85 → 顶部余量到 1480。地图背景 `MapBg` 自动铺满中间，无空白。

**可调开关 / 常量**（都在 `UiLayoutStretch.cs`）
- `EnableAdventureUiFit = true` —— 总开关，false 一键全还原
- `EnableAdventureMapStretch = true` —— 中间地图拉伸开关（主人看效果不满意可关，关后地图回到 654）
- `MAP_RIGHT_INSET = 0f` —— 地图右边距（原来是 35，主人嫌没居右）
- `MAP_BOTTOM_GAP = 16f` —— 地图底与详情面板顶的间隙
- `DETAIL_PANEL_BOTTOM_GAP = 0f` —— 详情面板底部预留（若被 BottomNav 遮挡就调大）

**生效条件**：仅 `逻辑高 > 1280+1`（更瘦屏）才改；标准 9:16 直接 return，美术摆的原样一点不动。幂等（按 instanceID 记 base，重复调用不累积）。

**已知边界**：`EnableAdventureMapStretch` 若在运行时从 true 改成 false，MapRoot 高度不会自动回退（需重开界面）。编译期开关不受影响。

**排查工具**：`Tools/prefab-analysis/dump_ui_tree.py <prefab路径> [深度]`，打印树 + 每节点的 anchor/offset/pivot。
> 注意 offsetMin/offsetMax 的正确算法是 `offsetMin = anchoredPosition - sizeDelta * pivot`（曾经写成 ±sizeDelta/2，只有 pivot=0.5 时碰巧对，pivot=0 或 1 的节点会全错，已修）。

## 六、以后做新界面的检查项（开工前先过一遍）

1. CanvasScaler 是否走 `ResolveUiMatch()`（竖屏应为 0 宽度匹配）
2. 顶部元素是否贴顶锚定（y=1）
3. 底部元素是否贴底锚定（y=0）
4. 中间区域是否有背景平铺；没有就补黑底
5. 1440×2960 与 1080×1920 两个分辨率各看一眼

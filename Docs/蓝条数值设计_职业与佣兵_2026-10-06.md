## 0. 2026-10-06 最终口径（主人第三条拍板 → 全文以此为准）

| 主人原话 | 落地 |
|---|---|
| **「蓝不足不能释放」** | 单一规则：MP < 耗蓝 → **直接不放**，CD 不重置、不排队、不透支。~~超载 Overload 方案作废~~（见 §9.5） |
| **「回蓝的速度不要太快」** | 基础回复下调：**治疗 1.2/s、法术 1.3/s**（回满一发要 80~100 秒，**比一关还长**）；真的急着用得多？→ 只有升级/升星这一条路 |
| **「SKILL_COOLDOWN_MUL 是技能 cd？先保持时间长的」** | ✅ 是的，`SKILL_COOLDOWN_MUL = 4.0` 就是**技能冷却总倍率**：`有效CD = 表里的基础CD × 4`。<br>佣兵走 `MercSkillCaster.Bind`：`CooldownTotal = (cfg.cooldown 或 8s) × SKILL_COOLDOWN_MUL`；玩家走 `PlayerSkillDefs.cs:777` 同一常量。<br>**维持 4.0 不动**（主人拍板「先保持时间长的」）→ 一关技能次数本来就很稀少。 |
> **口径变更带来的重新定位**：CD 这么长时，MP 不可能成为唯一的频率闸门（一关本来只够放 1~3 次）。
> 所以 MP 的三个作用改成：① **禁止连喷**（池只够 1.2~1.5 发）② **给 CD 缩减兜天花板**（不然堆满 CD 缩减会失控）③ **养成收益落点**（能把「放一发」变成「能连放两发」）。详见 §5 重算。

## 2. 四条公式（全部单一出口，业务里不许写数字）

```
① 有效 CD   = 技能基础 CD × SKILL_COOLDOWN_MUL     （= 4.0，主人拍板**维持不动**）
② 单次耗蓝   = 技能表「耗蓝」列（物攻/防御 = 0；恢复/法术按 §3）
③ MP 池上限  = 定位基础池 × (1 + 0.12×(★-1)) + 6 × (Lv-1)
④ 每秒回复   = 定位基础回复 × (1 + 0.12×(★-1))
⑤ 释放闸门   = CD 就绪 **且** MP ≥ 耗蓝            （MP 不足 → **不放**，CD 不重置、不排队）
```

### 2.1 定位基础值（**最终值，2026-10-06 拍板**）

| 定位 | 基础池 | 基础回复 | 典型技能耗蓝 | 满池能存 | 回满一发要多久 | 适用 |
|---|---|---|---|---|---|---|
| **治疗型** | **150** | **1.2 /s** | 100（单体）/ 120（解控·群体） | 1.25~1.5 发 | **83~100 s**（比一关还长） | 牧师 / 水系 / 圣光 / 所有「恢复」类 |
| **法术型** | **150** | **1.3 /s** | 120 | 1.25 发 | **92 s** | 火 / 雷 / 法 / 所有「法术」类 |
| **玩家**（4 技共享） | **300** | **1.8 /s** | 同档值（90/100/120） | 约 2.5~3.3 发 | 单技能 50~67 s | 牧师职业 / 法师职业 |

> 关键点：**满池只存 1.25~1.5 发** —— ★1 时**连放两发是不可能的**，这是紧张感的根。
> 回复刻意慢到「回一发要 80~100 秒」：一关之内**别指望靠回收完成第二次大节奏**，想要更多次只能升级/升星。
> 玩家池/回复只有佣兵的 2 倍、却要供最多 4 个技能 → 天然更紧张。
> ⚠ 硬约束：**单次耗蓝必须 ≤ 基础池**（100/120 ≤ 150 ✓），否则会出现「永远放不出」的死局。

### 2.2 成长系数

| 成长来源 | 池 | 回复 | 说明 |
|---|---|---|---|
| **每升 1 级** | **+6** | 不变 | 线性，稳定小收益 |
| **每升 1 星** | **+12%**（对基础） | **+12%**（对基础） | ★5 = ×1.48；逐星叠乘，演算见 §5 |

> 星级同时抬「**爆发储备**（池）」和「**释放节奏**（回复）」→ 在长 CD 口径下，最直观的收益是
> **「从只能放一发 → 能连放两发」**（演算见 §5.1：小白 ★1 池 150 只能 1.5 发；★3 起能 2.3 发；★5 能 3.0 发）。

## 4. 开局与跨关节奏（沿用已拍板口径）

| 时点 | 处理 |
|---|---|
| 每关开始 | MP = **满池**（每关独立结算，不继承） |
| 技能 CD | 开局仍按**满冷却进场**（`MercSkillCaster.Bind` 现有行为不变）→ 第一次技能要先把 CD 走完 |
| 抽卡 / 抽奖面板期间 | `Time.deltaTime = 0` → 不回蓝（天然） |
| 佣兵换人（同槽位） | 按槽位保留当前蓝量，**不回满**（防「换人刷蓝」） |
| **升级 / 升星（局内卡）** | 立刻重算新池，并把**新增的那部分直接补进当前蓝**（`MP = min(新池, 当前蓝 + (新池 - 旧池))`）→ 抽到卡那一下有「回一口」的正反馈 |

## 5. 紧张感 calibration（**按 MUL = 4.0 重算**）

**标定假设**：一关有效战斗时长 **T ≈ 75 s**（含波间隔）；`SKILL_COOLDOWN_MUL = **4.0**`（主人拍板维持不动）。

```
一关能放几次 N = min( CD 上限 = T / 有效CD ,  MP 上限 = (池 + 回复×T) / 单次耗蓝 )
连喷能力       = 池 ÷ 单次耗蓝        ← 长 CD 口径下，这才是真正被养成的东西
```

> **诚实前提**：MUL=4 时有效 CD 是 32~160 秒，一关本来只够 1~3 次。
> 所以**指望 MP 单独卡住频率是不现实的**（CD 已经卡死了）。长 CD 口径下 MP 真正提供的三件事：
> ① **禁止连喷**：★1 池只够 1.25~1.5 发 → 想连放两发是想都别想；
> ② **给 CD 缩减兜天花板**：一旦堆出 `CooldownReduce`，MP 立刻回来接管（见 §5.4）；
> ③ **养成收益的落点**：升星把「一发」变成「能两发、三发」，这是玩家能亲手摸到的进步。

### 5.1 小白 H011 / SK004 治愈之光（基础CD 8 → **有效CD 32s**，耗蓝 100，治疗型 150 / 1.2）

| 养成 | 池 | 回复/s | 回一发耗时 | **连喷能力** | N(CD) | N(MP) | **实际 N** | 体感 |
|---|---|---|---|---|---|---|---|---|
| **Lv1 ★1** | 150 | 1.20 | 83 s | **1.5 发** | 2.34 | 2.40 | **2.34** | 放一发就见底，第二发要等 83 秒 → **每一发都得挑时机** |
| Lv4 ★2 | 188 | 1.34 | 74 s | **1.9 发** | 2.34 | 2.89 | **2.34** | 还是不够双奶 |
| Lv7 ★3 | 231 | 1.49 | 67 s | **2.3 发** | 2.34 | 3.42 | **2.34** | **能连续双奶了** ← 关键手感跃迁点 |
| **Lv10 ★5** | 302 | 1.78 | 56 s | **3.0 发** | 2.34 | 4.35 | **2.34** | 蓝不再是烦恼；自由的连续性大幅上升 |

→ 结论：长 CD 口径下 **N 卡在 2.34 不变**（CD 说了算），**真正的养成收益是「连喷能力 1.5 → 3.0 发」**，也就是「危局里能连着救两次」这个可感知的跃迁。**这就是这一版口径里升星值多少钱的答案。**

### 5.3 玩家（牧师 4 技共用一条蓝，pool 300 / 回复 1.8）

牧师三技的有效 CD：heal_spring 48s / swift_mend 36s / sacred_revival 88s → 一关 CD 需求 ≈ **4.5 次**。

| 养成 | 池 | 回复/s | 一关总供给（按 100/发） | CD 需求 | **实际 N** | 体感 |
|---|---|---|---|---|---|---|
| **Lv1** | 300 | 1.80 | **4.35 发** | 4.5 次 | **4.35** | **刚好卡着**：大招放一次 = 少奶两次，必须取舍 |

→ 玩家侧的紧张感不是「憋蓝」，是「**这一口蓝给治疗还是给爆发**」—— roguelike 想要的决策密度。

### 5.4 负反馈校验：CD 缩减一起来，MP 立刻接管

| 小白配置 | 有效CD | N(CD) | N(MP) | **实际 N** | 谁说了算 |
|---|---|---|---|---|---|
| ★1Lv1，无缩减 | 32s | 2.34 | 2.40 | 2.34 | CD |
| ★1Lv1 + 缩减 50% | 16s | 4.69 | **2.40** | **2.40** | **MP** |
| ★5Lv10 + 缩减 50% | 16s | 4.69 | **4.35** | **4.35** | **MP** |

→ **无论 CD 缩减怎么堆，MP 都是那条天花板。** 这正是 §10 里「属性绝不能加蓝」的根本理由：这条负反馈是整个系统的安全绳。

## 6. 剩下的 4 个旋钮（每处改一个数字，全局生效）

| 旋钮 | 当前值（已拍板） | 可调范围 | 影响 |
|---|---|---|---|
| **A. SKILL_COOLDOWN_MUL** | **4.0 —— 锁定，不动** | 若日后要动，建议 2.0 | 降到 2.0 会把技能频率翻倍、MP 才有卡频率的空间；**主人已决定先保持长 CD**，所以 §5 全部按 4.0 成立。<br>⚠ 若哪天真要降：**必须先重过一遍 §5 的 calibration**，且同步把回复往下调（否则 MP 直接失去意义） |
| B. 定位基础回复 | 治疗 **1.2** / 法术 **1.3** | ±0.3 | 直接改「憋多久」。主人已定「不要太快」，往下调没问题、往上调超过 2.0 就失去稀缺感 |
| C. 单次耗蓝档位 | 100 / 120 | ±20 | 改「满池能存几发」= 允许多少次连喷。**硬约束：耗蓝必须 ≤ 基础池 150** |
| D. 每星成长 | 池 +12% / 回复 +12%（每级 +6） | 8%~15% | 改养成兑现速度；12% 使 ★1→★5 连喷能力 **1.5 → 3.0 发**（翻倍） |

> **长 CD 口径下的平衡口诀**：CD 决定「多久一次」，**MP 决定「能不能连着来两次」**，星级决定这条「连几次」能不能升级。

| **在线时长** | 「憋蓝」把一次失败拉成多次尝试：玩家会为了「这次不乱放技能」再开一把；CD 是地板、MP 是天花板，两段都值得摸清 |
| **留存** | ★1→★5 技能频率 +59%（小白）/ 玩家 +53%，是**肉眼可感知**的养成兑现；也使局内三选一的每张「升级 / 升星」卡价值上升 → 抽卡点击意愿上升 |
| **后期广告 / 变现** | 治疗永远稀缺（每次投放都要取舍），日后做「局内回蓝」类小额广告 / 道具，接受度天然高 |
| **难度手感** | 早期因缺蓝紧张（奶不上的那一刻）→ 中后期靠养成解锁 → 标准「先紧张后爽」曲线，避免前期劝退、后期无脑 |

## 9. 混合技能：一个单位里「有的要蓝、有的不要蓝」怎么办

### 9.1 先看清现状

| 单位 | 同时拥有几个主动技 | 会不会混 |
|---|---|---|
| **佣兵** | 1 主动（`MercSkillCaster._activeSkillId`）+ 1 被动 | **当前不会混**（要么全免费要么全收费）；但**佣兵的 CD 已经吃 Hero 的 `CooldownReduce`**（`SkillSystem.ApplyCooldownReduce`） |
| **玩家** | 最多 4（`RunLoadout.MaxSkillSlots = 4`） | **一定会混**：Heal/Magic 收费，Shield/AtkBuff/召唤/物理 AOE 免费 |

→ 所以「混合」是**玩家侧的主场景**；佣兵侧将来要多主动时才用得上，规则现在就要写死，免得届时各写一版。

### 9.2 规则（三条 + 一个令牌，不再多加）

| # | 规则 | 为什么 |
|---|---|---|
| 1 | **一个单位一条蓝，不按技能分池** | 分池 = 每条技能各自攒各自的稀缺 → 稀缺感消失（全都变成了 CD 制） |
| 2 | **免费技能 = 地板节奏**：0 蓝、只吃 CD，**永远可用** | 这是自动战斗为主的游戏的保底：任何时候单位都不会因为缺蓝站桩发呆，输出/操作节奏不断 |
| 3 | **收费技能 = 稀缺窗口**：CD + MP 双闸门；MP 不足时——自动侧**跳过本次机会**（CD 不重置、不排队，回够蓝再放）；手动侧**按钮置灰 + 显示「蓝 xx/yy」** | 「排队释放」会让 MP 变成延迟而不是稀缺；「耗尽即触发 CD」会让 CD 沦为惩罚。跳过最干净 |
| 4 | **同帧单发令牌**：一个单位同一帧最多释放 1 个技能 | 防止一条蓝被同帧扣多次；也防止一瞬间清屏毁手感 |

### 9.3 多收费技能的竞争顺序（**两侧各一条，互不混用**）

| 侧 | 顺序规则 | 真源 |
|---|---|---|
| **佣兵（自动）** | 治疗（触发到血量阈值）> 已就绪里**耗蓝最低**的 > 更贵的 | 新增，按 §9.3.1 |
| **玩家（自动）** | **玩家拖拽出来的槽序** 就是唯一优先级：① 最先放，② ③ 是它的替补 | **已实现**：`RunLoadout.MoveSkill` → `BattleManager.FindReadySkillSlot` 从 0 槽往下找 |

> 2026-10-06 主人拍板：「**不是手动释放，是手动拖拽调整释放顺序；不拖拽就按获得技能的先后顺序释放**」。
> → 玩家侧**不叠加**「先便宜后贵」那套成本排序 —— 玩家排出来的顺序就是意图，系统不许再替他重排。
> ⚠ 唯一前提：`PlayerSkillPassive.IsTriggerMet`（血线 / 怪群）仍会 gate —— ① 号技能不满足触发条件时会顺位给 ②，
> 这是「冷却好 ≠ 该放」的旧口径，不是顺序被改。

#### 9.3.1 佣兵侧的「先便宜后贵」（只在佣兵生效）
```
优先级 = 治疗（触发到血量阈值时，绝对优先）  >  已就绪里【耗蓝最低】的那个  >  更贵的
```
- 避免一次把池掏在大招上、导致应急技能永远放不出；也避免小技能永远抢不到。
- 别再加规则（再加「按目标数量」「按 DPS 期望」就是过度设计）。

### 9.4 混合单位的手感演算（示例）

假设某单位：免费技 SK001 疾风斩（基础CD 6 → 有效 **24s**）+ 收费技 SK004 治愈之光（有效 **32s**，耗蓝 100，治疗型 ★1Lv1）：

| 技能 | 是否收费 | 一关次数 | 体感 |
|---|---|---|---|
| 疾风斩 | 免费 | 75 / 24 = **3.1 次** | 稳定地板，一直在打 |
| 治愈之光 | 收费 100 | **2.34 次**（且**不能连放第二发**：池只有 1.5 发） | 稀缺珍貴的一口，放之前要犹豫 |

→ **「免费保底 + 收费点缀」是最佳手感模型**：节奏不断，稀缺感只在真正值钱的技能上出现。
→ 反面参照：两个都收费 → 单位后期几乎停摆（体验差）；两个都免费 → 回到纯 CD，没有取舍。
→ **建议写进后续内容制作的默认模板**：每个单位 = **1 个免费（保底）+ 1~2 个收费（稀缺）**。

## 10. 属性要不要加蓝？—— 结论：**不要；只给「回蓝」留一条窄入口并封顶**

### 10.1 核心论证：MP 已经是那条**天花板**，属性不能再来掀它

现成的演进路径里，**属性早就有一条提高技能频率的通道**：
`AttrType.CooldownReduce`（天赋 R10 + 披风/武器词缀都在写），且 `SKILL_COOLDOWN_REDUCE_CAP = 0.5`（最高 50%）。

算一笔帐（小白 SK004，基础CD 8 → **有效 CD 32s**，耗蓝 100，治疗型 150 / 1.2）：

| 配置 | 有效CD | N(CD) | N(MP) | **实际 N** | 谁说了算 |
|---|---|---|---|---|---|
| 基准 ★1Lv1 | 32s | 2.34 | 2.40 | **2.34** | CD（几乎持平） |
| ★1Lv1 + 冷却缩减 50% | 16s | 4.69 | **2.40** | **2.40** | **MP（立刻接管）** |
| ★5Lv10 + 冷却缩减 50% | 16s | 4.69 | **4.35** | **4.35** | **MP（仍是天花板）** |

> **关键洞察**：CD 堆到尽头，MP 会重新接管成为上限 —— **MP 就是 CD 堆叠的天然负反馈。**
> 如果属性还能加 MP/回蓝，这条负反馈就失效了：同一份装备投入同时抬「伤害 + 频率 + 资源」三重叠加 → 后期数值失控（典型的属性二次耦合）。这是本文给出的**最强理由**。

### 10.2 次要理由

| 理由 | 说明 |
|---|---|
| **稀缺资源不能由随机词条供给** | `ArmorAffixSystem` / `WeaponAffixSystem` 词条是随机的。让 MP 吃随机 → 同 Build 之间强度方差不可控，且玩家看不出自己的蓝条为什么比别人短 |
| **可感知性** | 玩家很难比较「+60 魔攻」与「+8% 回蓝」谁更好 → 增加选择噪音，却降低决策质量（把选择留给真正关键时刻，而不是每词条都要算） |
| **保住设计意图** | 「满池只存 1.25~1.5 发、禁止连喷」是紧张感的根；一旦 `+蓝上限` 词条进场，这条被撕开，前面所有 calibration 作废 |

### 10.3 允许的那条窄入口（分层用，不是属性）

| 来源 | 加池 | 加回蓝 | 建议与上限 |
|---|---|---|---|
| 定位基础值 | ✓ | ✓ | **统一 150；回复 治疗 1.2 / 法术 1.3**（玩家：300 / 1.8） |
| 等级 | ✓ +6/级 | ✗ | 线性小收益 |
| 星级 | ✓ +12%/星 | ✓ +12%/星 | ★5 = ×1.48 |
| **`CooldownReduce` 属性** | ✗ | ✗ | 走既有 50% cap（作用在 CD 这条闸门） |
| **新词条「回蓝 +N%」**（建议） | ✗ | ✓ | 只出「回蓝率」，**不出「+蓝上限」**；只出现在披风 / 饰品；**总回蓝加成 cap = +30%**（与 CD cap 同哲学） |
| **天赋大节点**（建议） | ✗ | ✓ 每节点 +8% | 并入上面 30% cap，不叠出天际 |
| 其它战斗属性（力量/智力/体质/魔攻/生命…） | ✗ | ✗ | **一律不挂 MP** |
| 战斗内道具 / 增益（预留） | 预留 | 预留 | 后续要加再开单据 |

> 为什么回蓝可以、池不行：**回蓝改的是「等多久」，池改的是「能不能连放两次」**。
> 前者是节奏调节可以有上限地松，后者直接拆掉决策结构。

### 10.4 若主人坚持要让属性加蓝 —— 备选方案（**不推荐放一线**）

给一个**有界 + 边际递减**的映射，并明确它是次选：

```
属性贡献 MP = min( 0.30 × 定位基础池 ,  k × √(智力) )      k 建议取 8
                ↑ 硬性天花板                    ↑ 边际递减：智力越高，每点换到的蓝越少
```
- 治疗型天花板 = 0.30 × 150 = **45 点**（最多多出 0.45 发）；法术型同为 45 点。
- 例：智力 25 → 40 点；智力 100 → 80 点 → 被 **45** 封顶。
- ⚠ 缺点：与 `CooldownReduce` **双重提速**；且玩家看不见自己的确切收益。
- 若真要走这条：必须同时把 `CooldownReduce` cap 从 50% 下调到 **35%**，把「频率」这条budget 分一半给 MP —— **一进一出，总预算不变**，这是唯一安全的做法。

### 10.5 边界总表（可直接写成常量）

| 常量（建议名） | 建议值 | 作用 |
|---|---|---|
| `SKILL_COOLDOWN_MUL` | **4.0（不动）** | 技能冷却总倍率；主人拍板保持长 CD |
| `MERC_MP_BASE_POOL` | **150** | 有蓝单位的基础池（玩家 300） |
| `MERC_MP_BASE_REGEN` | **1.2**（治疗）/ **1.3**（法术）；玩家 **1.8** | 每秒回复，刻意慢 |
| `MERC_MP_PER_LEVEL` | **+6** | 每级池成长 |
| `MERC_MP_PER_STAR` | **+0.12** | 每星池与回复各 +12%（★5 = ×1.48） |
| `MP_START_FULL` | **true** | 每关开局回满（已拍板） |
| `MP_REGEN_BONUS_CAP` | **0.30** | 所有外部回蓝加成的总量上限 |
| `MP_ATTR_CONTRIB_CAP_RATIO` | **0.30** | 若启用属性转 MP：属性贡献 ≤ 30% 基础池 |
| `MP_ATTR_K` | **8** | 若启用：`k × √(智力)` |
| `SKILL_COOLDOWN_REDUCE_CAP` | **0.50**（若启用属性转 MP → 调 **0.35**） | 频率总预算的另一半 |

> 已作废、不写进代码：`MP_OVERLOAD_EXHAUST_SEC` / `MP_OVERLOAD_CD_SLOW`（§9.5，主人拍板「蓝不足不能释放」）。

**单一释放闸门（落地时的唯一判据）**
```
可释放 ⇔ CD 就绪(_cooldownRemain ≤ 0) 且 MP ≥ 技能耗蓝
释放成功 → _cooldownRemain = CooldownTotal，MP -= 耗蓝
释放失败（MP 不足）→ 什么都不做，CD 不重置、不排队、不透支
```

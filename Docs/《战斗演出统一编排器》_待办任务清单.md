## 一、现状与根因（日志 + 代码双坐实）

### 1. 用户现象（2026-11-23 15:17）

用户诉求（已拍板）：**狗作为真战斗单位先上场打怪，玩家后加入帮忙**；且**佣兵救场/乱入是同一类问题**，要一并根治。

### 2. 日志铁证
- `Editor.log` 行 **219035** 起 `BattleBossHpBar.RefreshFromField` 持续刷，狗剧情激活在 **219789** —— 血条与狗剧情**无关**。
- 行 220771 `锁定目标 ×1（名牌=Visual）`；`BattleBossHpBar.PickTargets:636` 只对 `IsBossUnit || IsEliteWave` 刷条 → 那是**第二波精英怪**（单位名 Visual）触发的血条，非 Boss 波（日志无「首领来袭」）。**此项非 bug，属玩家误认**，见待确认项。

### 3. 架构病根（真因）
三类战斗内演出各写各的、靠散落标志抢时序：

| 演出 | 台词/数据 | 协程 | 抢时序标志 |
|---|---|---|---|
| 狗营救 | `PetRescueStoryBeats`(C#常量) | `BattleManager.PetRescue.cs` 4 协程 | `_petRescuePhase` + `_preBattleStoryPlaying` + `UnitsCanAct` |
| 友军救场 | `IntruderStoryBeats` | 散在 `Waves.cs` | `_preBattleStoryPlaying` + `UnitsCanAct` |
| 敌对乱入 | `IntruderEventDirector` 分派 | `Waves.cs`/`MonsterDeath.cs` | 同上 |

`_preBattleStoryPlaying` / `UnitsCanAct` 被 **5+ 文件、20+ 处**读写（Waves/Settlement/BossBlessing/Death/PetRescue/MonsterDeath）。任何一处时序变动即引发抢跑。8 轮补丁都在单个现象上打转，未触及此结构。

## 二、目标演出链（狗营救，拍板口径）

1. 第一波照常打 → 玩家正常往前走（不冻场）
2. 第二波刷出：狗作为**真战斗单位**先上场（走 `DeployRescuedPet`→`SpawnBattlePet` 唯一出口），怪与狗交战
3. 狗"汪汪"气泡 → 玩家喊话气泡（自动播；如需冻场仅在对话窗口期，且由编排器统一管）
4. 玩家/佣兵上前帮忙打第二波（狗在场并肩作战，计入战斗单位）
5. 第二波清完：狗叫两声 → 跑走 → 玩家点评气泡
6. 点评完 → 放行「首领来袭」→ Boss 波 → Boss 半血狗归队（保留 `TickPetRescueRejoin`）

## 三、架构设计（解耦达：单一职责 + 单一真源 + 数据驱动）

> 数据驱动用项目现成 **C# `Defs` 表**模式（与 `PetRescueStoryBeats`/`IntruderEventTable` 一致），**不引入 ScriptableObject**——项目无 SO 资产管线，强塞会破坏现有数据流。

### 组件 1：`BattleCutsceneDefs.cs`（数据层，新建）
- 定义演出步骤枚举：`SpawnPetFight` / `PlayBubbleAt` / `PlayBubbleOnHero` / `WaitWaveCleared` / `PlayRemark` / `ReleaseWave`
- 定义一张演出 = 有序 `Step[]`（编译期 C# 常量表，纯数据，无逻辑）
- 狗营救/友军救场/敌对乱入各配一张表，步骤顺序即分镜

### 组件 2：`BattleCutsceneDirector.cs`（编排层，新建；替代 PetRescue.cs 散落协程）
- **唯一协程**按步骤表顺序执行，每步做完才走下一步（消除多处 `StartCoroutine` 抢跑）
- 对外唯一标志 `IsOccupyingBattlefield`（true=演出占用战场，波次不得推进）
- 演出结束（`ReleaseWave` 步）发完成信号，波次系统收到才推进
- 冻结/解冻（`UnitsCanAct`）只在本组件内成对管理，禁止外部改

### 组件 3：波次闸收敛（`BattleManager.Waves.cs`）
- 把所有狗剧情相关的 `phase`/`UnitsCanAct`/分散判断，收敛为单一读 `BattleCutsceneDirector.IsOccupyingBattlefield`
- **注意**：`_preBattleStoryPlaying` 仍被开场剧情/抽奖/首波硬刷使用（Settlement/BossBlessing），**不能删**——新增标志只给战斗内演出，与旧标志**分层共存**（这是当前混乱的主因之一，务必分离）

### 组件 4：狗真参战（改 `PetRescue.cs` + `PetDeploy.cs`）
- 步骤 `SpawnPetFight` 调现有 `DeployRescuedPet()`（内部已走 `SpawnBattlePet` 唯一出口，含解锁/幂等判定）
- **删除**纯视觉狗 `SpawnRescueDogVisual` 及 `WavePlanner.Execute.cs:290-312` 的落位特判（不再需要）
- 半血归队 `TickPetRescueRejoin` 保留；因狗已参战，需处理幂等（已有，`SpawnBattlePet` 检查同 id 在场则早退）

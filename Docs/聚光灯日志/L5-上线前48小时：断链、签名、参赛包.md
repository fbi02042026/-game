# 日志 #5 · 上线前 48 小时：断链、签名、参赛包

> 发布窗口：**10/16–10/18**　标签：#聚光灯gamejam开发者日志
> 与上一篇间隔 ≥2 天；至少 1 张开发过程截图或短视频。

#### 正文

临上线我扫了一遍资源引用，报出 7 处图片丢失。查下去，图一张都没少，坏的是资源的标识文件——里面的 GUID 被写成了 56 字符的长串，而预制体里存的还是旧的 32 位十六进制，两边对不上。

这件事最麻烦的不是修，是**它看起来完全正常**，我差点就信了。

引擎对图片引用丢失的处理是静默退化：取不到就画一个纯色矩形，不报错，也不中断打包。再加上本地缓存里还留着旧索引，只要没触发重新导入，编辑器照样把图显示出来。也就是说——"能打包、不报错、看着像那么回事"，根本不能证明没断链。什么时候重新导入，什么时候才真正坏。

我不接受这种"看起来没事"。判定方法最后逼出来了：选中那个按钮，看 Inspector 里图片组件的 Source Image 槽位。显示图名 = 缓存兜底中；显示 `None (Sprite)` = 已经断了，你看到的是白块。我把 7 处挨个人工确认了一遍，没有一个是误报。

修法是**反着来的**：不去动预制体，也不动图，把预制体里已经存着的那串旧标识写回资源的 meta 文件。改完必须重启引擎才生效。7 处清完，全库 8000 多个标识复核零撞号。

但这类长串是引擎自己写回去的，之前已经换发过 626 个，现在又长出 300 多个——会反复。所以我加了两道：

1. **快照对比**：存一份"路径 → 标识"的全量基线，随时比对，专门抓"本来是正常的 32 位、变成 56 字符"这种蜕变，并拿旧值去预制体里查残留引用，直接判定断没断。
2. **引擎内报错**：保存预制体或场景时立刻查那一个文件，图片丢失直接打 Error。这一步是我的硬性要求——**不要兜底，要报错**，不然我根本看不出问题。写它的时候还踩了两个假警报源：引擎内置资源没有 meta 必须跳过（漏了会报 288 条假红），第三方素材包的示例文件有 93 条噪音，所以默认只扫自己的目录。

然后是参赛包本身。这个活动是禁联网的，所以我做了一个专门的构建开关：云存档直接失败并提示、广告不播（原本看广告换的刷新改成免费一次）、登录只留"开始游戏"、不接任何第三方 SDK，编译走 IL2CPP + 仅 ARM64。签名这事儿只有一次机会——证书定下之后不能换，所以这次就定死，一次做完。

还剩一件我没收尾的：上一轮把每关金币改成固定额度之后，总量比原来多了 45%，商店和天赋的节奏理论上会变快。我故意没动它们——调经济最怕一次改两个变量，那就永远不知道是哪边起的效。等跑完真实数据再说。

五篇日志写下来，回头看，这个月我干得最多的事不是加东西，是**推翻自己**：调了几天的怪量区间推翻重来，做了四版抽奖砍掉三版，排好的瘦身方案实测发现一半是空操作，连"编辑器看着没事"这件事我都不敢再信了。都是为了让它好玩一点，值得。

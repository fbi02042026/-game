## 三、任务清单

### T1 ★★★ 运行时 id 别名导致 6 个技能全部 fail-closed
- **现象**：技能槽正常显示、CD 正常转，但**释放瞬间被拒绝**（6 个全中）。
- **根因链（4 跳）**：
  1. `PlayerSkillTable.cs:265` — `cfg.id = string.IsNullOrEmpty(def.allyConfigId) ? def.id : def.allyConfigId;`
     → 6 个技能都配了 `allyConfigId`，运行时 id 变成 `ally_heal` / `ally_shield` / …
  2. `SkillConfig.cs:47` — `skillId = id`，`ToActiveSkill` 直接吃这个别名
  3. `RunDraftDirector.cs:488` — `SkillRegistry.Instance.GetActiveSkill(skillId)` 是**唯一**装配入口
  4. `SkillCastService.cs:55-60`
     ```csharp
     float mpCost = PlayerSkillDefs.MpCostOf(skill.skillId);
     if (mpCost < 0f) { Debug.LogError(...); return false; }   // fail closed
     ```
     `PlayerSkillDefs.MpCostOf:921-927` 用 `ally_heal` 查表 → 查不到 → 返回 **-1** → 拒绝。
- **最硬的佐证**：`SkillCastService.cs:68` 写的是 `if (skill.skillId == "holy_barrier")`。
  若运行时 id 真是玩家 id，这个分支本该命中；实际是 `ally_shield`，**该分支永远不可能为 true**
  → 说明是 id 被别名化，不是作者按别名写的。
- **连带后果（同一根因）**：
  - 圣盾壁垒退化成旧的「防御 +35% buff」，不再是 09-26 拍板的抵扣型护盾
    （绕过 `:68` 后掉进 `ExecuteAllySkillFallback:314` → `ApplyTeamBuff` → `AttrSystem.ApplyTimedBuff(Defense…)`）
  - `PlayerSkillPassive.IsTriggerMet("ally_heal")`（`PlayerSkillPassive.cs:73-89`）查不到 → 返回 `true`
    → **6 个技能的触发条件全部失效**（治愈之泉/圣盾的血线 ≤80%、天雷的身边 ≥3 怪）
  - 冷却字典 key 也变成 `ally_*`（`RegisterCooldown:438`）
  - `BattleUI.Skills.cs:280` 用 `RunLoadout` 的真 id（正确取到 100），释放侧用别名（拿到 -1）
    → UI 蓝量压暗与真实闸门对不上
- **做法（二选一，需主人拍板）**：
  - **方案 A（推荐）**：`MpCostOf` / 冷却 / 触发判定统一改回用**玩家真 id**，别名只在装配 SO 时用。
    改点集中在 `SkillCastService` 的取 id 处 + `PlayerSkillPassive.IsTriggerMet`。
  - **方案 B**：让 `PlayerSkillDefs` 同时能按 `ally_*` 查到（建别名索引）。改动小，但两套 id 继续并存，后患。
- **验收**：战斗里 6 个技能都能真的放出来（日志不再刷「查不到耗蓝 → 拒绝释放」）；
  圣盾表现为抵扣型护盾；治愈之泉/天雷的触发条件重新生效。
- **依赖**：无。🔴 **必须最先做**，否则 T2 之后的验收都做不了。
- **风险**：改 id 口径会牵动冷却字典 key 与被动触发，**必须全量回归 6 个技能**。

### T2 ★ 圣盾壁垒不读配表、不吃星级

  玩家+佣兵同享一层、先扣盾后扣血）—— 这段本身没问题，错在参数来源。
